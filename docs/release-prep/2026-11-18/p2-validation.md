# 合成验收工具 P2：修复与验证

本次只修发布验证工具，不改服务器转码逻辑、版本、runtime、工作流或凭据。Linux GPU / 真机 P1 仍未关闭。

## 先复现，再修复

独立审查在 `3acc0ffa5` 发现：只要 codec / height / 色彩标签正确、progress=end、drop_frames=0、解码退出 0，脚本就会写 pass。技术会话在自己的临时副本重放同一故障注入，确认 **0.04 秒 / 1 帧 / 无输出音轨被记为 8/8 pass**。

新增完整脚本回归 `test_truncated_no_audio_cannot_pass_full_checker`：生成端模拟为合法八秒 / 96 帧 / DTS，只有输出端注入截短 / 无音轨。未修复脚本下测试失败：预期拒绝，却没有抛出失败。修复后脚本在第一个不完整输出即非零退出，`cases=[]`，report 保留 `remaining duration` 错误，不用编码器退出 0 充当覆盖正确。

## 新的覆盖与内容条件

- 源样本使用 `ffprobe -count_frames`，须完整包含 8 秒 / 12 fps / 96 帧，不能把生成失败的短样本当合法源。
- 从源实际帧数 / fps 和 seek 落点计算剩余时长与帧数；当前八秒样本的 0 / 2 / 5 秒场景应为 8 / 6 / 3 秒、96 / 72 / 36 帧。
- 总时长、视频实际时间戳跨度与解码 PCM 音频时长分别检查，避免长音轨掩盖短视频。时长容差为 **一帧视频 + 两帧 48 kHz AAC**：12 fps 为约 0.126 秒，24 fps 为约 0.084 秒，覆盖边界取整及编码 priming / padding，不允许数秒缺失。
- ffprobe 实际读帧数与预期差不得超过一帧；另实际解码为 32×18 灰度原始帧，计数必须与 ffprobe 完全一致，不能信伪造的容器帧数。
- 实际帧时间戳须严格递增、无超过两帧的间隙；绝对时间轴模式的首帧须落在预期 seek 窗口。多帧输出须保持源帧率；单帧无法可靠推断帧率，不拿 ffprobe 的 0/0 / 估计值误拒合法短片。
- 输出必须存在 **AAC / 立体声**；实际解码 PCM 必须完整覆盖剩余时长，且合成音调 RMS >50。缺音轨、只残留很短的 AAC、静音均不通过。
- 已知 testsrc2 输出须有空间对比及帧间变化：灰度范围 >16，多帧平均相邻像素变化 >0.1；空白与冻结画面不通过。这些阈值只用于这里的公开合成测试图 / 音调，不是泛化的媒体质量标准。
- HDR→SDR 仍要求相应场景实际输出 BT.709；HDR 原样重封装保持 PQ / BT.2020，明确只算直通，不算 tone-map 或视觉验收。

## 验证结果

- 一个不依赖真实 GPU 的整脚本注入回归，保留真实候选模块及 `build_hls_command`，只替换硬件 / 外部执行边界；它会进入非 integration CI。
