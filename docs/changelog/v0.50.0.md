## v0.50.0: See more before opening a poster

Library poster walls can now show the details you care about at a glance, from ratings and video specs to Chinese subtitles and watch state. Feishu and Lark also gain an app-bot setup path that starts with a scan instead of a manually prepared webhook.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25, and this release does not migrate the database.

### Highlights

#### Choose what every poster tells you

Open **Library → Customize home → Poster badges** to turn on rating, year, resolution, HDR / Dolby Vision / Atmos, airing status, Chinese subtitles, unwatched-episode count, or a watch-progress bar. You can keep top badges visible or show them only on hover, and hide ratings below a chosen score. Everything is off by default, applies only to your account, and updates library walls immediately.

#### Link a Feishu or Lark app bot by scanning

Under **Settings → IM push**, add a Feishu channel and choose **Create an app by scanning**. The new flow can create an app bot, send to the person who scanned or to a group, and use interactive cards for notifications with a text fallback. Existing custom-bot webhooks continue to work without migration.

- A new app must have the permission to send messages as the app and must be published before the welcome message can succeed.
- Credentials from an unfinished scan stay in server memory for 30 minutes so you can return to the form and retry. Restarting the server clears that unfinished flow.
- International Lark accounts can select the Lark domain.

### More features and improvements

- **Switch episodes without leaving playback**: iPhone and iPad, Mac, and Apple TV 0.13.0, Android 0.10.0, and Android TV 0.8.0 add an episode picker inside the player. Changing seasons from that picker requires Server 0.50.0; with an older supported server, the current season remains available.

### Fixed

- A site disabled in MovieClaw could be silently enabled again when the browser extension refreshed its cookies. Cookie refreshes now preserve the disabled state and do not queue verification until the site is enabled again.

### Before you update

- There is no database migration. The Docker runtime remains 25, so updating from **Settings → Updates and maintenance** does not require a new runtime image.
- The new Feishu scan flow uses an external tenant-approval service. If app creation or the welcome message is rejected, follow the permission guidance shown in the linking dialog; the existing webhook method remains available.

## 简体中文

## v0.50.0：打开海报前，先看见关键信息

媒体库海报墙现在可以直接显示你关心的信息，包括评分、画面规格、中文字幕与观看状态。飞书和 Lark 也新增了扫码创建应用机器人的接入方式，不必先手工准备群 Webhook。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25，这一版没有数据库迁移。

### 本版亮点

#### 自己决定每张海报显示什么

到「媒体库 → 自定义首页 → 海报角标」，可以分别打开评分、年份、分辨率、HDR / 杜比视界 / 全景声、播出状态、中文字幕、未看集数和观看进度条。顶部角标可以常驻或只在悬停时显示，也能隐藏低于指定分数的评分。所有角标默认关闭，只影响你自己的账号；改动会立即反映到媒体库海报墙。

#### 扫码接入飞书或 Lark 应用机器人

在「设置 → IM 推送」里新增飞书通道，然后选择「扫码创建应用」。新流程可以创建应用机器人，默认推给扫码人，也可以改为推到群里；通知会优先使用图文卡片，失败时回退成纯文本。原有群自定义机器人 Webhook 不需要迁移，仍可继续使用。

- 新应用需要开通「以应用身份发消息」权限并发布版本，欢迎消息才能成功发出。
- 扫码后未完成接入的凭据会在服务器内存中保留 30 分钟，可以返回表单重试；服务器重启会清掉这次未完成的流程。
- 国际版 Lark 可以选择 Lark 域名。

### 其他新功能与改进

- **不用退出播放器就能选集**：iPhone 与 iPad、Mac、Apple TV 0.13.0，Android 0.10.0，以及 Android TV 0.8.0 都新增播放器内选集。要在播放器里跨季切换，需要服务器 0.50.0；搭配更早但仍受支持的服务器时，当前季仍可选择。

### 修好了

- 在 MovieClaw 中停用站点后，浏览器扩展刷新 Cookie 可能把它静默重新启用。现在 Cookie 刷新会保留停用状态，也不会在重新启用前排队验证。

### 升级须知

- 这一版没有数据库迁移。Docker 运行时仍是 25，可以直接从「设置 → 更新与维护」更新，不需要更换运行时镜像。
- 新的飞书扫码流程依赖外部租户审批服务。如果创建应用或欢迎消息被拒绝，请按接入弹窗里的权限提示处理；原有 Webhook 方式仍可使用。
