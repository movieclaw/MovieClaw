## v0.36.0: Network-drive titles play like local files

Titles from network drives (strm files) now remux and transcode like files on your disk. Android also gets instant notifications straight from your own server.

> ⚠️ **Update the Docker image**: Stop the container and back up the data directory, then run `docker compose pull && docker compose up -d`. In-app update cannot install this version; it shows that a new Docker image is required.

### Highlights

#### Network-drive titles no longer need a special player

Until now, a strm title only played if the player could decode the original file, and the web player told you to open it in Infuse or VidHub instead. Now the server checks each title's format and remuxes or transcodes it when needed, in the web player and in Jellyfin players. Links that only work inside your home network are relayed by the server. This applies automatically after the update, and the new official plugin **Network-drive spec prefetch (网盘规格预探)** checks titles in the background so playback starts sooner.

- Remuxing, transcoding and relaying run through your server, using its bandwidth and CPU as local files do. Public links still go straight to the player.
- Links to private addresses or local names (such as `alist`) are relayed. So are links with request headers written in Kodi style: `#EXTVLCOPT:http-user-agent=…` on the line before, or `|User-Agent=…` after the link.
- MKV titles get seek thumbnails. Their embedded subtitles load without reading the whole file, and this also speeds up local MKV files.
- The iPhone and Mac apps still play these titles directly, as before.
- Strm files must contain an http(s) link; local file paths are not supported.

#### Android notifications that arrive right away

The Android app could only check for news by itself every 15 minutes. With Android 0.3.0, it can keep a direct connection to your server, so notifications arrive as they happen without Google or vendor push, and ones missed while offline arrive after reconnecting. Turn it on in the app under Settings → Notifications → **Realtime notifications (keep connected) (实时通知（保持连接）)**. Download: https://github.com/movieclaw/MovieClaw/releases/download/v0.36.0/MovieClaw-Android-arm64.apk

- It is off by default and needs this server version. On an older server the switch turns back off and asks you to update the server.
- A silent persistent notification shows download progress (administrators only) or your own text, such as the default "今天入库 {今日入库} 集".
- Choose events under **Which events to push (推送哪些事)**. The choice is per account and shared with iPhone and the web.
- A step-by-step guide helps keep it running in the background on vivo/iQOO, Xiaomi/Redmi, OPPO/OnePlus/realme and Huawei/Honor phones.

### New features

- **Turn off official plugins**: Administrators can open a plugin under Settings → Plugins and choose **Disable (停用)** or **Uninstall (卸载)**. Uninstalled official plugins can be brought back with **Restore (恢复)**.
- **Plugins do more**: Plugins can run background jobs shown on the Activity page and can use the AI assistant. Chats started by a plugin are marked **Plugin (插件)** in the sidebar.
- **Firefox extension**: Settings → Resource Sites → **Install extension (安装扩展)** now also offers a Firefox package. It is unsigned: load it as a temporary add-on, and load it again after restarting Firefox.
- **Android activity page**: Long-press a playing session to see why it plays that way, open the title, end playback or sign out the device.
- **Android downloads and chats**: Season-pack rows show each episode's progress, and AI replies can show title, library and subscription cards.

### Improvements

- **Model API key**: Leave the key blank when editing a provider to keep the saved one. A new key is still needed when you change the provider type or endpoint.
- **Site checks**: They now say when a NexusPHP login has expired or a Cloudflare challenge blocks access, instead of blaming a site layout change.
- **Skip intro and credits**: End credits split into two parts are joined, so the next-episode prompt appears sooner. Intros that run into the story end earlier.
- **iPhone push**: The iPhone app attached to this release explains in Settings → Notifications when a sideloaded build cannot receive push.
- **Android**: New aurora app and notification icons, and the version footer shows the real version.

### Fixed

- With GPT-5.6 models on OpenAI, choosing a thinking level made the AI assistant fail with error 400 once it used tools.
- In the web player, after direct play failed twice, you were asked to enable software transcoding, or HDR titles failed, without hardware transcoding being tried.
- Libraries on a mergerfs pool (such as on fnOS) picked up new downloads only at the next scheduled check, up to 6 hours later. If such a library was created with **Monitor folder changes in real time (实时监控目录变化)** off, turn it on in the library's edit dialog.
- Episodes left unselected in a season pack kept the subscription waiting forever. They are now searched again.
- On slow machines, an update could leave the container stuck restarting on an older version.
- After a restart, background tasks could stay queued until the next restart.
- Android: AI chats with tool calls no longer crash or fail to load.
- Android: Tapping an expired account now opens sign-in with your server and user name filled in, instead of doing nothing.
- Plus 3 smaller fixes.

### For administrators

- The prefetch plugin is on by default. After the update it checks every existing strm title, one every 3 seconds, reading the start of each file from the drive. Tune or disable it under Settings → Plugins.
- Existing skip-intro results are hidden until each season is recognized again. This runs in the background, and a show someone starts playing goes first.
- Each Android device with realtime notifications holds one open connection to the server. Missed notifications are kept for 7 days, up to 200 per device.
- A plugin using the AI assistant runs with administrator rights and uses your model quota. Its approval screen points this out.
- OpenAI providers on the official endpoint now use the Responses API. Ones with another API endpoint stay on Chat Completions. Switch under Advanced settings → **API protocol (API 协议)**, or use thinking level Default or Off if the endpoint lacks `/v1/responses`.
- GPT-5.6 Luna no longer offers **Max (最高)**. Chats that used it run at the model's default level.

### Before you update

- This release migrates the database, and a Docker image update makes no automatic backup. To return to v0.35.0, stop the container, change the image tag to `movieclaw/movieclaw:v0.35.0`, restore the backup you made, then start it.
- Android features above need Android 0.3.0; Android 0.2.0 keeps working without them. Android TV 0.2.1 (https://github.com/movieclaw/MovieClaw/releases/download/v0.36.0/MovieClaw-AndroidTV.apk) has no visible changes. The iPhone and Mac apps stay at 0.7.0, and the Mac transcoder needs no update.

## v0.36.0：网盘里的片，和本地片一样播

网盘（strm）条目现在能像本地文件一样换封装、转码。Android 也能直接从你自己的服务器即时收到通知。

> ⚠️ **需要更新 Docker 镜像**：先停止容器并备份数据目录，再执行 `docker compose pull && docker compose up -d`。应用内更新装不了这一版，会提示需要拉取新的 Docker 镜像。

### 本版亮点

#### 网盘里的片，不用再挑播放器

以前 strm 条目只有播放器能直接解码原文件时才能播，网页播放器只会提示你改用 Infuse、VidHub。现在服务器会先探明每部片的格式，需要时换封装或转码，网页播放器和 Jellyfin 播放器都受益。只在家里网络能访问的直链，由服务器转发。升级后自动生效；新的官方插件「网盘规格预探」会在后台提前探好规格，起播更快。

- 换封装、转码和转发都经过你的服务器，和播放本地文件一样占用它的带宽与 CPU。公网直链仍直接交给播放器。
- 指向内网地址或本地名称（如 `alist`）的直链会被转发；按 Kodi 写法带了请求头的也会：上一行写 `#EXTVLCOPT:http-user-agent=…`，或在链接后接 `|User-Agent=…`。
- MKV 条目有进度条缩略图，内封字幕不用通读整片就能加载；本地 MKV 文件的内封字幕也因此更快。
- iPhone 和 Mac App 仍和以前一样直接播放这些条目。
- strm 文件里必须是 http(s) 链接，不支持本地文件路径。

#### Android 通知，即时送达

以前 Android App 只能每 15 分钟自己查一次有没有新消息。现在用 Android 0.3.0，App 可以和你的服务器保持直连，通知即时送达，不经过谷歌或厂商推送；离线期间错过的，重新连上后补发。在 App 的「设置 → 通知 → 实时通知（保持连接）」开启。下载：https://github.com/movieclaw/MovieClaw/releases/download/v0.36.0/MovieClaw-Android-arm64.apk

- 默认关闭，需要本版服务器。服务器较旧时开关会弹回关闭，并提示先更新服务器。
- 会常驻一条静音通知，显示下载进度（仅管理员）或你自定义的文字，默认是「今天入库 {今日入库} 集」。
- 在「推送哪些事」里选择要推的事件；按账号保存，与 iPhone、网页共用。
- vivo/iQOO、小米/Redmi、OPPO/一加/realme、华为/荣耀手机有分步引导，帮你让它在后台常驻。

### 新功能

- **官方插件可以停用**：管理员在「设置 → 插件」打开某个插件，可以「停用」或「卸载」；卸载的官方插件随时能「恢复」。
- **插件能做更多事**：插件可以建后台任务（在「活动」页显示），也可以调用 AI 助手。插件发起的对话在侧边栏标「插件」。
- **Firefox 扩展**：「设置 → 资源站点 → 安装扩展」现在也提供 Firefox 安装包。它没有签名：要作为临时附加组件载入，Firefox 重启后需重新载入。
- **Android 活动页**：长按正在播放的会话，可以查看为什么是这种播放方式、打开影片详情、结束播放或注销设备。
- **Android 下载与对话**：季包下载行显示每一集的进度；AI 回复可以展示影片、媒体库和订阅卡片。

### 体验改进

- **模型密钥**：编辑供应商时 API Key 留空，沿用已保存的密钥。更换供应商类型或 API 端点时仍要重填。
- **站点验证**：NexusPHP 站点登录过期、被 Cloudflare 人机验证拦下时会明确说明，不再误报站点改版。
- **跳过片头片尾**：断成两截的片尾会接成一段，「即将播放下一集」出现得更早；延续到剧情里的片头结束得更准。
- **iPhone 推送**：本版附带的 iPhone App 在侧载版收不到推送时，会在「设置 → 通知」里说明原因。
- **Android**：启动器和通知换成新的极光图标；页脚显示真实的版本号。

### 修好了

- 在 OpenAI 上使用 GPT-5.6 系列模型时，选了思考档位后 AI 助手一调用工具就报 400 的问题已修复。
- 网页播放器直通连续失败两次后，没试硬件转码就要求开启软件转码（HDR 片直接报错）的问题已修复。
- 媒体库放在 mergerfs 合并盘（如飞牛）上时，新下载要等下一次定时检查（最长约 6 小时）才入库的问题已修复。如果这种库建好时「实时监控目录变化」是关的，到库的编辑弹窗里把它打开。
- 季包里没勾选的集不会再让订阅一直等下去，会重新搜索。
- 慢机器上，更新后可能卡在旧版本反复重启的问题已修复。
- 重启后，后台任务可能一直排队、要再重启一次才动的问题已修复。
- Android：带工具调用的 AI 对话闪退或加载失败的问题已修复。
- Android：点已失效的账号不再没反应，现在会打开登录，并预填服务器和用户名。
- 以及 3 处细节修复。

### 管理员须知

- 网盘规格预探插件默认开启。升级后它会探一遍已有的全部 strm 条目，每 3 秒一个，每次从网盘读取文件开头一小段。在「设置 → 插件」调整或停用。
- 已有的片头片尾识别结果会先隐藏，等每一季重新识别后再出现。识别在后台进行，有人开始看的剧排在最前。
- 每台开启实时通知的 Android 设备和服务器保持一条连接。错过的通知保留 7 天，每台设备最多 200 条。
- 调用 AI 助手的插件以管理员身份运行，消耗你的模型用量；批准界面会标出这一点。
- 官方端点上的 OpenAI 供应商改用 Responses API；填了其他 API 端点的保持 Chat Completions。可在「高级设置 → API 协议」切换；端点不支持 `/v1/responses` 时，把思考档位改为「默认」或「关」。
- GPT-5.6 Luna 不再提供「最高」档；用过这一档的对话改按模型默认强度运行。

- 本版包含数据库迁移，更新 Docker 镜像不会自动备份。要回到 v0.35.0：停止容器，把镜像标签改回 `movieclaw/movieclaw:v0.35.0`，恢复你做的备份后再启动。
