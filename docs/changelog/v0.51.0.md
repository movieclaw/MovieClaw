## v0.51.0: Decide when a video counts as watched

Set one watched-status rule for every device, and use the web interface in German. This release also improves importing completed downloads from network mounts and remembering subtitle choices between episodes.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release adds a database migration; an in-app update backs up SQLite before switching versions.

### Highlights

#### Choose when playback marks a video watched

Open **Settings → Playback → Watched status** to set a played threshold from 80% to 100%. The server applies it to subsequent online progress reports and offline viewing uploads, without requiring a client update. You can also turn on **Prefer detected credits** for TV episodes.

- The default remains 90%, with detected credits off. At that default, videos shorter than five minutes retain the existing rule: at least 5% playback counts as watched.
- Credits must have been successfully detected in a TV library with **Detect intros and credits** enabled, and must run to the end. Otherwise the percentage applies. Valid credits replace the percentage and can mark watched earlier or later.
- Marking watched clears the resume position. A 100% threshold allows one second for stored duration precision. Changing the rule does not rewrite existing watch history.

#### Use the web interface in German

Choose **Deutsch** from the language selector, or use a browser set to German. The web interface gains German translations and German date and number formatting. Server-generated messages still fall back to English. German is also available as a quick pick for the library metadata language under **Settings → Metadata and organization**.

### More features and improvements

- **Hide a continue-watching card without changing history**: sync plugins can now hide a whole title from **Up next** without marking it watched or erasing its playback history. New playback after the hide makes it appear again; older delayed reports do not. This is a sync API capability, not a new web menu action.
- **Limit an MCP endpoint to the tools you want**: administrators can set an endpoint's `excluded_tools` through the API. Excluded tools are omitted from discovery and direct calls are rejected, including through compact commands. The web endpoint editor does not yet expose this setting.
- **Keep progress tied to the version you watched**: reports for a replaced file use that version's historical duration. If its duration is unavailable, the reported resume position is preserved instead of borrowing another version's length to decide whether it is watched.

### Fixed

- Completed downloads written by another machine to a network-mounted import-watch directory could remain unimported because local file events never arrived. Network directories are now polled, and downloader completion requests an immediate inspection.
- Titles already marked watched could incorrectly remain in the library's unfinished filter after a replay or an older device reported a resume position.
- Turning subtitles off for one TV episode could be forgotten when starting the next episode in an app.
- Two confirmations arriving together during interactive channel linking could try to save the same account twice and fail the binding.
- Hardware transcoding on VAAPI, QSV or NVENC could fail when restarting to fill missing segments after seeking. The GPU path now disables incompatible automatic software scaling.
- A cancelled request or protocol error during network recovery could leave later requests blocked even after the upstream service recovered.
- Process-based plugins can now subscribe to registered custom events from other running plugins; the SDK previously rejected these subscriptions.

### Before you update

- Runtime 25 is unchanged. The migration adds two fields for continue-watching visibility and preserves existing watch state. If you need to roll back after an in-app update, restore the matching pre-update database backup together with the old application version.
- For a Docker image upgrade, stop the container and back up its data directory first. To roll back, restore that backup and use the previous image tag.

## 简体中文

## v0.51.0：自己决定什么时候算看完

所有设备共用一套已看判定规则，网页界面新增德语。这一版还改善了网络挂载目录里的下载完成入库，以及剧集之间的字幕选择沿用。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版包含数据库迁移；应用内更新会在切换版本前备份 SQLite 数据库。

### 本版亮点

#### 自己决定播放到哪里才标记已看

到「设置 → 播放 → 已看判定」，可以把完成百分比设为 80% 到 100%。服务器会对之后收到的在线播放进度和离线观看补传应用规则，不必更新客户端。剧集还可以打开「优先按片尾判定」。

- 默认仍为 90%，片尾判定默认关闭。保持默认时，不足五分钟的短片沿用原规则：播放至少 5% 就算已看。
- 片尾必须来自已开启「片头片尾识别」的剧集库，且该集已识别成功、片尾直达结尾；否则仍按百分比判断。有效片尾会替代百分比，可能早于或晚于所填比例。
- 标记已看会清掉续播点。100% 为库内片长精度保留一秒容差。修改规则不会重写已有观看记录。

#### 用德语浏览网页

从语言选择器选择 **Deutsch**，或使用设为德语的浏览器，即可使用德语网页界面以及德语日期、数字格式。服务器生成的消息仍回落到英文。「设置 → 刮削与整理」的媒体库语言快捷选项也新增了德语。

### 其他新功能与改进

- **隐藏续看卡片，不改观看记录**：同步插件现在可以从「接下来继续」隐藏整部作品，不必伪装已看或清除播放历史。隐藏后发生的新播放会让作品重新出现；迟到的旧上报不会。这是同步 API 能力，网页菜单尚未新增对应操作。
- **让 MCP 端点只开放需要的工具**：管理员可以通过 API 配置端点的 `excluded_tools`。排除的工具不会出现在发现列表中，直接调用或通过紧凑命令调用也会被拒绝。网页端点编辑器暂未提供这个选项。
- **续播进度跟着实际观看的版本走**：片源被替换后，旧版本的上报会使用自己的历史片长。无法确定该版本片长时保留上报的续播点，不借用其他版本的片长来判定已看。

### 修好了

- 另一台机器把下载写到网络挂载的监听导入目录时，本机收不到文件事件，可能迟迟不入库。现在网络目录会定时巡检，下载器报告完成时也会立即请求检查。
- 已标记看完的作品，在重播或旧设备写回续播点后，可能错误地留在媒体库的「未看完」筛选里。
- 在 App 里关掉某集字幕后，下一集可能又自动打开字幕。
- 交互式通道绑定同时收到两路确认时，可能重复保存同一账号，导致绑定失败。
- VAAPI、QSV 或 NVENC 硬件转码在拖动后重启补片时可能失败；现在 GPU 链路会关闭不兼容的软件自动缩放。
- 网络恢复探测期间取消请求或遇到协议错误，可能让后续请求在上游恢复后仍一直被阻断。
- 进程型插件现在能订阅其他运行中插件已注册的自定义事件；此前 SDK 会拒绝这类订阅。

### 升级须知

- 运行时仍为 25。数据库迁移新增两个续看可见性字段，保留原有观看状态。应用内更新后若需回退，请恢复对应的更新前数据库备份，并同时回退应用版本。
- 如果通过 Docker 镜像升级，请先停容器并备份数据目录。回退时恢复这份备份，并使用上一版镜像标签。
