## v0.48.0: Site seasons match, and image subtitles stay direct

A series that sites split into a later season can be matched to the right episodes. On the website, image subtitles no longer transcode the whole file.

> ✅ Update from Settings → Updates and maintenance. This release migrates the database and makes a backup first. To return to MovieClaw Server 0.47.2, restore that backup; see Before you update. The Docker runtime stays 25.

### Highlights

#### A site's later season lands on the right episodes

Some series are one long season on TMDB, while release sites publish a later block as the next season. Solo Leveling is one: TMDB season 1 runs 25 episodes, and sites publish episodes 13–25 as season 2 after a gap of about 280 days. Subscriptions used to ignore that season 2. After this update, the next metadata refresh stores the mapping. Matching, manual grab, and import then treat the site's season 2 episode 1 as season 1 episode 13.

Open the series. Under the episode title, a line names the range, for example “Episodes 13–25: the site released these as season 2; they are mapped into this season automatically.” Subscription activity records the same fact. New titles get the mapping when they are added. An existing series gets it the next time you refresh metadata: open the library and choose **Refresh metadata** from the ⋯ menu, or refresh that title.

- A normal series, and a season that already exists on TMDB, is not renumbered.
- The later block is mapped once its first episode has aired. Episodes that have not aired are not grabbed early.
- Episode 0 stays episode 0.

#### Image subtitles no longer transcode the whole file

On the website, a PGS image subtitle — including one inside a disc image — is drawn on the picture. Choosing it, or opening a title that remembered it, keeps direct play. The video is not capped at 1080p and HDR stays HDR. The subtitle menu says image subtitles are drawn by the player. Picture in picture, casting, and system full screen do not show that overlay. While the track is extracted, the player says **Preparing subtitles…**. A large disc can take a few minutes. If the track fails to load, the menu says so.

**Burn into video** is a separate action in the subtitle menu. It asks **Burn subtitles into the video?** first. Burning transcodes: up to 1080p, and HDR becomes SDR. **Burn in anyway** starts it. If software transcoding is off, **Enable and burn in** turns it on, and other titles that need software transcoding use it too. **Don't burn in** leaves the picture as it is. **Stop burning in** returns to direct play. The burn is not remembered the next time you open the title.

Apps that cannot draw PGS still burn the track in when you select it.

### More features and improvements

- In a library whose type is **Other** or that only reads NFO, an actor has no person page. The card now opens **View {name}'s titles in this library**. The poster wall shows a removable **Actor** chip with that name. **Save as collection** is not offered while that chip is on, because a collection cannot store an actor filter. Directors, and actors who already open a person page, are unchanged.
- A folder from a plugin that only allows reading is labeled **Read-only** when you edit the library. It cannot be **Set as primary root**. Deleting a file there does not ask you to confirm a permanent delete. It says the files are read-only here, and that you delete them in that service; they disappear here after the next sync. This release does not add a built-in connection to another media server.

### Fixed

- Some Blu-ray folders and ISO images played a commentary, picture-in-picture, or storyboard that was within a minute of the feature but much smaller. *The Silence of the Lambs* could play a 480i commentary, and *Kiki's Delivery Service* could play a storyboard of the same length. After the server starts, those discs switch to the feature and the resolution and audio are read again. Discs that were already the feature are left alone. ISO bitrates that were far too high or too low are corrected in the same pass, so a fast connection is less likely to offer a lower quality, and a slow one is more likely to. A duration that made playback look finished as soon as it started is corrected too. You do not scan the library. A disc that is being reread can show empty specs until the probe finishes.
- Choosing an image subtitle that this server could not burn used to leave an error page. The choice was remembered, so the title would not open again. The title opens, and the burn is dropped.
- **Stop burning in**, changing episode, or leaving the player cancels a burn that had not started. It does not start the next time you open the title.
- Jellyfin clients built on the Kotlin SDK, such as Flow, could fail to open a title with “Deserialization failed” even though the server returned success. Those detail pages open. A bitrate that does not fit the number those clients expect is omitted instead of breaking the page.

### For administrators

- Settings → Notifications and integrations → Webhook can send **Intro and outro detection updated** when intro and outro results are written for a season.

### Before you update

- This release adds a nullable column on each title (`season_mapping`). Updating from Settings → Updates and maintenance makes a backup first. **Roll back to a previous version** to 0.47.2 restores that backup. Changes made after the update are lost, including the season mapping. The Docker runtime stays 25, so this in-app update does not require a new image.
- If you update by pulling a Docker image, there is no automatic backup. Stop the container and back up the data directory first. To roll back, restore that backup and use the 0.47.2 image.
- Until you refresh metadata, an existing series matches as it did in 0.47.2. Titles added after the update get the mapping when they are created.
- Disc spec correction runs in the background after startup. It does not need a library scan.

## 简体中文

## v0.48.0：站点上的下一季能对上，图形字幕不再整片转码

站点把一季拆开、按下一季发布的剧，可以归到正确的集。网页上的图形字幕不再把整部片转码。

> ✅ 在「设置 → 更新与维护」里更新。这一版会迁移数据库，并先做备份。要回到 MovieClaw 服务器 0.47.2，请恢复这份备份；见文末「升级须知」。Docker 运行时仍是 25。

### 本版亮点

#### 站点上的下一季落到正确的集

有的剧在 TMDB 上是一条长季，站点却把后面一段按下一季发布。《我独自升级》就是这样：TMDB 第 1 季有 25 集，站点在大约隔了 280 天之后，把第 13–25 集按第 2 季发布。订阅以前收不到这一季。这一版在下一次刷新元数据时记下对照。自动匹配、手动投递和入库会把站点的第 2 季第 1 集当成第 1 季第 13 集。

打开这部剧。分集标题下面有一行说明范围，例如「第 13–25 集：站点按「第 2 季」发布，已自动归入本季」。订阅动态里也有同样的记录。新入库的剧在建档时就有这份对照。已经在库里的剧，要等下一次刷新元数据：打开这个库，在 ⋯ 菜单里点「刷新元数据」，或只刷新这一部。

- 普通剧，以及 TMDB 上本来就有的那一季，不会被改季号。
- 后面那段要等它的第一集已经播出，才开始对照。还没播的集不会提前去抓。
- 第 0 集仍是第 0 集。

#### 图形字幕不再把整部片转码

在网页上，PGS 图形字幕（包括原盘里的）画在画面上。选中它，或打开一部记住了这条字幕的片子，仍然直放。视频不会被压到最高 1080p，HDR 也还是 HDR。字幕菜单写明图形字幕由播放器绘制。画中画、投屏和系统全屏里看不到这条字幕。抽取的时候播放器显示「字幕准备中…」。很大的原盘可能要几分钟。这一轨加载失败时，菜单里会说明。

「压制进画面」是字幕菜单里单独的一项。它先问「把字幕压制进画面？」。压制会转码：最高 1080p，HDR 变为 SDR。「继续压制」就开始。软件转码还没打开时，「开启并压制」会把它打开，之后其他需要软件转码的片子也会用上。「不压制」保持现在的画面。「取消压制」回到直放。这次压制不会在下次打开这部片时自动再来。

自己画不了 PGS 的 App，选中这条轨时仍会压制进画面。

### 其他新功能与改进

- 类型为「其他」、或只读 NFO 的库里，演员没有人物页。演员卡现在会打开「在本库查看 {name} 的作品」。海报墙上有一枚可以摘掉的「演员」条件，写着这个名字。带着这枚条件时不提供「存为合集」，因为合集存不下按演员筛。导演，以及本来就能打开人物页的演员，保持原样。
- 插件提供的、只能读取的目录，在编辑库时标成「只读」，不能「设为主根」。删除那里的文件时，不再走永久删除的确认。说明写着这些文件在这里是只读的，要到对方那里删，下次同步后这里会跟着消失。这一版没有自带连接另一台媒体服务器的功能。

### 修好了

- 有的蓝光目录和光盘镜像播成了解说、画中画或分镜：长度和正片差不到一分钟，文件却小得多。《沉默的羔羊》可能播成 480i 解说版，《魔女宅急便》可能播成分镜。服务器启动之后，这些盘会换回正片，并重新读取分辨率和音轨。本来就是正片的盘不动。ISO 上高得离谱或低得离谱的码率在同一次里改正，线路够用时较少再提示换低画质，线路不够时更容易提示。片长记错、一点播放就像已经看完的，也会一起改正。不用扫描库。正在重读的那张盘，探测完成前规格可能是空的。
- 选了一条这台服务器压制不了的图形字幕时，以前会停在错误页，而且选择被记住，这部片再也打不开。现在这部片能打开，压制会被撤掉。
- 「取消压制」、换集或离开播放器时，还没开始的压制会被取消。下次打开这部片不会再启动它。
- 用 Kotlin SDK 做的 Jellyfin 客户端（例如 Flow）打开详情时，可能整页报 Deserialization failed，服务器却返回成功。这些详情页现在打得开。码率放不进这些客户端要的数字时，会略过，不再把整页弄坏。

### 管理员须知

- 「设置 → 通知与集成 → Webhook」可以在一季写回片头片尾时发送「片头片尾的识别结果更新了」。

### 升级须知

- 这一版给每个条目加上可空的列（`season_mapping`）。从「设置 → 更新与维护」更新会先做备份。在「回退到历史版本」里回到 0.47.2 会恢复这份备份。更新之后的改动都会丢失，包括这份季号对照。Docker 运行时仍是 25，所以这次应用内更新不必换镜像。
- 如果是拉取 Docker 镜像更新的，不会自动备份。请先停止容器并备份数据目录。要回退，恢复这份备份，并使用 0.47.2 的镜像。
- 还没刷新元数据之前，库里已有的剧和 0.47.2 一样匹配。更新之后新入库的剧，在建档时就有这份对照。
- 原盘规格在启动后于后台修正，不用扫描库。
