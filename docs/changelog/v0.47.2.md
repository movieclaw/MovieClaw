## v0.47.2: A stability update

Renamed episodes in a TV library no longer stay at season 0, episode 0, and actor photos from NFO files show in Other libraries.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release does not migrate the database.

### Fixed

- A file in a TV library could be renamed, including into a Season folder or to a name like S01E01, and the next scan would keep the show but leave the season and episode at 0. The episode list then treated those episodes as not in the library. The scan that notices the rename now fills in the season and episode from the new file name. When the episode NFO beside the file gives both, that NFO wins. The show stays the one already on the file. A season and episode you entered yourself when claiming the file stay as you set them. Ignored files, files in the trash, and disc images stay as they are. If the name and the NFO do not give a usable episode number, the old numbers stay. Episodes already stuck at 0 from 0.47.1 or earlier are repaired when you open that library and choose **Scan library** from the ⋯ menu. The scheduled task **Library reconciliation** skips folders that have not changed, so that round does not repair them.

- In a library whose type is **Other** (it does not identify titles or look up metadata; it reads an NFO when one is present, otherwise the file name), actor photos written in the NFO did not appear under **Cast and crew** after a scan or after **Read NFO files and covers again**. They do now. Photos already stored by an earlier scan appear without reading the NFO again. If you later change a photo address in the NFO, choose **Read NFO files and covers again** from that library’s ⋯ menu.

- Notices, subscription health, and import errors that sent you to **Settings → Watch Import** now say **Settings → Automatic import**, the name of that page. The 0.47.1 notice for a download that finished in an ignored folder is included.

### Before you update

- There is no database migration. The Docker runtime stays 25, so updating from Settings → Updates and maintenance does not require a new image. **Roll back to a previous version** can return to 0.47.1 without restoring a backup, because the database structure is unchanged.

Thanks to @Migflyway. Full changes: [v0.47.1 → v0.47.2](https://github.com/movieclaw/MovieClaw/compare/v0.47.1...v0.47.2).

## 简体中文

## v0.47.2：稳定性更新

剧集库里改名之后季和集还停在 0 的文件会补上季集，类型为「其他」的库里 NFO 的演员头像会显示出来。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版不迁移数据库。

### 修好了

- 剧集库里的文件改名之后（包括放进 Season 目录，或改成 S01E01 这样的名字），下一次扫描会认出是同一个文件，作品还是原来那部，但季和集可能一直是 0。剧集页里这些集就不算在库。认出这次改名的扫描会按新文件名补上季和集；文件旁边的分集 NFO 写了季和集时，以 NFO 为准。你认领时自己填的季和集保持不动。已忽略的文件、回收站里的文件、原盘保持原样。文件名和 NFO 都读不出集数时，原来的季集保持不动。0.47.1 或更早已经卡在季 0 集 0 的，打开这个剧集库，在 ⋯ 菜单里点「扫描库」就会补上。定时任务「媒体库对账」会跳过没有再变化的目录，这一轮不会自己补上。

- 类型为「其他」的库（不识别、不刮削，有 NFO 就读 NFO，否则按文件名展示）里，NFO 写了演员头像，扫描之后或点过「重新读取 NFO 与封面」之后，详情页「演职员」里仍然没有头像。这一版会显示。升级前已经扫进去的头像不用再读一遍。之后改了 NFO 里的头像地址，在这个库的 ⋯ 菜单里点「重新读取 NFO 与封面」。

- 通知、订阅体检和入库失败说明里，还把你指到「设置 → 监听导入」。这个页面的名字是「设置 → 自动入库」。这一版改成页面上的名字。0.47.1 里「下载完成但无法入库」的提示也改过来了。

### 升级须知

- 没有数据库迁移。Docker 运行时仍是 25，所以从「设置 → 更新与维护」更新不必换镜像。在「回退到历史版本」里回到 0.47.1 时不用恢复备份，因为数据库结构没有变。

感谢 @Migflyway。完整改动：[v0.47.1 → v0.47.2](https://github.com/movieclaw/MovieClaw/compare/v0.47.1...v0.47.2)。
