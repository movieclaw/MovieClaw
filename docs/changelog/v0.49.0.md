## v0.49.0: Local titles join watch-state sync

Compatible media-server plugins can now sync watch state for local and NFO-only titles. This release also adds HDWing tracker support, repairs stale Blu-ray main-title records, and makes playback, channels, and Web carousels more reliable.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25, and this release does not migrate the database.

### Highlights

#### Local titles can keep their watch state in sync

Two-way sync used to skip a title when it had no TMDB or IMDb ID. Compatible plugins can now import watch history and write back watched, resume, and favorite state for those local or NFO-only movies and shows. A plugin may also opt in to videos from an Other library. Existing movie-and-TV sync keeps its previous scope, and MovieClaw adds no new background sync or setting by itself.

#### Blu-ray libraries recover the real main title

A temporary partial read could leave a disc or ISO recorded with a bonus feature as its main title, even after the storage returned to normal. Startup recovery and a manual full reprobe now compare the complete playlist set before correcting the title, duration, chapters, and media details. Unmounted, changing, or still-incomplete discs keep their existing records for a later retry.

### More features and improvements

- **HDWing tracker support**: Add 瓷器 (HDWing / HDChina) with an existing authenticated cookie. MovieClaw can browse and search its categories, read promotions and profile statistics, and download torrent files. Account-password login is not offered because the site requires Cloudflare Turnstile.
- **The expected subtitle is there on first play**: When a title has no remembered choice and no choice carried over from the same series, playback now applies the library language policy. A remembered choice, a same-series choice, and an explicit subtitle-off choice still take priority.
- **Redirected plugin streams keep credentials at their source**: Cross-origin redirects no longer receive the media server's account token. Sources that need ffmpeg continue through the MovieClaw server, including seeking and reconnecting.

### Fixed

- The large carousel on **My subscriptions** and the movie and TV discovery pages could flash white between posters. It now waits for the next image to decode, keeps the current poster while loading, and starts its timer and progress indicator when the new poster is actually on screen.
- Updating or restarting the service while a channel Agent was waiting for a reply could leave only “Thinking💭” behind. During a graceful restart, the channel now receives an interruption notice after the in-progress run is cancelled, and queued outbound messages get a bounded chance to finish.
- An OpenAI-compatible endpoint that sent no first byte, or stopped sending stream chunks, could leave a channel showing “Thinking💭” for 7–10 minutes. With the default provider settings, 90 seconds without data now ends the request and sends the existing failure notice. A provider-specific timeout still takes precedence.
- If a poster, NFO, or subtitle disappeared after a library organization plan was prepared, that missing sidecar could stop the whole job. The main file and the other planned files now continue, while the missing file is listed in the job's errors.
- A delete that mixed writable cloud-drive files with read-only or currently unavailable plugin files could change some remote files before reporting failure. The whole operation is now rejected before any file or ledger row changes. A disabled plugin is also unavailable for new primary roots, uploads, recycling, and deletion until it returns.

### Before you update

- There is no database migration. The Docker runtime stays 25, so updating from Settings → Updates and maintenance does not require a new image.
- This release changes subtitle selection and playback of credentialed, redirected plugin streams. Administrators who use media-server plugins should check direct play, seeking, subtitle selection, and a transcoded title after updating.

## v0.49.0：本地条目也能同步观看状态

兼容的媒体服务器插件现在可以为本地和只读 NFO 的条目同步观看状态。这一版还加入瓷器（HDWing）站点适配，能纠正蓝光原盘里记错的正片，并提高播放、渠道对话和网页轮播的可靠性。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25，这一版不迁移数据库。

### 本版亮点

#### 本地条目也能保持观看状态同步

一部作品没有 TMDB 或 IMDb 编号时，双向同步以前会跳过它。兼容的插件现在可以为这些本地或只读 NFO 的电影、剧集导入观看记录，并写回已看、续播点和收藏状态。插件也可以显式纳入「其他」库里的视频。原有的电影和剧集同步范围保持不变；MovieClaw 本身不会因此新增后台同步或设置项。

#### 蓝光媒体库会找回真正的正片

原盘目录或 ISO 临时只读到一部分时，花絮可能被记成正片；存储恢复后，这条错误记录仍可能一直保留。现在启动自愈和手动全量补探会先对照完整播放列表，再纠正正片、时长、章节和媒体规格。原盘没有挂载、仍在变化或仍读不完整时，已有记录保持不动，留到之后重试。

### 其他新功能与改进

- **瓷器（HDWing / HDChina）站点适配**：使用已经登录的 Cookie 添加站点后，可以浏览和搜索分类、读取优惠与用户资料统计，并下载种子文件。站点登录需要 Cloudflare Turnstile，因此不提供账号密码登录。
- **第一次播放就带上该选的字幕**：一部片没有记住的选择、同一部剧也没有沿用选择时，现在会应用媒体库语言策略。记住的选择、同剧沿用的选择，以及明确关闭字幕，仍然优先。
- **插件取流跳转时，凭据留在原来的站点**：跨站跳转不会收到媒体服务器账号令牌；需要 ffmpeg 的片源继续经 MovieClaw 服务器转发，拖动进度和断线重连也遵守同一条保护。

### 修好了

- 「我的订阅」和电影、剧集发现页顶部的大图轮播换张时可能闪白。现在会等下一张图片解码完成，加载期间保留当前海报；计时和进度指示也从新海报真正出现时开始。
- 渠道 Agent 等待回复时更新或重启服务，原渠道可能只留下「思考中💭」。优雅重启会取消进行中的处理并发送中断提示，也会给已经排队的出站消息一段有限的完成时间。
- OpenAI 兼容端点一直不回首字节，或流式回答中途不再传数据时，渠道可能显示「思考中💭」7–10 分钟。使用供应商默认设置时，现在连续 90 秒没有数据就结束请求，并发送原有的失败提示；单独配置过的供应商超时仍然优先。
- 媒体库整理计划建好后，如果其中一张海报、一份 NFO 或字幕消失了，这个旁车文件可能让整项任务中止。现在主文件和其他计划内文件会继续，缺失文件列在任务错误里。
- 一次删除同时包含可写网盘文件、只读或插件暂时不可用的文件时，可能先改掉一部分远端文件，最后才报失败。现在任何文件或台账行改变之前就整批拒绝。插件停用期间，也不能把它的新目录设为主根，不能上传、回收或删除，直到插件恢复。

### 升级须知

- 这一版不迁移数据库。Docker 运行时仍是 25，所以从「设置 → 更新与维护」更新不需要换镜像。
- 这一版改了默认字幕选择，以及带凭据、会跳转的插件片源播放。使用媒体服务器插件的管理员，更新后请检查直放、拖动进度、字幕选择和一部需要转码的片子。
