## v0.49.0: Local titles join watch-state sync

Compatible media-server plugins can now sync watch state for local and NFO-only titles, including opt-in videos from Other libraries. Playback also restores the expected default subtitle, protects credentials across redirected plugin streams, and recovers more cleanly from interrupted library work.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25, and this release does not migrate the database.

### Highlights

#### Local titles can keep their watch state in sync

Two-way sync used to skip a title when it had no TMDB or IMDb ID. Compatible plugins can now import watch history and write back watched, resume, and favorite state for those local or NFO-only movies and shows. A plugin may also opt in to videos from an Other library. Existing movie-and-TV sync keeps its previous scope, and MovieClaw adds no new background sync or setting by itself.

#### The expected subtitle is there on first play

When a title had no remembered subtitle and no choice carried over from the same series, playback could start without the subtitle selected by the library's language policy. The opening session now applies that policy automatically. A remembered choice, a same-series choice, and an explicit subtitle-off choice still take priority.

#### Redirected plugin streams keep credentials at their source

A media-server plugin may return a stream that redirects to another host. Playback can now follow that stream without forwarding the media server's account token to the other host. Sources that need ffmpeg continue through the MovieClaw server, so the same protection applies during seeking and reconnecting.

### Fixed

- An OpenAI-compatible endpoint that sent no first byte, or stopped sending stream chunks, could leave a channel showing “Thinking💭” for 7–10 minutes. With the default provider settings, 90 seconds without data now ends the request and sends the existing failure notice. A provider-specific timeout still takes precedence, and a long answer that keeps producing data is not cut off by total duration.
- If one Blu-ray playlist file was temporarily unreadable while the server rechecked a disc or ISO, the server could replace valid main-playlist, duration, chapter, or media-spec information with a partial result. It now keeps the existing information and retries later. A malformed candidate is also left out instead of becoming the selected playlist.
- If a poster, NFO, or subtitle disappeared after a library organization plan was prepared, that missing sidecar could stop the whole organization job. The main file and the other planned files now continue, while the missing file is listed in the job's errors.
- A delete that mixed writable cloud-drive files with read-only or currently unavailable plugin files could change some remote files before reporting failure. The whole operation is now rejected before any file or ledger row changes. A disabled plugin is also treated as unavailable for new primary roots, uploads, recycling, and deletion until it returns.

### Before you update

- There is no database migration. The Docker runtime stays 25, so updating from Settings → Updates and maintenance does not require a new image.
- This release changes subtitle selection and playback of credentialed, redirected plugin streams. Administrators who use media-server plugins should check direct play, seeking, subtitle selection, and a transcoded title after updating.

## v0.49.0：本地条目也能同步观看状态

兼容的媒体服务器插件现在可以为本地和只读 NFO 的条目同步观看状态，也可以显式纳入「其他」库里的视频。播放会恢复应选的默认字幕，插件取流发生跳转时不会把凭据带到另一个站点；媒体库任务遇到临时中断时也更容易继续完成。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25，这一版不迁移数据库。

### 本版亮点

#### 本地条目也能保持观看状态同步

一部作品没有 TMDB 或 IMDb 编号时，双向同步以前会跳过它。兼容的插件现在可以为这些本地或只读 NFO 的电影、剧集导入观看记录，并写回已看、续播点和收藏状态。插件也可以显式纳入「其他」库里的视频。原有的电影和剧集同步范围保持不变；MovieClaw 本身不会因此新增后台同步或设置项。

#### 第一次播放就带上该选的字幕

一部片没有记住的字幕、同一部剧也没有沿用选择时，起播可能没有带上媒体库语言策略挑出的字幕。现在开会话时会自动应用这条策略。记住的选择、同剧沿用的选择，以及明确关闭字幕，仍然优先。

#### 插件取流跳转时，凭据留在原来的站点

媒体服务器插件给出的播放地址可能跳到另一个主机。现在播放可以继续跟随这个地址，但不会把媒体服务器账号的令牌交给另一个主机。需要 ffmpeg 的片源继续经 MovieClaw 服务器转发，因此拖动进度和断线重连时也遵守同一条保护。

### 修好了

- OpenAI 兼容端点一直不回首字节，或流式回答中途不再传数据时，渠道可能显示「思考中💭」7–10 分钟。使用供应商默认设置时，现在连续 90 秒没有数据就结束请求，并发送原有的失败提示。单独配置过的供应商超时仍然优先；只要回答持续有数据，长回答不会因为总时长被截断。
- 服务器重新检查蓝光目录或 ISO 时，只要一份播放列表临时读不到，就可能用不完整结果替换已有的正片、时长、章节或媒体规格。现在保留已有信息，之后再试；格式损坏的候选也不会被当成正片。
- 媒体库整理计划建好后，如果其中一张海报、一份 NFO 或字幕消失了，这个旁车文件可能让整项整理任务中止。现在主文件和其他计划内文件会继续，缺失文件列在任务错误里。
- 一次删除同时包含可写网盘文件、只读或插件暂时不可用的文件时，可能先改掉一部分远端文件，最后才报失败。现在任何文件或台账行改变之前就整批拒绝。插件停用期间，也不能把它的新目录设为主根，不能上传、回收或删除，直到插件恢复。

### 升级须知

- 这一版不迁移数据库。Docker 运行时仍是 25，所以从「设置 → 更新与维护」更新不需要换镜像。
- 这一版改了默认字幕选择，以及带凭据、会跳转的插件片源播放。使用媒体服务器插件的管理员，更新后请检查直放、拖动进度、字幕选择和一部需要转码的片子。
