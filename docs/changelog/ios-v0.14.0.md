## iPhone and iPad 0.14.0: Follow a local actor into the library

Cast cards in local and NFO libraries can now lead straight to every title by that actor in the same library, even when no online person page exists.

> ✅ Works with MovieClaw Server 0.28.0 or later, the same as 0.13.0. The new actor-filtered wall requires Server 0.48.0 or later. This build is the unsigned IPA at https://github.com/movieclaw/MovieClaw/releases/tag/ios-v0.14.0. It is not uploaded to TestFlight.

### Highlights

#### Find the rest of an actor's work in a local library

On an item detail page, tap an actor who has no online person page. The app opens that same library with **Actor: Name** shown as an active condition; remove the condition or clear all filters to return to the full library. Actors with an online person page still open that page, and directors without one remain static.

Thanks to @Migflyway. Full changes: [ios-v0.13.0 → ios-v0.14.0](https://github.com/movieclaw/MovieClaw/compare/ios-v0.13.0...ios-v0.14.0).

## 简体中文

## iPhone 与 iPad 0.14.0：从本地演员找到同库作品

本地库和 NFO 库里的演员卡现在也能直接打开这位演员在同一媒体库中的全部作品，不再依赖在线影人页。

> ✅ 搭配 MovieClaw 服务器 0.28.0 或更新版本即可使用，与 0.13.0 相同。新的演员筛选海报墙需要服务器 0.48.0 或更新版本。这一版是未签名 IPA：https://github.com/movieclaw/MovieClaw/releases/tag/ios-v0.14.0。没有上传到 TestFlight。

### 本版亮点

#### 在本地库里继续看这位演员的作品

在条目详情页点没有在线影人页的演员，App 会打开同一媒体库，并把「演员：姓名」显示为当前条件。摘掉这项条件或清空全部筛选，就会回到整库。带在线影人页的演员仍进入影人页；没有影人页的导演仍不可点。

感谢 @Migflyway。完整改动：[ios-v0.13.0 → ios-v0.14.0](https://github.com/movieclaw/MovieClaw/compare/ios-v0.13.0...ios-v0.14.0)。
