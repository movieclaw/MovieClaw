## v0.52.0: Open videos in an external player

Send a video straight to the player you prefer from the web interface. This release also stops duplicate cleanup from deleting the cloud-drive file a `.strm` plays, makes in-app update rollbacks and downloader connection checks more resilient, and keeps batch subtitle jobs from tripping rate limits.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release adds a database migration; an in-app update backs up SQLite before switching versions.

### Highlights

#### Open in an external player

On a title's detail page or an episode card, choose **Open in external player** to play the original file in a player installed on your device. The link is signed and points at the original file. External players don't sync progress, so use **Mark as watched** when you finish.

### More features and improvements

- **Audio and subtitle choices remembered separately**: within a TV series, the audio track and the subtitle selection each follow your most recent choice.
- **Batch subtitle jobs no longer stall on rate limits**: requests are paced per subtitle provider automatically, with no new setting to configure.
- **HDDolby uses its new domain** `www.uhddolby.com`.
- **More complete German translations** in the web interface.

### Fixed

- With cloud-drive archiving, keeping the `.strm` copy in **Duplicate files** could send the cloud-drive file that `.strm` plays to the recycle bin, and a later purge deleted it, leaving the `.strm` unplayable. Duplicate cleanup now skips those files and shows why. A cloud-drive copy is also no longer deleted while a `.strm` for the same episode remains, including one in the recycle bin; files already in the recycle bin from earlier cleanups stay there instead of being purged. Remove the `.strm` first if you really want the cloud-drive file gone.
- An interrupted rollback of an in-app update could leave the database and application snapshots out of step. Paired snapshots are now restored together, and an interrupted rollback is completed before startup.
- An interrupted downloader connection check could stay stuck. Checks now recover after an interruption.
- External VTT subtitles recorded by a library scan could fail to load.
- Cloud-drive relay playback over a slow connection now switches connections and resumes instead of stalling.

### Before you update

- Runtime 25 is unchanged. The migration adds two nullable fields for downloader connection checks. To roll back after an in-app update, restore the matching pre-update database backup together with the old application version.
- For a Docker image upgrade, stop the container and back up its data directory first. To roll back, restore that backup and use the previous image tag.

## 简体中文

## v0.52.0：用外部播放器打开

在网页里一键把视频交给你常用的播放器。这一版还修好了重复清理会删掉 `.strm` 所播网盘文件的问题，让应用内更新回退和下载器连接检测更可靠，批量字幕任务也不再撞上限流。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版包含数据库迁移；应用内更新会在切换版本前备份 SQLite 数据库。

### 本版亮点

#### 用外部播放器打开

在条目详情页或剧集卡片上选「用外部播放器打开」，就能用设备上装的播放器直接播放原文件。链接带签名，指向原文件。外部播放器不同步进度，看完请点「标记为已看」。

### 其他新功能与改进

- **音轨与字幕分别记忆**：同一部剧里，音轨和字幕各自沿用你最近一次的选择。
- **批量字幕不再被限流卡住**：按字幕供应商自动控制请求节奏，不需要额外设置。
- **高清杜比换用新域名** `www.uhddolby.com`。
- **网页界面的德语翻译更完整**。

### 修好了

- 开启网盘归档时，在「重复文件」里选择保留 `.strm`，可能把这个 `.strm` 正在播放的网盘文件送进回收站，之后清理时被真的删掉，`.strm` 就再也播不了。现在重复清理会跳过这类文件并说明原因；同一集还有 `.strm`（包括回收站里的）时，也不再删除网盘上的副本，之前清理进回收站的这类文件会留在回收站里，不会被清掉。确实要删网盘文件，请先删掉对应的 `.strm`。
- 应用内更新回退中途被打断时，数据库和程序快照可能对不上。现在两者成对恢复，启动前会先完成未完成的回退。
- 下载器连接检测中途被打断后可能一直卡住，现在中断后能自动恢复。
- 扫描登记的外挂 VTT 字幕可能加载不出来。
- 网盘中继播放遇到慢连接时会自动换连接续传，不再卡住。

### 升级须知

- Docker 运行时仍是 25。迁移为下载器连接检测新增两个可空字段。应用内更新后如需回退，请把对应的更新前数据库备份和旧版程序一起恢复。
- 用 Docker 镜像升级时，先停容器并备份数据目录；回退时恢复该备份并换回上一个镜像 tag。
