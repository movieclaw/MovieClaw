## v0.38.0: Take your library offline on iPhone

The server now prepares films and episodes for iPhone offline downloads, with smaller transcoded copies when you need to save space. Adding a model provider is also easier: fetch the model list straight from the endpoint.

> ⚠️ **Update the Docker image**: Stop the container and back up the data directory, then run `docker compose pull && docker compose up -d`. In-app update cannot install this version; it shows that a new Docker image is required.

### Highlights

#### Watch on the plane, not just at home

Until now, the iPhone app could only stream from your server, so no network meant nothing to watch. With iPhone 0.8.0 or later, open a title's ⋯ menu and tap **Download (下载)** to keep the original file or a 1080p, 720p or 480p copy, each with an estimated size. Transcoded copies stream to the phone while the server is still converting them. Blu-ray, DVD and ISO disc titles cannot be downloaded yet.

- Only qualities below the source are offered. A lower quality is not always smaller, so go by the estimated size.
- Smaller copies are made by the server's GPU. Without one, an online Mac transcoder makes them in HEVC, which is usually smaller.
- With neither, smaller copies need software transcoding. There is no switch in Settings: an administrator turns it on from the prompt shown when playing a title that needs it.
- HDR titles need a GPU or the Mac transcoder for smaller copies, and those copies are in SDR.
- Smaller copies keep one stereo audio track. Text subtitles (SRT, ASS) come along; picture-based subtitles stay only in the original.

#### Set up a model provider without copying model names

On a compatible endpoint you used to type every model ID by hand, and OpenAI only offered its built-in list. Now **Fetch models from endpoint (从端点获取模型列表)** lists the models your key can see. On OpenAI and compatible endpoints you can add models that aren't built in; other providers offer only their built-in models. Start at Settings → **Model Providers (模型接入)** → add or edit a provider (administrators).

- You choose the connection-test model; on your first provider it also becomes the default AI model.
- GPT-6 Astra and GPT-6.1 Sol need the Responses API, set under Advanced settings → **API protocol (API 协议)**. Under Chat Completions they are hidden.
- Under Chat Completions, GPT-6 Sol and Luna can only run with thinking off.
- DeepSeek's official models can now turn thinking off.
- Known issue: Kimi K2.6 and K2.5 on Bailian can no longer turn thinking on, and earlier level choices now run without thinking. For thinking, use Kimi K2.6 through Kimi's official platform, where it is on by default.

### More features and improvements

- **18 new built-in models**: GPT-6 Astra, GPT-6.1 Sol, GPT-6 Sol and GPT-6 Luna on OpenAI; Qwen3.8 27B, 2.4T-A95B, Omni Flash and the Max 0902 snapshot, Qwen3.7 Flash, DeepSeek V4.1 Flash, Kimi K2.7 Code, GLM-5.3, MiniMax-M3 and MiMo-V2.5-Pro on Bailian; DeepSeek Flash, GLM-5.3 FlashX, Kimi K2.7 Code and K2.7 Code HighSpeed on their official platforms.
- **More thinking**: GPT-5.6 Luna gains the **Max (最高)** level.
- **Custom models**: A thinking budget is required only with **budget-based control (预算分段)**.
- **Command line**: New `mclaw llm models discover` lists an endpoint's models.

### Fixed

- On slow disks, a first install no longer gets cut off halfway through database setup and then fails on every restart.
- If you are already stuck this way (logs repeat `table … already exists`), this version cannot repair it. On a first install with no data yet, stop the container, delete the files starting with `movieclaw.db` in the data directory, and start again. If it happened during an upgrade, do not delete anything: restore your own backup, or, if that upgrade went through in-app update, the automatic one named after the old version in `data/updates/backup`.

### For administrators

- **Downloads are on for every member by default.** To block a member, go to Settings → Members → Edit member and turn off **Download videos to device (下载影片到设备)**.
- Turning it off stops new and unfinished downloads; titles already downloaded still play. It also rejects whole-file downloads from Jellyfin clients such as VidHub, and Infuse may be affected too.
- Conversions run one at a time and pause for playback. **Activity → Downloading (正在下载)** shows each one's quality, who converts it, speed and progress.
- Copies take disk space in the data directory, with no size limit, and appear in Settings → Update & Maintenance → Cache Management as **Offline download transcodes (离线下载转码)**. A copy is deleted once the phone finishes it, unless another device still needs it. Known issue: other copies are not cleaned on a schedule; one left 72 hours without access is removed only when someone next starts a smaller-quality download.
- Original-quality downloads of cloud-drive strm items are relayed through the server.
- Offline viewing syncs back when the phone reconnects and adds to watch history and play counts. For viewing synced later, webhooks get only the **Finished (看完)** event, with its real time.
- Known issue: cancelling or deleting a download on iPhone doesn't stop its conversion on the server. Everything already queued, such as a whole season, is still converted, and the copies stay for at least 72 hours. To stop it, stop the container, delete the `cache/offline-exports` folder in the data directory, then start the container. Unfinished smaller-quality downloads for the account signed in on the iPhone start over by themselves a while after the app is next opened; if one shows an error, delete it and download it again.
- Known issue: a conversion may wait forever and hold up the ones behind it. This can happen when the Mac transcoder it needs goes offline, or, with only an Intel GPU, no Mac transcoder and software transcoding off, for some HDR and 10-bit SDR titles, which are still offered. Bring the transcoder back online, or delete the stuck download on every iPhone that requested it and clean up as in the previous item.

### Before you update

- This release migrates the database, and a Docker image update makes no automatic backup. To return to v0.37.0, stop the container, change the image tag to `movieclaw/movieclaw:v0.37.0`, restore the backup you made, then start it.
- Server releases no longer include the app downloads (Mac transcoder, Mac app, iPhone, Android and Android TV). Each app has its own release; the Apps section below lists the latest versions. Android's fixed download link is https://movieclaw.io/download/android.apk.
- Windows 1.0.x will not update itself to the new Windows app. Download it from https://github.com/movieclaw/MovieClaw/releases/tag/windows-v0.1.0.

## 简体中文

## v0.38.0：把片库装进 iPhone，离线也能看

服务器现在能为 iPhone 准备离线下载，想省空间时还能下转码后的小版本。接入模型供应商也更省事：可以直接从端点获取模型列表。

> ⚠️ **需要更新 Docker 镜像**：先停止容器并备份数据目录，再执行 `docker compose pull && docker compose up -d`。应用内更新装不了这一版，会提示需要拉取新的 Docker 镜像。

### 本版亮点

#### 在飞机上也能看，不只在家里

以前 iPhone App 只能在线播放，没网就没片看。现在用 iPhone 0.8.0 或更新版本，在影片详情的 ⋯ 菜单里点「下载」，可以存原画，也可以存 1080p、720p 或 480p，每档都标出预计大小。转码版不用等服务器转完，边转边下。原盘（蓝光、DVD、ISO）暂不支持下载。

- 只提供比片源低的画质。低画质不一定更小，以每档标出的预计大小为准。
- 小画质由服务器的显卡来转；没有显卡时，由在线的 Mac 转码器转成 HEVC，体积通常更小。
- 两者都没有时，小画质需要软件转码。设置里没有这个开关：管理员播放需要转码的片子时，会弹窗询问是否开启。
- HDR 片的小画质需要显卡或 Mac 转码器，转出来是 SDR 画面。
- 转码版只保留一条立体声音轨。文本字幕（SRT、ASS）随片下载，图形字幕只在原画里。

#### 接入模型，不用再手抄模型名

以前兼容端点要一个个手填模型 ID，OpenAI 也只能用内置目录里的模型。现在点「从端点获取模型列表」，就能列出你的密钥能看到的模型。OpenAI 和兼容端点可以补录内置目录以外的模型；其他供应商只能选内置模型。从「设置 → 模型接入」新增或编辑供应商开始（仅管理员）。

- 可以自己选连接测试用的模型；接入第一个供应商时，它同时成为 AI 默认模型。
- GPT-6 Astra 和 GPT-6.1 Sol 必须用 Responses API，在「高级设置 → API 协议」里切换；选 Chat Completions 时不显示。
- 在 Chat Completions 下，GPT-6 Sol 和 Luna 只能关闭思考。
- DeepSeek 官方模型现在可以关闭思考。
- 已知问题：百炼上的 Kimi K2.6、K2.5 无法开启思考，以前选过的思考档位现在按不思考运行。需要思考时，可以改用 Kimi 官方平台的 K2.6，那里默认开启思考。

### 其他新功能与改进

- **新收录 18 个模型**：OpenAI 的 GPT-6 Astra、GPT-6.1 Sol、GPT-6 Sol、GPT-6 Luna；百炼的 Qwen3.8 27B、2.4T-A95B、Omni Flash 与 Max 0902 快照，Qwen3.7 Flash，DeepSeek V4.1 Flash，Kimi K2.7 Code，GLM-5.3，MiniMax-M3，MiMo-V2.5-Pro；以及官方平台的 DeepSeek Flash、GLM-5.3 FlashX、Kimi K2.7 Code 与 K2.7 Code HighSpeed。
- **更多思考档位**：GPT-5.6 Luna 新增「最高」档。
- **自定义模型**：只有用「预算分段」控制思考时，才必须填思考预算。
- **命令行**：新增 `mclaw llm models discover`，列出端点上的模型。

### 修好了

- 慢盘上首次安装时，不会再出现数据库初始化被中途打断、此后每次重启都起不来的问题。
- 如果已经这样卡住（日志反复出现 `table … already exists`），这一版修不好它。没有数据的首次安装：停止容器，删掉数据目录里以 `movieclaw.db` 开头的文件，再重新启动。如果是在升级时卡住的，什么都不要删：用你自己的备份恢复；那次升级若是走的应用内更新，也可以用 `data/updates/backup` 里以旧版本号命名的自动备份。

### 管理员须知

- **所有成员默认可以下载。** 要禁止某个成员，到「设置 → 成员 → 编辑成员」关闭「下载影片到设备」。
- 关闭后，新的和没下完的下载都会停，已经下好的照常能看。它也会拒绝 VidHub 等 Jellyfin 客户端的整文件下载，Infuse 可能同样受影响。
- 转码一次只转一部，有人播放时让路。「活动 → 正在下载」会显示每个转码的画质、由谁在转、速度和进度。
- 转码副本占用数据目录的空间，没有容量上限，在「设置 → 更新与维护 → 缓存管理」里显示为「离线下载转码」。手机下载完成后副本自动删除，家里其他设备还要用的除外。已知问题：其余副本没有定时清理，超过 72 小时无人访问的，要等下一次有人发起小画质下载时才删除。
- 网盘 strm 条目的原画下载经服务器中转。
- 离线观看在手机联网后同步回来，计入观看记录和播放次数。补传的观看只会向 Webhook 发「看完」事件，时间是实际看完的时间。
- 已知问题：在 iPhone 上取消或删除下载，服务器上的转码不会跟着停。已经排上的（比如一整季）仍会全部转完，副本至少保留 72 小时。要立即停止：停掉容器，删除数据目录下的 `cache/offline-exports` 文件夹，再启动容器。iPhone 上当前登录账号没下完的较小画质下载，下次打开 App 后过一会儿会自动从头开始；个别显示出错的，删掉后重新下载。
- 已知问题：转码可能一直等下去，并堵住后面的转码。可能出现在它依赖的 Mac 转码器离线时；或者服务器只有 Intel 核显、没有 Mac 转码器、软件转码没开时，部分 HDR 片和 10-bit SDR 片（这些片仍会列出小画质）。可以让转码器重新上线；或者在每台发起过这个下载的 iPhone 上删掉它，再按上一条停容器清理。

### 升级须知

- 本版包含数据库迁移，更新 Docker 镜像不会自动备份。要回到 v0.37.0：停止容器，把镜像标签改回 `movieclaw/movieclaw:v0.37.0`，恢复你做的备份后再启动。
- 服务器的 Release 不再附带各客户端安装包（Mac 转码器、Mac 版、iPhone、Android、Android TV）。各客户端单独发布，下方「客户端」一节列出最新版本。Android 的固定下载地址是 https://movieclaw.io/download/android.apk。
- Windows 1.0.x 不会自动更新到新版 Windows App，请到 https://github.com/movieclaw/MovieClaw/releases/tag/windows-v0.1.0 手动下载。
