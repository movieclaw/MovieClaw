## v0.45.0: New models show up on their own

Connect a provider once and the model menu keeps up with that provider. Series between seasons also pick up a newly announced season sooner.

> ✅ Update from Settings → Updates and maintenance. This release migrates the database and makes a backup first. MovieClaw Server 0.44.0 still runs if you restore that backup; see Before you update.

### Highlights

#### The model menu follows the provider

Open a conversation and the model menu, or set the defaults under Settings → AI preferences. After Settings → AI providers finishes a connection test, MovieClaw asks that provider which models it has. The scheduled task checks again every 6 hours, and skips a provider updated in the last 24 hours. A model newer than the built-in list shows up on its own when MovieClaw already knows its context window and how thinking works. Models it cannot describe stay out of the menu.

- Providers you already use keep their existing models. A custom endpoint with no built-in list shows at most the 12 newest models MovieClaw can describe.
- A model you already picked is still recognized, including a name saved before this release.
- Settings → Updates and maintenance → Scheduled tasks lists **Update model catalog (更新模型目录)**. It runs every 6 hours, skips a provider updated in the last 24 hours, and does nothing when no provider is connected.
- iPhone, Android and the website share this menu. You do not need a new app for it.

### Fixed

- In the sidebar, **Activity** always opens the activity overview. Back from a page inside Activity returns to that overview.
- A cloud library that does not keep a local copy waits until intro and outro detection, including the picture check, is saved before **Free local space for cloud libraries** deletes the local file. The outro is no longer cut short and then saved that way.
- A smart subscription that was created and queued, but never searched or matched, now does both.
- A series you have not subscribed to, and that is not marked ended or canceled, is refreshed every 3 days during the gap between seasons. A newly dated season and its air schedule show up before the premiere. Movies, ended shows and canceled shows are unchanged.

### For administrators

- **Update model catalog** is on and runs every 6 hours. Turn that task off under Scheduled tasks to stop it. A successful connection test still refreshes that provider.
- If the public catalog cannot be reached, MovieClaw keeps the parameters it already has, including the snapshot shipped with this version.

### Before you update

- The migration adds optional columns on each AI provider. Restoring the backup and running 0.44.0 ignores those columns.
- The migration also removes a hidden switch that could stop smart subscriptions with no control to turn them back on. Restoring an older backup brings that switch back with the rest of the database. Running 0.44.0 on this database, without that restore, does not recreate the switch, so those subscriptions keep running.

Full changes: [v0.44.0 → v0.45.0](https://github.com/movieclaw/MovieClaw/compare/v0.44.0...v0.45.0).

## 简体中文

## v0.45.0：新模型自己出现在菜单里

接上一家模型服务之后，模型菜单会跟着这家服务更新。季和季之间的空档里，新定档的一季也会更早出现。

> ✅ 在「设置 → 更新与维护」里更新。这一版会迁移数据库，并先做备份。要回到 MovieClaw 服务器 0.44.0，请恢复这份备份；见文末「升级须知」。

### 本版亮点

#### 模型菜单跟着服务商走

打开对话框里的模型菜单，或到「设置 → AI 设定」里改默认模型。在「设置 → 模型接入」里连接测试通过之后，MovieClaw 会向这家服务询问有哪些模型。定时任务每 6 小时再查一次，24 小时内更新过的会跳过。比内置清单更新的模型，只要上下文长度和思考方式已经知道，就会自己出现在菜单里。说不清参数的模型不会进菜单。

- 已经在用的服务商，原有模型都还在。没有内置清单的自定义端点，最多显示 MovieClaw 说得清的最新 12 个。
- 已经选过的模型仍然认得出，包括这一版之前记下的名字。
- 「设置 → 更新与维护 → 定时任务」里有「更新模型目录」，每 6 小时跑一次。24 小时内更新过的服务商会跳过；一个模型服务都没接时，这个任务什么也不做。
- iPhone、Android 和网页用的是同一份菜单，不必为这件事另装新 App。

### 修好了

- 侧栏的「活动」一律打开活动总览。从活动里的页面返回，回到的是这份总览。
- 网盘媒体库没有勾选「本地也保留一份」时，「网盘库腾空本地」会等片头片尾识别连同画面核对落库，再删本地文件。片尾不再被截短之后照常保存。
- 智能订阅已经建好、也显示进了队列，却一直不搜索、不匹配的，现在会做这两件事。
- 没有订阅、也没有被标成完结或取消的剧，在两季之间改为每 3 天刷新一次。新季定档之后，播出日历会赶在首播前出现。电影、已完结和已取消的剧照旧。

### 管理员须知

- 「更新模型目录」默认开着，每 6 小时跑一次。在「定时任务」里关掉它就停。某家服务商的连接测试通过时，仍会刷新这一家。
- 公共目录连不上时，MovieClaw 继续用已经有的参数，包括这一版自带的快照。

### 升级须知

- 迁移给每个模型服务商加上可空的列。恢复备份再跑 0.44.0 时，这些列会被忽略。
- 迁移同时去掉一个藏起来的开关。它能让智能订阅停住，而界面上没有地方把它重新打开。恢复更早的备份时，这个开关会跟数据库一起回来。不恢复备份、直接用这份数据库跑 0.44.0，不会把开关造回来，这些订阅会继续运行。

完整改动：[v0.44.0 → v0.45.0](https://github.com/movieclaw/MovieClaw/compare/v0.44.0...v0.45.0)。
