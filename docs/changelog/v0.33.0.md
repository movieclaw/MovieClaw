## v0.33.0: Tell it what you want, let it pick the release

Subscriptions can now pick releases for you: say what quality you want and how long you're willing to wait. MovieClaw also gets its first Android app, and WeChat or Telegram no longer gets a message for every episode of a season.

> ✅ No Docker image update is required. Update from Settings → Update & Maintenance.

### Highlights

#### Subscribe without building a rule group first

Until now, a subscription only knew what to download through a rule group you had to set up. Pick **Smart selection (智能选择)** instead: set the resolution and source you prefer and how long to wait for them, once for movies and once for shows. A matching release is downloaded as soon as it appears. If none turns up in time, the best acceptable one is taken, and a show keeps to the same release where it can. Administrators set it up under Settings → Subscription Rules (订阅规则) → Smart selection, or straight from the subscribe dialog.

- It is the default for new subscriptions on the web and in iPhone 0.6.0. To use a rule group, open More options (更多选项) → Selection method (选择方式) → **Rules (规则模式)**.
- Options: 4K or 1080p; WEB-DL, Blu-ray or Remux; wait not at all, up to 3 hours, 1 day, or 1 to 7 days; allow later upgrades; accept only the chosen resolution.
- A subscription keeps the settings it was created with. Later changes apply to new subscriptions only, and a subscription can't switch between smart and rules.
- Each episode or movie shows how long it will wait and the current candidate. You can **Download current candidate now (立即下载当前候选)** or extend the wait.
- Only administrators change the settings. Members can subscribe this way once an administrator has saved them.
- Existing subscriptions keep their rule groups. Android and the AI assistant still create rule-based subscriptions.

#### MovieClaw on Android

Android phones had only the web app. The new Android app browses your libraries, discover, search and subscriptions, and plays with subtitle and audio switching, skip intro and AI subtitles. Download https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-Android-arm64.apk, install it and sign in with your server address, user name and password.

- Needs Android 8.0 or later on an arm64 phone or tablet. Android asks you to allow installing unknown apps.
- If you installed an earlier test build of this app, uninstall it first; it is signed differently.
- No push notifications: the app itself checks for new notices about every 15 minutes.
- Smart selection, subscription rules, sites and downloaders are managed on the web.
- Disc images (ISO) play only when the server address is http, not https.
- The interface is in Chinese only.

#### One message per season, not one per episode

WeChat, Telegram and other IM channels used to get a message for every download, every import and every upgraded episode. Now a batch of episodes shares a few messages: when the download starts, when the first episodes can be watched, when everything has arrived, and when something is stuck. Episodes are written as ranges, such as 第 1–8 集. This applies automatically after the update.

- Upgrades are merged per subscription. Episodes you removed from a subscription no longer send messages.
- The iPhone app's expandable notification cards need push, which the sideloaded iPhone app does not receive.

### New features

- **Discover**: On the web, Discover Movies (发现电影) and Discover Shows (发现剧集) are now one **Discover (发现)** entry. Switch between movies and shows, or TMDB and Douban, from the page title. On phones the web app now opens on Library.
- **Transcoder limits**: Under Settings → Playback (播放), choose how many jobs (1–4) each Mac transcoder runs. The page also shows its chip, memory and load, and playback in the browser through it starts sooner.
- **Naming templates**: Templates no longer have to include the title, season or episode. Known issue: a file-name template of only `{release_name}` renames scanned files to 未命名 when you organize a library. This is fixed in v0.35.0; update to get the fix.

### Improvements

- **Same-name movies**: When a release can't be told apart from another movie with the same title and year, the subscription skips it and keeps looking. It no longer pauses and raises an alert for you to confirm, and such alerts left from before clear after the update.
- **Settings on the web**: Switches save at once and text saves when you leave the field. Dangerous actions sit at the bottom or in ⋯.
- **Downloaders and sites** are added and edited in a side panel. Clicking outside it or pressing Esc discards what you typed.
- **Rule preview**: The **Simulate (模拟一单)** panel is now **Preview matching (预览匹配)** under Subscription Rules → Custom rules.
- **Devices**: Devices are grouped into four kinds, each listing up to five online. **View all (查看全部)** opens the full list.
- **iPhone settings**: Server Settings (服务器设置) is redesigned, with device search, a page per member and Fanart.tv setup.
- **Subtitles**: Web, iPhone and Mac menus show each track's own name, such as 简体中文特效, and mark forced subtitles.

### Fixed

- Shared links (分享) now play. Since v0.28.0, starting playback from one failed with a server error.
- A show's poster no longer gets replaced by an episode thumbnail, on the web and in Jellyfin players such as Infuse.
- Opening a title in Infuse or another Jellyfin player no longer shows it as playing under Activity (活动).
- Plus 6 smaller fixes.

### For administrators

- The Mac transcoder's job limit is now stored on the server. Older transcoders still work, but the limit can't be changed from the web until you update: https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClawTranscoder-macos-arm64.zip.

### Before you update

- This release migrates the database. After an in-app update, you can return to v0.32.0 under Settings → Update & Maintenance → **Choose a version to roll back… (选择版本回退…)**. It restores the automatic backup taken before the update, and data added since is lost.
- If you updated by pulling the Docker image, there is no automatic backup. To return, stop the container, change the image tag to `movieclaw/movieclaw:v0.32.0`, restore your own backup of the data directory, then start it.
- Changes listed for iPhone need app 0.6.0: https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-iOS-unsigned.ipa. The Mac app is at https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-macos-arm64.zip.
- Older apps keep working with this server but can't create smart subscriptions. With app 0.6.0 on an older server, choose Rules to subscribe.

Thanks to @anlan-home for the Android app, and to @WadeChenn for improving it. Full changes: [v0.32.0 → v0.33.0](https://github.com/movieclaw/MovieClaw/compare/v0.32.0...v0.33.0).

## 简体中文

## v0.33.0：说出想要什么，版本交给它挑

订阅现在可以替你挑版本：说清想要的画质和愿意等多久就行。MovieClaw 也有了第一个 Android App。整季下载时，微信、Telegram 不会再一集一条地发消息。

> ✅ 本版无需更新 Docker 镜像，在「设置 → 更新与维护」里更新即可。

### 本版亮点

#### 订阅前不用先配规则组

以前订阅只能靠你事先配好的规则组来决定下什么。现在可以选「智能选择」：电影和剧集各设一次，选好想要的分辨率、片源和最多等多久。符合要求的版本一出现就下载。等到期还没有，就下当前最好的合格版本，剧集也会尽量跟着同一个版本。管理员在「设置 → 订阅规则 → 智能选择」里设置，或者直接在订阅弹窗里设置。

- 网页和 iPhone 0.6.0 新建订阅时默认用智能选择。要用规则组，在「更多选项 → 选择方式」里选「规则模式」。
- 可选项：4K 或 1080p；WEB-DL、蓝光或 Remux；不等待、最多 3 小时、1 天或自定义 1～7 天；是否允许后续洗版；是否只接受所选分辨率。
- 订阅会按创建时的设置执行。之后改设置只影响新订阅，已有订阅也不能在智能和规则之间切换。
- 订阅详情会写明每集或每部片最晚等到什么时候、当前候选是哪个，可以「立即下载当前候选」或延长等待。
- 只有管理员能改设置。管理员保存过以后，成员也能用智能选择订阅。
- 已有订阅继续用原来的规则组。Android 和 AI 助手创建的仍是规则订阅。

#### 在 Android 上看片

以前 Android 手机只能用网页。新的 Android App 能浏览媒体库、发现、搜索和订阅，播放时能切换字幕和音轨、跳过片头、生成 AI 字幕。下载 https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-Android-arm64.apk 安装后，输入服务器地址、用户名和密码登录。

- 需要 Android 8.0 或更新版本，arm64 的手机或平板。安装时系统会要求允许安装未知应用。
- 装过这个 App 早期测试包的，先卸载它，签名不同。
- 没有推送，App 自己大约每 15 分钟检查一次新通知。
- 智能选择、订阅规则、站点和下载器在网页端管理。
- 光盘镜像（ISO）只在服务器地址是 http 时能播，https 不行。
- 界面只有中文。

#### 一季一组消息，不再一集一条

以前每次下载、每次入库、每集洗版，微信、Telegram 等 IM 通道都会各收到一条消息。现在同一批剧集共用几条：开始下载时、前几集可以先看时、全部到齐时，以及卡住时。集数写成区间，比如「第 1–8 集」。升级后自动生效。

- 洗版消息按订阅合并。已经从订阅里移出的季集不会再发消息。
- iPhone App 的可展开通知卡片依赖推送，侧载的 iPhone App 收不到推送。

### 新功能

- **发现**：网页的「发现电影」「发现剧集」合并成一个「发现」入口。电影和剧集、TMDB 和豆瓣都在页面标题处切换。手机上的网页现在打开后先进媒体库。
- **转码并发**：在「设置 → 播放」里为每台 Mac 转码器设置同时转码的任务数（1～4 路），页面还会显示它的芯片、内存和负载；网页经它播放时起播更快。
- **命名模板**：模板不再必须包含片名、季号或集号。已知问题：文件名模板只用 `{release_name}` 时，整理媒体库会把扫描入库的文件改名为「未命名」。已在 v0.35.0 修复，升级即可。

### 体验改进

- **同名电影**：资源无法和同名同年的另一部电影区分时，订阅会跳过它继续找，不再停下来发告警等你确认。之前留下的这类待确认告警，升级后会自动消失。
- **网页设置**：开关改完即存，文本离开输入框就保存。危险操作放到页底或 ⋯ 菜单里。
- **下载器和站点**改在侧边面板里新增和编辑。在面板外点一下或按 Esc，已填的内容会直接丢弃。
- **规则预览**：「模拟一单」改为「订阅规则 → 自定义规则」里的「预览匹配」。
- **设备**：设备分四类显示，每类最多列出 5 台在线设备，点「查看全部」看完整列表。
- **iPhone 设置**：「服务器设置」改版，支持搜索设备、给每个成员单独的详情页，也能配置 Fanart.tv。
- **字幕**：网页、iPhone 和 Mac 的字幕菜单显示每条轨道自己的名字（如「简体中文特效」），并标出强制字幕。

### 修好了

- 分享链接现在能播放了。从 v0.28.0 起，用分享链接起播会报服务器错误。
- 剧集海报被单集缩略图顶替的问题已修复，网页和 Infuse 等 Jellyfin 播放器都不会再出现。
- 在 Infuse 等 Jellyfin 播放器里打开影片详情，「活动」里不会再误显示为正在播放。
- 以及 6 处细节修复。

### 管理员须知

- Mac 转码器的并发上限改为保存在服务器上。旧版转码器照常能用，但更新前不能在网页里调整上限：https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClawTranscoder-macos-arm64.zip。

### 升级须知

- 本版包含数据库迁移。走应用内更新的，可以在「设置 → 更新与维护 → 选择版本回退…」里回到 v0.32.0。回退会恢复更新前自动生成的备份，之后新增的数据会丢失。
- 拉取 Docker 镜像升级的没有自动备份。要回退：停止容器，把镜像标签改回 `movieclaw/movieclaw:v0.32.0`，恢复你自己备份的数据目录后再启动。
- 文中 iPhone 的改动需要 App 0.6.0：https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-iOS-unsigned.ipa。Mac 版在 https://github.com/movieclaw/MovieClaw/releases/download/v0.33.0/MovieClaw-macos-arm64.zip。
- 旧版 App 连这台服务器照常能用，只是不能创建智能订阅。0.6.0 的 App 连旧服务器时，订阅请选「规则模式」。
