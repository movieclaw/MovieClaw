## v0.16.0: Less wasted work when playing and downloading

Disconnected streams no longer keep reading the entire film. Playback and downloads use less CPU and memory, and the external application port can be changed in settings.

> ⚠️ **A Docker image update is required.** Container entry and port handling have changed. Pull `movieclaw/movieclaw:v0.16.0` and recreate the container.

### Highlights

#### Close playback or cancel a download, and disk reads stop

After seeking or disconnecting, old requests could keep reading tens of gigabytes and compete with active playback. They now stop promptly. Video traffic also avoids one forwarding layer, with significantly lower CPU usage and normal memory use in same-machine tests.

#### Change the service port from settings

Application Settings includes the external port. Restart to apply it; an occupied port falls back to the previous working port. Host-network and native deployments can use this directly, while bridge deployments should generally change the Compose port mapping.

### More features and improvements

- **Faster qBittorrent status refreshes**: Reuse connections and login sessions instead of reconnecting on every poll.
- **A continuous startup entry point**: A Starting page remains available through startup or restarts.
- **Updated bundled recognition model**: Includes `torrent-ner-v3` for better season and episode recognition in individual filenames.
- **More stable layouts**: Downloader settings expand one item at a time, with improved backdrop scrolling and task-center layout.

### Before you update

- Older images cannot install this version through an in-app update alone.
- Existing model v3 installations are unaffected. Fresh installations from the new image use v3 immediately.

Full changes: [v0.15.0 → v0.16.0](https://github.com/movieclaw/MovieClaw/compare/v0.15.0...v0.16.0).

## 简体中文

## v0.16.0：播放和下载，少让 NAS 白忙

这一版修复连接断开后仍继续读完整部影片的问题。播放与下载更省 CPU 和内存，应用对外端口也能在设置里修改。

> ⚠️ **本版需要更新 Docker 镜像**：容器入口与端口处理方式已变化，请拉取 `movieclaw/movieclaw:v0.16.0` 并重建容器。

### 本版亮点

#### 关掉播放或取消下载，读盘及时停下来

以前拖动进度或断开连接后，旧请求可能继续读完几十 GB 的文件，挤占真正的播放和下载。现在连接断开后及时停止，视频流也减少了一层转发，同机测试中 CPU 开销明显降低，内存回到正常范围。

#### 想换服务端口，在设置里改

「设置 → 应用设置」新增对外端口配置，修改后重启生效。端口被占用时会回退到上一个可用端口。host 网络或裸机部署可以直接使用；桥接部署仍建议修改 Compose 的端口映射。

### 其他新功能与改进

- **qBittorrent 状态刷新更快**：复用连接和登录会话，减少每次轮询的连接开销。
- **启动入口持续可用**：启动或重启期间显示「正在启动」占位页。
- **识别模型随镜像更新**：内置 `torrent-ner-v3`，改善单集文件名的季集识别。
- **界面细节**：下载器设置改为单项展开，详情页背景滚动和任务中心排版更稳定。

### 升级须知

- 旧镜像不能通过应用内更新直接升到本版。
- 已单独安装模型 v3 的实例不受影响，新镜像的新装实例直接使用 v3。

完整改动见 [v0.15.0 → v0.16.0](https://github.com/movieclaw/MovieClaw/compare/v0.15.0...v0.16.0)。
