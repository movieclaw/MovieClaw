## v0.49.1: Long-running series land in the right season

Long-running anime that number episodes continuously across seasons are now matched, downloaded, and filed under the right TMDB season. Refreshed tracker entries also get another chance when their seed count or other matching details improve.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release has one database migration; the in-app updater backs up the database before applying it.

### Highlights

#### Continuous episode numbers no longer confuse seasons

Some long-running series keep counting upward instead of restarting at episode 1 each season. MovieClaw now uses the complete TMDB season ranges to understand season-local numbers, official continuous numbers, and releases fixed to S01. The same interpretation follows a title through subscription matching, file selection, download verification, import, and library scanning. Ambiguous, out-of-range, E00, or unreadable candidates are rejected with an explanation instead of being guessed.

### More features and improvements

- **Refreshed torrents are reconsidered**: An existing tracker entry that was rejected for too few seeders or incomplete metadata is queued again when a matching field really changes. This also survives a service restart, and a busy set of frequently changing entries no longer starves the rest of the queue.

### Fixed

- Updating only one default AI model with `mclaw llm defaults update` could silently reset the other model to automatic selection. Omitted fields now keep their current values; an explicit null still returns only that field to automatic selection.
- Opening **Hand to Agent** from a failed subtitle job, notice, or download could fail when the diagnostic report exceeded the conversation limit. Oversized reports are now bounded while retaining the identifiers the Agent needs to read the full details.
- A subtitle job that exhausted validation retries could incorrectly recommend a model with a larger output budget. The message now distinguishes truncated output from output that did not satisfy the required format.
- In bilingual subtitle generation, the reading-speed warning counted the second, usually original-language line as if it were translated text. The completion message now counts only the translated line and records the second line separately.

### Before you update

- This release adds a persistent queue marker to tracker entries. The in-app updater creates its usual database backup. For a manual container update, stop the service and back up the data directory first; restore that backup before rolling back to 0.49.0.
- The Docker runtime remains 25, so the application can be updated without changing the runtime image.

Full changes: [v0.49.0 → v0.49.1](https://github.com/movieclaw/MovieClaw/compare/v0.49.0...v0.49.1).

## v0.49.1：长篇剧集会落进正确的季

长篇动画按跨季连续集号发布时，现在能匹配、下载并归入正确的 TMDB 季。站点里已经见过的种子，如果做种数或其他匹配信息后来变好，也会重新获得一次匹配机会。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版有一次数据库迁移；应用内更新会在执行前备份数据库。

### 本版亮点

#### 连续集号不会再把季弄乱

有些长篇剧集换季后不从第 1 集重新编号，而是一直往下数。MovieClaw 现在会用完整的 TMDB 季区间，统一理解季内集号、官方连续集号，以及固定写成 S01 的资源。同一套解释会贯穿订阅匹配、文件选择、下载核验、入库和媒体库扫描。遇到多种可能、越界、E00 或读不到文件清单的候选时，会说明原因并拒绝，不再猜测。

### 其他新功能与改进

- **刷新过的种子会重新评估**：已经因为做种数太少或资料不完整而被拒绝的站点条目，只要匹配会用到的字段真的变了，就会重新排队。服务重启后队列仍在；一批频繁变化的热门条目也不会一直挡住后面的候选。

### 修好了

- 用 `mclaw llm defaults update` 只更新一个默认 AI 模型时，另一个模型可能被静默改回自动推荐。现在没传的字段保持原值；显式传 null 仍只把对应字段改回自动推荐。
- 字幕任务、告警或下载失败后点「交给 Agent」，诊断工单太长时可能无法创建会话。现在会控制工单长度，并保留让 Agent 重新读取完整详情所需的标识。
- 字幕任务因为格式校验反复失败而终止时，提示可能误导用户换成输出预算更大的模型。现在会区分输出被截断和输出格式不合要求两种情况。
- 生成双语字幕时，超读速提示会把第二行通常作为原文的字幕也算成译文。完成提示现在只统计第一行译文，第二行另行记录。

### 升级须知

- 这一版给站点种子增加持久的待重评标记。应用内更新会照常自动备份数据库。手动更新容器时，请先停服务并备份数据目录；要回退到 0.49.0 时，先恢复这份备份。
- Docker 运行时仍是 25，不换运行时镜像也能更新应用。
