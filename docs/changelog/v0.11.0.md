## v0.11.0: Find new episodes sooner, with a fallback for stalled downloads

Subscriptions use airing schedules to look for new resources and can replace downloads that stop making progress. Completed episodes in a season pack can be imported before the whole pack finishes.

✅ If you already use the image for v0.10.0, no Docker image update is required. Update from **Settings → Application**.

### Highlights

#### Subscriptions watch for the likely release window

Episode schedules, tracker time zones and historical release times help predict when a resource may appear. Subscriptions check within that window, and saved forecasts continue after restarting.

#### Look for a healthier torrent when a download stops moving

After a prolonged lack of meaningful progress, a subscription can search for replacements and record its attempts. Before removing the old task, it checks ratio, seeding and hit-and-run risks. Queued or checking tasks are not casually mistaken for stalled downloads.

#### Import finished episodes while the rest keeps downloading

Fully downloaded video files in qBittorrent and Transmission can be identified and organized early. Remaining files keep downloading, and the task center shows download, import and replacement history.

### More features and improvements

- **Separate future-episode tracking**: Continuing to follow new episodes is distinct from pausing the current subscription.
- **Clearer task details**: Added failure reasons, import history, replacement actions and mobile cards.
- **Easier CLI downloads**: Preview destinations from search results using the same routing rules as the web interface.
- **More accurate timing**: Consistent tracker time conversions improve forecasts and download status.

### Fixed

- If a completed torrent clearly lacks promised episodes, only those missing episodes return to search.
- Full-series packs no longer implicitly promise specials, avoiding waits for nonexistent files.
- Improved partial-import retries, root-path reconciliation and download-state synchronization.

### Before you update

- This release updates the database and corrects some historical tracker timestamps. Restore the automatic pre-update backup when rolling back across versions.

Full changes: [v0.10.0 → v0.11.0](https://github.com/movieclaw/MovieClaw/compare/v0.10.0...v0.11.0).

## 简体中文

## v0.11.0：追更新集少等一会，下载卡住也有后手

这一版让订阅结合播出时间寻找新资源，下载长期没有进展时尝试替换。整季包里已经下好的集，也可以提前入库。

✅ 已使用 v0.10.0 对应镜像的用户无需更新 Docker 镜像，在「设置 → 应用」一键更新即可。

### 本版亮点

#### 新集什么时候有资源，订阅会提前留意

订阅结合剧集播出计划、站点时区和历史发布时间，预测资源可能出现的窗口，并在窗口内主动探测。预测会保留，重启后还能继续追踪。

#### 下载一直不动，自动寻找更健康的资源

长时间没有有效进度时，订阅可以重新搜索替代种子，并记录换源过程。清理旧任务前会检查分享率、做种和 H&R 风险，排队或校验中的任务也不会轻易被当成卡死。

#### 整季还没下完，完整的单集先入库

qBittorrent、Transmission 中已经完整下载的视频文件，可以先识别和整理，其余文件继续下载。任务中心能看到下载、入库和替换过程。

### 其他新功能与改进

- **追未来新集可单独开关**：持续追新与暂停当前订阅分开控制。
- **任务详情更好查**：补上失败原因、入库历史、换源入口和手机卡片布局。
- **命令行下载更方便**：搜索结果可直接预检下载目标，复用网页的路由规则。
- **时间显示更准确**：统一站点时间换算，预计发布和下载状态更可靠。

### 修好了

- 完成的种子明确缺少承诺集数时，缺集会退回重找。
- 全集包不再默认承诺特别篇，避免一直等不存在的文件。
- 改善分批入库重试、根路径对账和下载状态同步。

### 升级须知

- 本版会更新数据库，并修正部分站点的历史时间。如需跨版本回退，请用更新前自动生成的备份恢复。

完整改动见 [v0.10.0 → v0.11.0](https://github.com/movieclaw/MovieClaw/compare/v0.10.0...v0.11.0)。
