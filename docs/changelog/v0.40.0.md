## v0.40.0: Your library on a cloud drive

A library can now live on a 115 cloud drive (beta, through a plugin): bring in what's already on the drive, move new downloads there and free up the disk at home. New episodes of shows you follow are also found sooner after they're published.

> ✅ No Docker image update is required. Update from Settings → Update & Maintenance.

### Highlights

#### Out of disk space at home? Keep the library on 115

A full NAS used to mean buying disks or deleting films, and films already on a cloud drive couldn't join the library. Now an administrator installs the 115 plugin, signs in, and adds 115 folders to a library: their videos are identified by file name, without downloading or changing anything on the drive. Make a 115 folder the library's primary root, and new downloads play right away, then upload to 115 and free their local space.

How to get started:

1. Download `cloud-115-0.1.0-beta.1.mcplugin` from https://github.com/movieclaw/movieclaw-plugins/releases/tag/cloud-115-v0.1.0-beta.1 (all official plugins: https://github.com/movieclaw/movieclaw-plugins/releases).
2. Settings → Plugins → **Upload plugin package (上传插件包)**, then approve it. Approval downloads the Python packages it depends on from PyPI, or from the mirror set under Settings → Network.
3. Settings → Cloud Drive → **Add cloud drive account (添加网盘账号)**: scan the QR code, or import cookies from the browser extension.
4. Media library management → edit a library → the **＋ 115 网盘目录** button.

- The plugin is a beta under GPL-3.0. Without a drive plugin, nothing changes and no drive settings appear.
- Drive accounts and folders are managed on the web only. Apps can play these files.
- Away from home, drive files play through your home server, unless one person is away using an app that can fall back on its own (Mac 0.9.1 for now): then it streams straight from the drive. Change this under Settings → Playback → **Playing cloud-drive files away from home (在外面播放网盘上的片子)**.
- Deleting a title also deletes its drive copy, into 115's recycle bin. When MovieClaw's own recycle bin would automatically purge more than 50 drive files or 200 GB at once, it holds off and sends a notice so you can purge by hand.
- Discs, ISOs and extras on the drive are skipped. See them in Media library management, on the library's ··· menu → **纳管报告**.

#### New episodes show up sooner

Release-time forecasts could be hours off for shows that air twice a day or have one odd release, so new episodes waited for the next routine site check. Forecasts now learn from the same time slot and from multi-episode packs, and check most often right around the expected moment. In our replay of real tracking data, the median time from publish to discovery dropped from about 2 hours to under 15 minutes. This applies automatically.

### More features and improvements

- **Plugins can bring Python packages**: before approving, you see each package, its size and whether it has native code. Download them through a mirror under Settings → Network → **Plugin dependencies (插件依赖)**.
- **Smart subscription settings apply to existing subscriptions**: saving the movie or TV preferences under Settings → Subscription Rules updates running subscriptions too. A shorter wait applies at once; a longer one doesn't push back an episode already waiting.
- **Android updates through your server**: Android 0.5.0 and Android TV 0.4.0 can fetch their own updates through this server when GitHub is unreachable, using its proxy and mirror settings.

### Fixed

- A smart subscription could grab a season pack from another show with the same name that lacked the wanted episodes. It then stayed stuck submitting and looked complete. Those episodes now go back to searching.
- Packs of a same-name show that declare far fewer episodes than the season has aired (such as "全8集" for a 13-episode series) are no longer downloaded as that show.
- Titles with TrueHD audio that needed converting, such as Dolby Vision films on a TV without Dolby Vision, failed to start on Android.
- Seasons whose first audio track is Audio Vivid (common in some Chinese WEB-DLs) got no intro, outro or ad markers. Episodes that failed this way are retried after the update.
- On the same files, the sync check for generated subtitles now uses an audio track it can decode.
- When playback was capped to a lower bitrate, such as away from home, 7.1 audio converted to 5.1 lost its center and surround channels.

### For administrators

- Drive features are admin-only.
- In a library whose primary root is on the drive, local copies are removed by default once the upload is verified. This also applies to files already in the library, uploaded newest first. Turn on **Keep a local copy (本地也保留一份)** when editing the library to keep both.
- Settings → Cloud Drive → **Delete download tasks after local copies are freed (本地腾空后删除下载任务)** is on by default. It deletes the downloader task and its data; torrents with H&R, not sent by MovieClaw or still feeding local files are kept.
- Uploads use your home upload bandwidth and pause while someone is streaming from outside. Background drive work stops at 70% of each account's daily request budget, keeping the rest for playback.

### Before you update

- This release migrates the database. To return to v0.39.0, use Settings → Update & Maintenance → **Roll back to an earlier version (回退到历史版本)**. It restores the backup taken before the update, so anything since is lost, including drive accounts and libraries added in this version. Files already uploaded and freed locally stay only on 115, and v0.39.0 can't play them. If you update by pulling the Docker image instead, no backup is made, so stop the container and back up the data directory first.

## v0.40.0：媒体库放上网盘

媒体库现在可以放在 115 网盘上（通过插件，内测）：网盘上已有的片子能直接加进库，新下载的片子传到网盘，腾出家里的硬盘。追的剧出了新一集，也会更快被发现。

> ✅ 不需要更新 Docker 镜像，在「设置 → 更新与维护」里一键更新即可。

### 本版亮点

#### 家里硬盘满了？把媒体库放到 115

以前 NAS 满了只能加硬盘或删片，网盘上已有的片子也进不了媒体库。现在管理员装好 115 插件、登录账号，就能把 115 上的文件夹加进媒体库：里面的片子按文件名识别，不下载、不改动网盘上的文件。把 115 文件夹设为库的主根后，新下载的片子入库立即能看，随后传到 115、腾出本地空间。

开始使用：

1. 从 https://github.com/movieclaw/movieclaw-plugins/releases/tag/cloud-115-v0.1.0-beta.1 下载 `cloud-115-0.1.0-beta.1.mcplugin`（全部官方插件见 https://github.com/movieclaw/movieclaw-plugins/releases）。
2. 「设置 → 插件 → 上传插件包」，再批准安装。批准时会从 PyPI（或「设置 → 网络」里设的镜像）下载它依赖的 Python 包。
3. 「设置 → 网盘 → 添加网盘账号」：扫码登录，或用浏览器扩展导入 Cookie。
4. 「媒体库管理」里编辑一个库，点带 ＋ 号的「115 网盘目录」按钮。

- 插件是内测版，以 GPL-3.0 发布。不装网盘插件就什么都不变，也看不到网盘相关的设置。
- 网盘账号和目录只能在网页上管理，各个 App 都能播放这些片子。
- 在外面播放网盘上的片子经家里转发；只有一个人在外面、用的又是能自己改走转发的 App（目前是 Mac 0.9.1）时，才直连网盘。可以在「设置 → 播放 → 在外面播放网盘上的片子」里改。
- 删除影片会连网盘上的副本一起删，进 115 的回收站。MovieClaw 自己的回收站到期自动清理时，一次涉及超过 50 个网盘文件或 200 GB 就先不删，发系统通知等你手动清理。
- 网盘上的原盘、ISO 和花絮会跳过，在「媒体库管理」里库那一行的「···」→「纳管报告」里能看到。

#### 新一集更早被发现

以前一天更两集、或者偶尔错时发布的剧，预测的发布时间可能差好几个小时，新一集只能等下一轮例行刷新站点才被发现。现在预测只参考同一时段的发布记录，也会参考多集合集，并在预计发布的那一刻前后查得最勤。在我们用真实追剧数据回放的测试中，新一集从发布到被发现的中位时间从约 2 小时缩短到 15 分钟以内。升级后自动生效。

### 其他新功能与改进

- **插件可以带 Python 包**：批准前能看到每个包、大小和是否含本机代码。可以在「设置 → 网络 → 插件依赖」里换成镜像下载。
- **智能订阅设置对已有订阅生效**：在「设置 → 订阅规则」里保存电影或剧集偏好后，已有的订阅也跟着改。等待时间改短立即生效；改长不会推迟已经在等的集。
- **安卓经服务器更新**：Android 0.5.0 和 Android TV 0.4.0 连不上 GitHub 时，可以经这台服务器下载更新，走服务器的代理与镜像设置。

### 修好了

- 智能订阅可能抓到同名另一部剧的整季合集，里面没有要的集数。之后订阅会一直停在「提交中」，还显示为已完成。这个问题已修复，这些集会回到寻找中。
- 同名剧的合集声明的集数远少于这一季已播的集数时（如 13 集的剧遇上「全8集」），不会再被当成这部剧下载。
- 需要转码的 TrueHD 音轨片子（如在不支持杜比视界的电视上播杜比视界电影），在安卓上起播失败的问题已修复。
- 第一条音轨是 Audio Vivid（菁彩声，部分国内 WEB-DL 常见）的剧，整季识别不出片头、片尾和广告。这个问题已修复，之前因此失败的集升级后会自动重试。
- 同样的片子，生成字幕的音画同步检查现在也会换用能解码的音轨。
- 限码率转码时（比如在外面看），7.1 音轨转成 5.1 后中置和环绕没有声音的问题已修复。

### 管理员须知

- 网盘功能只有管理员能用。
- 主根在网盘的库，上传核验后默认删掉本地那份；库里已有的本地文件也一样，从新到旧逐个上传。编辑库时打开「本地也保留一份」，两边就都保留。
- 「设置 → 网盘 → 本地腾空后删除下载任务」默认开启，会删除下载器里的任务和下载的数据；有 H&R 考核的、不是 MovieClaw 投递的、还供着库里本地文件的种子会保留。
- 上传占用家里的上行带宽，外面有人看片时自动暂停。网盘的后台任务用到每个账号每日请求预算的 70% 就停，余量留给播放。

### 升级须知

- 这一版会迁移数据库。要回到 v0.39.0，到「设置 → 更新与维护 → 回退到历史版本」，它会恢复更新前的自动备份，之后的改动都会丢失，包括这一版里添加的网盘账号和媒体库。已经传到网盘并腾空本地的文件只在 115 上，v0.39.0 播不了。如果你是拉取 Docker 镜像更新的，不会自动备份，请先停止容器并备份数据目录。
