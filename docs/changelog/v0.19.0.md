## v0.19.0：NAS 没显卡，把转码交给 Mac

这一版带来可直接下载的 Mac 转码器，设备通过配对码授权。刮削语言、图片和文件命名可以按库配置，大库整理与 Infuse 浏览也更快了。

> ⚠️ **本版需要更新 Docker 镜像**：远程转码连接、命令行与运行时依赖已更新，请拉取 `movieclaw/movieclaw:v0.19.0` 并重建容器，再进行应用内更新。

### 本版亮点

#### 让一台 Mac，替 NAS 做硬件转码

在 Release 附件下载 Mac 转码器，在「设置 → 播放 → 远程转码」接入。支持 Apple Silicon、macOS 12 及以上，不需要把 NAS 挂载到 Mac；转码器读取源视频、把播放分片回传服务器，离线时播放器会按原有链路重试或降级。

#### 连命令行和转码器，不用再手抄令牌

客户端显示配对码，管理员在「设置 → 成员与设备 → 设备」核对并批准。已授权设备可查看最近活动、单独撤销；无人值守机器还可以创建手工令牌。mclaw 改为独立二进制，Linux、macOS、Windows 都能下载使用。

#### 片库怎么命名、选什么图，按你的习惯来

「设置 → 媒体库 → 刮削与整理」可以配置元数据语言顺序、海报与背景偏好、目录和文件命名模板，以及图片、NFO、分集剧照写入开关。不同媒体库可以覆盖全局设置，默认行为沿用原来的规则。

### 其他新功能与改进

- **蓝光原盘自动入库**：保留完整目录树，按主播放列表识别电影；拿不准的布局等待人工处理。
- **大库整理更快**：减少进度记录和广播的重复开销，整理时其他接口也更少受影响。
- **Infuse 首屏浏览提速**：列表先取必要信息，减少启动扫描的等待。
- **失败任务可以忽略**：侧栏警示能清掉，必要时可撤销；媒体库待处理入口也始终能找到。
- **订阅库存更明确**：电影标出已入库，剧集标出已收齐；豆瓣分季作品能更准确地对应订阅季。
- **设置重新分组**：新增概览与开局指引，「应用」改名「更新与维护」。

### 修好了

- SMB、NFS 上下载完成却一直没有入库记录的问题，有了定期巡检兜底。
- 下载器里的旧种子已消失时，订阅不再永久卡在「已投递」。
- 泛指 HDR 的资源不再被无条件排除，入库实测规格与种子声明不符时会提醒复查。
- 首次同意软件转码后按钮没反应、关闭播放后转码仍继续的问题得到修复。
- iPhone 本可直出的影片不再误转码，远程转码器掉线也不再作废已缓存分片。
- 原盘分段不再被当成独立电影，下载器失联时也不会猜测文件已经完成。
- Remux 标记、附属图片和预览文件在整理与转移时保留得更完整。

### 升级须知

- 仓库已迁到 movieclaw 组织，旧地址会自动跳转，已有部署无需修改。
- `mclaw login` 改为设备配对，不再接受密码；退出 CLI 只清本地凭证，停用设备请在网页里撤销。
- 多盘合集、剧集原盘等复杂原盘布局暂需人工处理。

完整改动见 [v0.18.0 → v0.19.0](https://github.com/movieclaw/MovieClaw/compare/v0.18.0...v0.19.0)。
