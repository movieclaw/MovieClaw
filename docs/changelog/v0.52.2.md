## v0.52.2: A stability update

AI subtitle generation now catches offloaded local files during preflight instead of failing after submit, clears superseded failed subtitle jobs from Activity automatically, keeps dismissed failures from overriding successful files on detail pages, preserves configured LLM test models on partial updates, and guards watch-history imports against reused member IDs.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release includes a no-op compatibility database migration; an in-app update backs up SQLite before switching versions.

### Fixed

- After a cloud-drive copy was verified and the local video file was offloaded, **Generate AI subtitles** preflight could still pick an embedded subtitle or audio track and appear ready to start, then fail on submit with `"The reference subtitle cannot be read. Check the file and try again."`. Preflight now checks local source-file readability up front and blocks unreadable embedded and audio tracks with the same message; readable external subtitle files can still be selected manually.
- When AI subtitle generation failed earlier and later succeeded for the same file and target language, the older failed jobs remained in **Activity → Needs attention** until dismissed manually. Succeeding now clears earlier failed jobs for the same file and subtitle target automatically, and startup reconciliation clears legacy failures that already have a newer retained success while preserving manual dismiss/undismiss choices, failure records, and retry actions.
- Dismissing an older failed AI subtitle job could push it ahead of newer jobs and make the item detail page keep showing **AI subtitles incomplete**, or reopen the dismissed failure instead of opening **Generate AI subtitles** on an already-generated file. Dismissing or undismissing jobs no longer overtakes newer jobs, and detail pages ignore dismissed failures when choosing the current badge and click action.
- Editing unrelated fields of an LLM provider without resending the connection-test model (such as from older iOS builds) reset the configured test model to the first catalog entry, which could mark a working provider as failed. Omitting the test model on update now preserves the existing model while it remains compatible.
- A background watch-history import could run after the bound member was deleted and write history into a new member that reused the same numeric ID. Watch-history imports now verify member identity when provided and reject stale bindings with a conflict.

### Before you update

- The Docker runtime stays 25, so updating from **Settings → Updates and maintenance** does not require a new image.
- This release advances the database migration version via a no-op compatibility migration without changing any table schema. To roll back to 0.52.1 after an in-app update, use **Roll back to a previous version** to restore the pre-update SQLite backup together with 0.52.1.
- For a Docker image upgrade, stop the container and back up its data directory first. To roll back, restore that backup and switch the image tag back to `v0.52.1`.

Thanks to @o1xhack. Full changes: [v0.52.1 → v0.52.2](https://github.com/movieclaw/MovieClaw/compare/v0.52.1...v0.52.2).

## v0.52.2：稳定性更新

本地影片腾空后，「AI 生成字幕」会在预检阶段直接拦截不可读的源文件，不再提交时才报错；同目标字幕生成成功后会自动清理更早的失败任务，忽略旧失败不再覆盖更新的任务或干扰详情页入口，编辑 LLM 供应商无关字段会保留已配置的测试模型，观看记录导入也会校验成员身份以防错写到复用 ID 的新账号。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版包含无表结构变更的兼容数据库迁移；应用内更新会在切换版本前备份 SQLite 数据库。

### 修好了

- 影片上传网盘核验并腾空本地副本后，发起「AI 生成字幕」时预检仍可能选中内封字幕或音轨并显示可开始，真正提交才报「参考字幕暂时无法读取，请检查文件后重试」。现在预检会提前检查本地源文件可读性，并以同一提示直接拦截不可读的内封轨与音轨；同目录可读的外挂字幕仍可手动选择。
- 同一文件、同一目标语言的 AI 字幕此前失败、后来重新生成成功后，更早的失败记录仍留在「活动 → 需要处理」里，只能手动清理。现在新任务成功后会自动收尾同文件同目标的更早失败；升级启动时，对已有仍在保留期内的后续成功记录的存量旧失败也会自动补齐收尾，同时保留手动忽略/撤销忽略决定、失败记录与重试入口。
- 忽略旧的 AI 字幕失败任务后，详情页可能误把它当成最新任务，导致详情页继续显示「AI 未完成」，或在已生成成功的文件上点击「AI 生成字幕」时打开旧失败页。现在忽略与撤销忽略不再盖过更新的任务，详情页也会跳过已忽略失败来决定状态与点击入口。
- 通过未回传测试模型字段的客户端（如旧版 iOS）编辑 LLM 供应商无关字段时，会把已配置的连接测试模型冲回目录第一个，可能导致原本正常的供应商变为失败。现在更新时省略该字段会保留原测试模型（在仍兼容的前提下）。
- 后台导入观看记录在绑定成员被删除后才执行时，可能把记录误写进复用同一数字 ID 的新成员。现在导入支持校验成员身份，过期绑定会整批返回冲突而不再写入错误账号。

### 升级须知

- Docker 运行时仍是 25，从「设置 → 更新与维护」更新不必换镜像。
- 本版包含一条不改动表结构的空操作兼容迁移，但数据库迁移版本号会相对 0.52.1 前进。应用内更新后如需回到 0.52.1，请在「回退到历史版本」里随 0.52.1 一并恢复更新前的 SQLite 备份。
- 使用 Docker 镜像升级时，请先停容器并备份数据目录；如需回退，恢复该备份并把镜像标签改回 `v0.52.1` 后启动。

感谢 @o1xhack 的贡献。完整改动：[v0.52.1 → v0.52.2](https://github.com/movieclaw/MovieClaw/compare/v0.52.1...v0.52.2)。
