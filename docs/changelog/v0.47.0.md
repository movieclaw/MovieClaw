## v0.47.0: Find what you have not finished

A library, a kind wall, and a home row can list only titles that still have something unfinished on the shelf.

> ✅ Update from Settings → Updates and maintenance. The Docker runtime stays 25. This release does not migrate the database.

### Highlights

#### Unfinished is a watch filter

Open a library, choose **Filter**, then **Watch status**, then **Unfinished**. A kind wall such as All movies has the same **Watch status** menu: **All watch states**, **Unwatched**, **Unfinished**, **In progress**, **Watched**, **My favorites**, and **Previously watched**. If nothing matches, the wall says **No matching titles. Change or clear the watch filter.**

**Unfinished** means this library still has an on-shelf file you have not finished. Episodes that are not in the library, and files that live in another library, do not count. Several files of the same episode count once.

Under **Customize home**, a library row or a kind row can set **Watch status** to **Unfinished**. That choice wins over **Unwatched**. A **Recently watched** sort ignores both and still shows titles you have played. The row's subtitle shows **Unfinished**.

**View all** opens the wall with that row's sort, direction, and watch filter. The library sort menu includes **Random**, which home rows already had, so a random row opens as **Random**. Back and forward keep the filter that is in the address.

These filters are on the website with this server. The apps keep working here without the new filter.

### Fixed

- Subscribing a title that is already in the library moves its next metadata refresh earlier, onto the schedule used for subscriptions. A refresh that is already due stays due. The next time is never pushed later.
- **Calibrate (校准时间轴)** no longer crashes before it starts. The same crash stopped automatic calibration before translation. Opening title cards and signs with no speech nearby no longer make a correctly timed subtitle fail the check: an event more than 5 seconds from any speech is left out of the score, and a window that is almost only those cards is skipped. If a sampled window is still off by more than 1 second after one correction, that correction is not applied to the whole file. Translation still starts only after the timing check passes. When **Calibrate** has no audio and compares two subtitles, it uses the whole file instead of the short audio sample windows.
- A background task that is waiting on another task no longer fills every worker, so other tasks keep running. A queue of tasks for one library no longer blocks tasks for a different library. Checking a plugin's files on a mount that stalls no longer stops heartbeats, cancel, and wait timeouts.
- HDR tone mapping on **Intel / AMD graphics (VAAPI)** is used only after the hardware check has completed that HDR chain. If the check does not pass, an HDR title that needs tone mapping does not keep using VAAPI's tone-map filter, and playback uses another available path. SDR transcoding on VAAPI is unchanged. **NVIDIA graphics (NVENC)** already required this check. The first playback after startup waits until the check has finished recording tone-map and HEVC results.

### Before you update

- There is no database migration. The Docker runtime stays 25, so updating from Settings → Updates and maintenance does not require a new image. **Rollback** → **Roll back to a previous version** can return to 0.46.0 without restoring a backup, because the database structure is unchanged.

Thanks to @o1xhack and @jasonhorga. Full changes: [v0.46.0 → v0.47.0](https://github.com/movieclaw/MovieClaw/compare/v0.46.0...v0.47.0).

## 简体中文

## v0.47.0：找出还没看完的

媒体库、按类型合成的墙，以及首页的一行，都可以只列出这个库里还没看完的作品。

> ✅ 在「设置 → 更新与维护」里更新。Docker 运行时仍是 25。这一版不迁移数据库。

### 本版亮点

#### 观看里多了「未看完」

打开一个媒体库，点「筛选」，再点「观看」，选「未看完」。全部电影这类按类型合成的墙也有同一个「观看」菜单：「全部观看状态」「未看」「未看完」「在看」「已看完」「我收藏的」「看过的」。没有符合的作品时，墙上写着「没有符合条件的作品，可切换或清除观看筛选。」

「未看完」指这个库里还有在架、你没看完的文件。还没入库的集，以及放在别的库里的文件，不算。同一集有好几份片源，只算一次。

在「自定义首页」里，库的一行或按类型的一行可以把「观看」设成「未看完」。它优先于「未看」。排序是「最近观看」时，这两项都不生效，这一行仍是你播过的。行副标题会写「未看完」。

点「查看全部」，墙用这一行的排序、方向和观看筛选打开。库的排序菜单里有「随机」，首页行本来就有这一档，所以随机的一行打开后仍是「随机」。浏览器的前进和后退会保留地址里的筛选。

这些筛选在这一版服务器的网页上。各个 App 在这台服务器上照常用，只是没有这个新筛选项。

### 修好了

- 给已经在库里的作品新建订阅时，下一次元数据刷新会提前到有订阅时用的那档。已经到点的刷新仍马上做。不会把下一次刷新改得更晚。
- 「校准时间轴」不再一开始就中断。字幕生成里的自动校准以前会在同一步停下。片头字卡、旁边没有对白的标牌，不再让一份时间本来就对的字幕过不了检查：离任何语音超过 5 秒的事件不计入分数，几乎只有这些字卡的窗口会跳过。某个抽样窗口在一次校正之后仍偏差超过 1 秒时，不会把这一次校正套到整份字幕上。翻译仍要等时间轴检查通过才开始。没有音轨、改用另一份字幕做参考时，「校准时间轴」按整份文件比较，不再只用那几段很短的音频抽样窗。
- 一个后台任务在等另一个任务时，不再占满全部工作位置，别的任务继续跑。同一个库积压的一串任务，不再挡住别的库。在会卡住的挂载上检查插件文件时，不再让心跳、取消和等待超时停住。
- Intel / AMD 显卡（VAAPI）的 HDR 色调映射，要等硬件检查真的跑完这条 HDR 链才启用。检查没通过时，需要色调映射的 HDR 不再继续用 VAAPI 的色调映射滤镜，播放改走别的可用路径。VAAPI 上的普通 SDR 转码不变。NVIDIA 显卡（NVENC）本来就要先通过这项检查。服务器刚启动后的第一次播放，会等检查把色调映射和 HEVC 的结果写完，不再用写到一半的结果。

### 升级须知

- 没有数据库迁移。Docker 运行时仍是 25，所以从「设置 → 更新与维护」更新不必换镜像。在「回退到历史版本」里回到 0.46.0 时不用恢复备份，因为数据库结构没有变。
