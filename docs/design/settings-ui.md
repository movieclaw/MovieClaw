# Web 设置页交互规范

参照 Linear / Vercel 的设置页。组件在 `apps/web/components/settings-ui.tsx`。
样板分区：个人信息、通知（简单页），刮削与整理（复杂页：折叠行 + 混合保存）。

## 页面结构

- 一页由若干小节（`SettingsSection`）组成：小节标题 + 可选说明，标题行右侧放整个小节的动作（添加、邀请）。
- 内容列居中，表单类分区最大宽度 `max-w-2xl`。
- 小节之间间距 40px（`space-y-10`）。

## 小节内容二选一

| 形态 | 组件 | 用于 | 保存方式 |
|---|---|---|---|
| 行组 | `SettingsList` + `SettingsRow` | 开关、下拉、单个文本值、只读信息、单个动作 | 即时生效，不配保存按钮 |
| 卡片 | `SettingsCard` | 多个字段一起提交的表单（改密码、连接配置） | 页脚右侧唯一的提交按钮，没填全时置灰 |

- 行：左边是名称和一行灰色说明，右边是控件。行内错误贴在说明下方。
- 单个文本值（昵称）：输入框常驻，失焦或回车保存，Esc 放弃；保存成功给轻提示，失败在行内报错并回退。
- 卡片页脚：左边是限制条件或提示，右边是提交按钮。成功用轻提示，并清空一次性字段（密码）。

## 保存方式按控件类型选

| 控件 | 保存 |
|---|---|
| 开关、单选、分段、下拉、芯片 | 改完即存（必要时 400ms 合并连续改动），失败轻提示并重读服务端值 |
| 单个文本 / 数字 | 失焦或回车提交，Esc 放弃 |
| 多个相关字段（连接配置、模板、凭据） | 卡片或弹窗整体提交，页脚右侧唯一的提交按钮，没改动或不合法时置灰 |

不再出现「整页底部一个保存按钮」管一堆开关的形态。

## 控件

- 开关统一用 `cloud-push-ui` 的 `Toggle`，不用原生复选框表示「立即生效的开关」。
- 分区内的页签统一用 `SettingsTabs`（配合 `useTabParam`）。
- 列表为空统一用 `SettingsEmpty`，文案里提到的按钮必须真的在屏幕上。
- 警示 / 错误条用 `cloud-push-ui` 的 `Banner` / `ErrorBanner`。
- 行尾「⋯」菜单统一用 `SettingsMoreMenu`（危险项标 `danger`，自动排到分隔线后、红字）。
- 改完即存需要显式反馈时用 `SettingsSaveStatus`（保存中… / ✓ 已保存 / 保存失败）。
- 弹窗里的按钮也用 `SETTINGS_*_BUTTON_CLASS`：取消在左、提交在右，与页面同一尺寸。

## 按钮

- 主按钮 `SETTINGS_PRIMARY_BUTTON_CLASS`：卡片页脚的提交，或小节标题行右侧的「添加 / 新建」；每屏最多一个。
- 次要按钮 `SETTINGS_BUTTON_CLASS`：行尾动作（恢复、发送）。
- 危险按钮 `SETTINGS_DANGER_BUTTON_CLASS`：只出现在危险区，点击后先弹确认框，后果写在确认框里。
- 所有按钮统一用小号（高 32px）。

## 列表

- 条目少：放在行组里，每行行尾放动作；条目数写在小节说明里。
- 条目多：小节标题行放搜索和主按钮；行内次要动作收进「⋯」菜单。
- 复杂对象（下载器、站点等多字段配置）的新增与编辑：用 `SettingsDrawer`（右侧抽屉，手机底部抽屉），页脚常驻取消 + 提交；不在列表里展开大表单。
- 行尾最多一个常驻按钮（最常用的动作，如「编辑」），其余进「⋯」菜单。例外：逐条处理的队列（如自动入库的待处理清单）里，处置动作（认领 / 忽略）都常驻。
- 「⋯」菜单里可逆但影响大的项（停用）标 `warn` 黄字，不可逆的（删除、注销）标 `danger` 红字；两类成组排在最后。项不可用时用 `hint` 写原因。

## 危险操作

- 放在页面最底部的「危险操作」小节，用 `SettingsCard tone="danger"`。
- 列表里单条的删除、注销放在行尾「⋯」菜单的最后一项，红字，先确认。

## 小节标题

- 一律用 `SettingsSection` 的标题（14px 半粗），不再用极小的大写灰字 `.group-label` 做分组。
- 分区开头的介绍文字放第一个小节之前，一段话说清这一页管什么。

## 材质

- 只复用 `.css-glass`、`.btn-glass`、`.btn-accent`、`--line` 等现有样式和变量，主题换皮（Netflix）自动生效，组件里不写主题判断。
