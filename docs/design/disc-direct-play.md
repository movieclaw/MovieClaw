# 原盘与镜像直推：光盘结构交给手机端引擎解析

> 状态：已实现并真机验证（2026-09-28，iPhone Air 连 NAS）。起因：所有播放都要直通直推、给 NAS 减压（用户拍板）；
> 改前多剪辑原盘让 NAS 起 ffmpeg 换封装，ISO 直接 404。
>
> 关联文档：[disc-playback.md](disc-playback.md)（现有原盘播放：选主片、诱饵判定、Jellyfin 兼容层）、
> [player-engine.md](player-engine.md)（自研引擎与兜底阶梯）。

## 0. 现状

| 形态 | 在位数量 | 现在怎么放 | 问题 |
|---|---|---|---|
| 单剪辑 BDMV | 122 | 直出整个 m2ts（档 0） | 路径拼接写死小写 `.m2ts`，扩展名是 `.M2TS` 的盘在区分大小写的 NAS 上 404 |
| 多剪辑 BDMV | 14 | 档 1：NAS 起 ffmpeg concat、换封装成 HLS | NAS 起进程；只映射第一路视频（杜比视界增强层丢失）、TrueHD 退成 AC-3 核心、字幕整轨不进流（PGS 没了） |
| ISO（蓝光 / DVD） | 57（4.6% 字节） | 取流 404 | 服务端没有任何 UDF / ISO9660 读取；ffprobe 读 ISO 只是碰巧嗅探到盘内字节，规格不可信 |
| DVD 目录（VIDEO_TS） | 2 | 404 | 没有 IFO 解析 |

## 1. 原则

- **光盘结构全在手机端解析**：UDF / ISO9660、MPLS 播放列表、选主片、多剪辑拼接、时间轴折叠、章节、音轨语言。
  服务端只按 Range 供文件字节，不起任何进程。这是「服务端弱、终端强」的直接推论。
- **复用引擎现成的实现**：我们 fork 的 AetherEngine 已完整支持蓝光与 DVD 的 ISO——`UDFReader`、`MPLSParser`、
  `BDTitleSelector`（排除短播放列表与重复剪辑诱饵）、`ConcatIOReader`（多个 m2ts 拼成一条虚拟 TS）、
  `Demuxer` 里按剪辑折叠时间戳、章节与 STN 语言。缺的只有两样：经 HTTP 读 BDMV **目录**；让我们的取流地址被认作镜像
  （引擎现在靠地址后缀 `.iso` 判断）。
- **其它客户端不拒之门外**：能直放任意文件的播放器（MPV、Infuse 这类通用播放器）同样拿到 ISO 原字节，
  万一它自己读得了镜像呢（用户拍板）；只有网页、系统播放器这类必须服务端换封装的客户端，ISO 才给明确的中文拒绝。
  多剪辑原盘对没申报目录读取的客户端继续走档 1 HLS。

## 2. 方案

### 2.1 能力申报

新增两个申报位，只有自研引擎申报：

- `disc_image`：能读光盘镜像（蓝光 UDF、DVD ISO9660）。
- `disc_folder`：能经「目录取流」接口读 BDMV / VIDEO_TS 目录。

### 2.2 决策

| 形态 | 申报了 | 没申报 |
|---|---|---|
| ISO | 档 0，交付方式 `disc_image`，取流地址就是原文件地址（ISO 原字节） | 通用播放器（`universal`）同样档 0 给原字节；其余拒绝：「服务端读不了光盘镜像的盘内结构……」 |
| 多剪辑 BDMV | 档 0，交付方式 `disc_folder`：目录取流基址 + 服务端选中的播放列表名 | 维持档 1 HLS |
| 单剪辑 BDMV | 档 0，交付方式 `disc_folder`（同多剪辑：续播与拖动按 EP map 一次定位，不再对整个 m2ts 按时间二分） | 维持直出 m2ts，修掉大小写问题 |
| DVD 目录 | 引擎补齐 DVD 目录读取后按 `disc_folder` 开放 | 维持 404 → 改为明确拒绝 |

服务端选中的播放列表名随会话下发：服务端的诱饵判定（同一剪辑以同一 IN_time 重复出现即排除）与台账时长一致，
客户端按名字选同一部主片，避免两边各选各的。

### 2.3 取流接口

- `GET /playback/files/{id}/stream`：container 是 `iso` 时直接出原字节（跳过原盘分支），支持 `Range: bytes=0-0`
  （引擎用它取总长）。
- `GET /playback/files/{id}/disc?token=`：列目录，返回相对路径与大小。只列白名单子树——
  `BDMV/index.bdmv`、`BDMV/MovieObject.bdmv`、`BDMV/PLAYLIST/*.mpls`、`BDMV/CLIPINF/*.clpi`、`BDMV/STREAM/*.m2ts`、
  `VIDEO_TS/*.IFO|BUP|VOB`。
- `GET /playback/files/{id}/disc/{path}?token=`：按 Range 出目录里的单个文件。路径必须命中列目录的结果
  （按实际文件名大小写不敏感地解析），不拼接用户给的路径，杜绝路径穿越。
- token 沿用现有的按 file_id 授权（12 小时）；取流字节照常记到活动页；管理员结束播放后的拒绝窗口照常生效。

### 2.4 引擎（fork 补丁，登记在 [fork 的 PATCHES.md](https://github.com/yipengfei329/AetherEngine/blob/main/PATCHES.md)）

- **P4 镜像地址**：URL 片段 `#aether-disc-image` 声明「这是光盘镜像」，HTTP 源直接走镜像读取器，不再依赖 `.iso` 后缀
  （片段只在本机、不随请求发出）。
- **P5 目录读取**：「可列目录、可按相对路径开文件」的读取协议与 HTTP 实现（列目录走 `/disc`，每个文件一个 Range
  读取器，最多同时开 3 个）；`DiscReader.wrap` 在缓存查找之前分支到 `wrapBluRayFolder`，复用 MPLS 解析、选主片、
  多文件拼接与时间轴折叠；按服务端指定的播放列表名选主片（只读这一个 MPLS）。
- **P7 跳转**：按时间二分在各剪辑时间戳重叠时落到别的剪辑、经 HTTP 读机械盘每一步都是一次请求加寻道；改成读选中
  标题各剪辑的 CLPI，按 EP map 把「折叠后的时间 → 剪辑 + 剪辑内 PTS → 关键帧字节偏移」一次定位。
  续播起播 14.8 → 2.7 秒（《不一样的天空》），跨剪辑跳到 3600 秒约 1 秒落地。
- **P9 双 PID 杜比视界**：UHD 原盘的增强层（PID 0x1015）RPU 挂到基础层，下游转 8.1（详见 PATCHES.md）。
- **P10 / P11**：默认音轨与记着的音轨，见 2.6。
- **P13 DVD 时间轴**：DVD 镜像整个 VTS 的 VOB 首尾相接当一条 MPEG-PS 读，很多盘每个 cell 的 PTS 从头开始（《公司的力量》
  三个 cell 各自从 0.37 秒起），播放头与按时间二分的定位在第二个 cell 起全乱。主 PGC 的每个 cell 当成一个剪辑交给同一套折叠，
  cell 的时间戳基准由导航包（PCI 的 VOBU 起始 PTS 减去 cell 内已播时间）当场算出，定位查 IFO 的时间表一次按字节到位。

### 2.5 App

- `PlayerCapability` 为自研引擎申报 `disc_image` / `disc_folder`。
- 会话的交付方式是 `disc_image` / `disc_folder` 时，`NativeEngine` 按类型装载（镜像：原文件地址 + 镜像开关；
  目录：目录基址 + 播放列表名）。
- 兜底：自研引擎失败时直接到服务端一级
  （多剪辑 → 档 1 HLS；ISO → 中文报错）。

### 2.6 轨道

音轨、字幕菜单本来按服务端的探测结果列，可服务端读不了 ISO 的盘内结构：蓝光镜像《怦然心动》的清单是空的，
DVD 镜像《聪明的一休》按整个镜像猜出 3 条音轨（菜单 VOB 里的也算上了），主片其实只有 1 条。DVB / ARIB / VobSub
这类字幕服务端也不提供。

- **引擎的轨为准**：自研引擎读出轨道后发 `tracksChanged`，控制器（`PlaybackController.adoptEngineTracks`）
  用引擎读到的轨补菜单——光盘镜像整份换成引擎的，其余只补服务端清单里缺的内封字幕。引用仍是 `embedded:N`
  （第 N 条内封轨，与服务端探测顺序一致），选轨、记忆、上报都照旧；语言来自盘的 MPLS / IFO。
- **解不了的置灰**：引擎里没有解码器的字幕（ARIB、Teletext，引擎报的是编码描述名）放进「不可用」并给中文原因，
  不给选了不出字的选项。
- **默认音轨**：没有一条音轨标了默认时，引擎原来按帧数、码率挑，《怦然心动》起播放的是西班牙语配音；
  补丁 P10 改成以第一条音轨的语言为准（同服务端「标了默认的，否则第一条」）。
- **记着的音轨**：用户在这张盘上换过的音轨装载前按序号交给引擎（补丁 P11），首帧就是它；原来首帧后再重载一次，
  起播 2.5 → 4.2 秒。

### 2.7 DVD 目录（VIDEO_TS）

片库里有 2 部 DVD 目录（《情事》《哪吒闹海》，台账容器 `dvd`）。原来决策把它当普通文件「原文件直连」，取流地址指向的是个
文件夹，一律 404，自研引擎只好降级（09-28 改成 404 报「文件不在」后更是直接放不了）。现在与蓝光目录同一条路：

- **决策**：申报了 `disc_folder` 的全解码播放器，DVD 目录给 `disc="folder"`、档 0（媒体事实新增 `dvd_folder`）；
  其余播放器维持原样。
- **取流接口**：目录清单与单文件接口放行 `dvd`，白名单加 `VIDEO_TS/(VIDEO_TS|VTS_NN_N).(IFO|BUP|VOB)`，只看
  `VIDEO_TS` 一层。
- **引擎（补丁 P26）**：目录里有 `VIDEO_TS/` 就走 DVD 分支。选标题、读片长 / 章节 / 语言与读 DVD 镜像共用
  `dvdTitleSet`；标题集的 VOB 按分段顺序首尾相接（`MultiFileConcatIOReader`），与镜像里连续的扇区是同一段字节，
  P13 的 cell 折叠表与时间表原样可用。

## 3. 验证

真机（iPhone Air 连 NAS，2026-09-27 ～ 28）：

| 片源 | 结果 |
|---|---|
| 多剪辑原盘《不一样的天空》（12 个 m2ts、主片 2 段、42.5 GB）/《完美陌生人》 | 目录直推，NAS 不起进程；续播起播 14.8 → 2.7 秒（P7），跨剪辑跳到 3600 秒约 1 秒落地；PGS、音轨切换正常 |
| 蓝光镜像《怦然心动》 | 起播约 2 秒；音轨 3 条、字幕 5 条由引擎读出补进菜单（语言来自 MPLS），中英 PGS 上屏、切换正常；画中画里 PGS 经 OCR 显示 |
| DVD 镜像《公司的力量》（3 个 cell，PTS 各自从 0 起） | P13 前跳过 2670 秒读到结尾；P13 后跨 cell 跳转、直接续播到第二个 cell 都准确 |
| DVD 镜像《聪明的一休》（26 个 cell） | IFO 只声明 1 条音轨、没有字幕，菜单按引擎读到的只列 1 条（服务端原先猜成 3 条）；续播 0.68 秒 |
| UHD 原盘《疾速追杀4》/《疯狂动物城2》 | 画面「杜比视界 · 片源 DV P7（已转 8.1）」（P9）；连播 10 分钟温度正常 |
| 单剪辑 UHD 原盘《疾速追杀4》按目录直推（09-28 上线后） | 续播到 1800 秒按 EP map 一次落地（剪辑内字节偏移 15.3 GB）、拖到 5000 秒正常；杜比视界照常合成；掉帧 0，起播 3.3 秒 |

单测：决策（申报 / 没申报 × ISO / 多剪辑 / 单剪辑）、目录接口的白名单与路径穿越、ISO 原字节的 Range、`.M2TS` 大小写；
App 侧的引擎补轨逻辑（`PlayerTracksTests`）。

## 4. 不做与后续

- 不解 AACS / CSS（片库都是解密过的）；不做光盘菜单、多角度、SubPath。
- 引擎按整个 m2ts 拼接、不按 in/out 裁剪字节：主片播放列表的 in/out 通常覆盖整个剪辑；无缝分支的盘可能在接缝处多出几帧，真机观察。
- Jellyfin / Infuse 的多剪辑直推（服务端把多段虚拟拼成一个 m2ts，要保留 EP map 的 SPN 换算字节偏移）后续再议。
- ISO 的台账规格：后续在服务端用同一套逻辑读出主片再探测，给决策与详情页用。
