# 国际化（i18n）：全端多语言与跟随系统切换

> 状态：分批实施中（2026-10-24，v2：改为语义键）；P0 工程接入、Mac 深链及 iOS 26/27 基础链路已验证；tvOS 26 语言能力已实测，其余迁移继续进行，完成范围与待办见文末。首期范围 Web + 苹果三端（iPhone/iPad、Mac、
> Apple TV）及它们依赖的服务端能力；Android / Android TV / Windows / 鸿蒙后续复用同一套键规范、
> 服务端与术语表。
> 关联文档：[metadata.md](metadata.md)（元数据语言）、[settings-ui.md](settings-ui.md)（设置页规范）、
> [domain-events.md](domain-events.md)（通知渲染）、[cloud-push.md](cloud-push.md)（推送）、
> [plugin-market.md](plugin-market.md) / [theme-plugins.md](theme-plugins.md)（插件与主题清单）。

## 0. 目标与成功标准

支持 **简体中文（zh-Hans）** 与 **英语（en）** 两种界面语言，**默认跟随系统 / 浏览器**，
用户可在符合各平台惯例的位置改选。

可验证的成功标准：

1. 浏览器语言为英语的新访客，从初始化页、登录页到登录后的所有页面看到的是英文，
   **包括服务端返回的报错**（如「密码错误」）。
2. iPhone / Mac / Apple TV 系统语言为英语时 App 全英文；系统语言为日语、德语等不支持的语言时回退英文。
3. 用户在 Web「外观与语言」里改为 English，**不刷新页面立即生效**，换浏览器登录同一账号仍是 English。
4. 英文 iPhone 收到的推送是英文，中文 iPhone 收到的同一事件推送是中文（同一账号两台设备各按各的）。
5. 现有中文用户在整个迁移过程中**零感知**：每个迁移 PR 合并前后中文界面逐字一致（自动校验，§10.2）。
6. 代码里引用不存在的键**编译不过**；CI 阻止新增裸写的中文（棘轮）、英文漏翻 / 过期、占位符不一致。

不在本期范围：繁体中文（§11 给出低成本补齐路径）、从右到左语言、按用户切换影片元数据语言、
系统日志 / CLI / 代码注释的翻译。

## 2. 核心决策一览

| # | 决策 | 理由（展开见对应章节） |
|---|---|---|
| D1 | **语义键**：代码只引用稳定的标识键（`player.controls.play`），中文、英文都是该键的译文；三端同一套键规范（§3） | 键表达「用途」而非「措辞」：改中文措辞不动代码；同一中文在不同语境可以有不同英文（「播放」作按钮 / 作名词）；编译期校验键存在；跨端同一概念同一个键，可按键对齐译法 |
| D2 | **类型安全的键**：Web 用 next-intl 的类型增强、苹果用 Xcode 26 的 String Catalog 生成符号、服务端用测试扫描 | 写错 / 删掉在用的键在编译或测试阶段就失败，而不是上线后显示一串键名 |
| D3 | **中文是源语言**：`zh-Hans` 文件是事实源，英文从它翻译；英文过期由哈希锁检测（§10.3） | 产品与开发都以中文为母语；语义键下中文改了键不变，必须有机制标记英文待重译 |
| D4 | **语言由客户端决定**，服务端从请求里读，不替客户端做主 | 平台惯例（苹果跟随系统、Web 跟随浏览器/账号）；所有端零成本复用 |
| D5 | 不支持的系统语言 → **英语**；所有 `zh-*` → 简体 | 德、日、法等用户看英文远比看中文友好；繁体用户读简体的门槛最低 |
| D6 | **Web 有应用内切换**（登录页 + 设置），**苹果端不做应用内切换**，设置里放一行跳系统的「单个 App 语言」 | 苹果人机界面指南的建议，系统级单 App 语言已覆盖；Web 没有系统级设置，必须自己提供 |
| D7 | 服务端渲染给**某台设备**的文字（App 推送）用该设备的语言；渲染给**某个人**的（IM、系统通知）用这个人的语言 | 推送在设备上看，跟设备一致最自然；IM 没有设备语境 |
| D8 | 报错与落库文字一律带 **键 + 参数**；服务端同时给出已翻译的 `message` | 新客户端可按键分支处理，旧客户端照旧显示 `message`；切语言后历史记录也能重新渲染 |
| D9 | 影片元数据语言**本期不按人切换**，仍是管理员的全局设置；初始化时按管理员的浏览器语言给默认值 | 按人切换要多语言落库，属于 [metadata.md](metadata.md) 的后续演进 |
| D10 | 翻译由开发时的 Agent 按**术语表**生成，关键页面人工过目；不接第三方翻译平台 | 两种语言、开发主力是 Agent，平台的协作价值用不上；无需新增密钥 |

## 3. 键规范（三端共用）

### 3.1 形态

- `命名空间.范围.用途`，2～4 段，段内 lowerCamel，只用 ASCII：
  `player.controls.play`、`settings.downloaders.addTitle`、`library.scan.progress`、
  `errors.auth.wrongPassword`。
- **键描述用途，不复述措辞**：`deleteConfirmTitle`，不是 `areYouSureToDelete`；
  中文从「确定删除？」改成「删除这个下载器？」时键不变。
- **一个键对应一处语义**：同样是「播放」，播放按钮 `player.controls.play`、统计里的名词
  `stats.playback.title` 各用各的键。不为「中文刚好相同」而复用。
- 例外是 `common.*`：只收录白名单内的通用词（保存、取消、删除、确定、重试、关闭、编辑、完成、
  加载中、暂无内容……约 50 个，清单见术语表），在任何语境下中英文都不变。

### 3.2 命名空间

一级命名空间固定，三端同一个概念用同一个命名空间与键，便于跨端对齐译法：

```
common  nav  auth  setup  home  library  media  player  search  subscription
download  settings.<分区 id>  notify  agent  plugins  activity  errors  units
```

`settings.<分区 id>` 与 Web 设置分区 id 一致（`settings.downloaders`、`settings.appearance`…）。
Web 的英文资源按一级命名空间拆文件，苹果用一份 catalog（§6.2），服务端按命名空间拆文件。

### 3.3 写法约束

- **参数一律命名**、ICU 风格：`{count}`、`{title}`；**不拼接句子**（不把一句话拆成两个键再拼），
  不把带格式的数字 / 日期提前转成字符串传进去，交给格式化（§5.2）。
- 复数、选择用 ICU：`{count, plural, one {# movie} other {# movies}}`；中文译文通常只写 `{count} 部影片`。
- **代码里的键必须是字面量**（便于静态检查）；枚举到文案用显式映射表：

  ```ts
  const KIND_LABEL = { movie: "media.kind.movie", tv: "media.kind.tv" } as const;
  t(KIND_LABEL[kind]);
  ```

- 每个键可以附**给译者的说明**（Web/服务端写在 `_meta` 文件，苹果写在 catalog 的 comment），
  语境不明显的必须写：按钮还是标题、多长会截断、参数是什么。

## 4. 语言解析：一条链路贯穿三端

### 4.1 语言标签

- 内部只认两个值：`zh-Hans`、`en`。用户偏好额外有 `auto`（跟随系统/浏览器）。
- 归一规则（服务端 `movieclaw_api.i18n.negotiate()`、Web `lib/i18n/negotiate.ts` 两处实现，
  共用同一组单测用例）：
  - `zh`、`zh-CN`、`zh-Hans*`、`zh-SG` → `zh-Hans`
  - `zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant*` → `zh-Hans`（D5；繁体上线后改为 `zh-Hant`）
  - `en*` → `en`
  - 严格匹配语言标签，不接受 `zhfoo` / `zh_CN`；q 值遵守 HTTP 权重语法（0～1、最多三位小数），
    排除 `q=0` 和无效权重，再按权重稳定排序取第一个能归一的；全部不能归一 → `en`

### 4.2 Web 的判定顺序

```
账号偏好（ui_prefs.language，非 auto 时）
  > 本浏览器的 cookie mc_locale（登录页选的、或账号偏好的镜像）
  > 浏览器 Accept-Language
  > en
```

- 判定在 Next 服务端完成（next-intl 的 `getRequestConfig` 读 cookie + 请求头），结果写进
  `<html lang>` 并注入客户端，首帧就是正确语言，不闪烁。
- 登录后拉到账号偏好：与 cookie 不一致时以账号为准并回写 cookie。

### 4.3 服务端的判定（请求上下文）

一个纯 ASGI 中间件（遵守 #172：不用 BaseHTTPMiddleware）解析后放进 contextvar `current_locale`：

```
cookie mc_locale（只有 Web 会带，覆盖 SSE / <img> / EventSource 这类设不了请求头的请求）
  > Accept-Language（带了头但都不支持，如 fr → en）
  > zh-Hans（完全不带头或为空）
```

- **完全不带 `Accept-Language` 的请求按 `zh-Hans` 回复**：还没本地化的 Android、Android TV、
  桌面、鸿蒙客户端（OkHttp 等默认不带）以及 CLI、插件都属此类，回落英文会让它们的中文界面混进英文。
  Web 的 `negotiate` 与服务端共用同一份用例 `tests/i18n/negotiation.json`（PR #1027 评审）。

- Web 的 API 客户端在每个 fetch 上显式设置 `Accept-Language: <已判定语言>`（该头不是浏览器
  禁止设置的头），保证「浏览器是中文、账号选了英文」时报错也是英文。
- 苹果端由 APIClient 显式发送 bundle 生效语言。P0 实测发现 URLSession 默认头在日语环境仍为
  `ja`，即使 bundle 已回退英文；不能依赖默认头表达 App 实际语言。

### 4.4 服务端主动发出的文字用谁的语言（D7）

| 场景 | 语言来源 |
|---|---|
| App 推送（APNs / 云推送） | 目标设备 `login_device.locale` |
| IM 推送、Webhook 的可读文本、系统通知、Agent 后台任务回报 | 成员 `ui_prefs.language`（非 auto）> 该成员最近一次请求的语言 `last_locale` > `zh-Hans`（存量用户兜底） |

- `login_device` 新增 `locale`、`timezone` 两列；人的交互客户端请求若与库里不同才写（值不变不写盘）。
  `timezone` 用于推送里出现的绝对时间（如「今晚 20:00 更新」）。
  Web / 原生 API 客户端以 `X-MovieClaw-Timezone` 传 IANA 时区；非法值忽略并保留原值。
- 成员（含超管）新增 `last_locale`，同样只在变化时写。
- 旧客户端不带新信息也没关系：`Accept-Language` 本来就有，字段为空时按兜底链走。

## 5. 语言设置入口（产品设计）

原则：

1. **默认零操作**：首次使用就按系统 / 浏览器选对语言，绝大多数人永远不用找入口。
2. **看不懂当前语言的人也能找到入口**：地球图标 + 语言**自称**（「简体中文」「English」），
   不用国旗（国旗代表国家不代表语言），不用当前语言去翻译其它语言的名字。
3. **符合平台惯例**：苹果用系统的单 App 语言设置；Web 没有系统级设置，才自己提供。
4. **个人偏好，不是服务器配置**：放在「账号」组，成员与超管都能改，各管各的；
   不在「系统」组放全局界面语言。
5. **不增加设置项**：不单独做「地区格式」「时区」设置，日期数字格式跟语言走，时区跟浏览器 / 系统。

### 5.1 Web

**入口 1：登录页与初始化页（登录前）**
- 卡片下方一个轻量文字按钮：`🌐 English ▾` / `🌐 简体中文 ▾`，点开为两项列表。
- 只写 cookie `mc_locale`，不需要账号。这是「误入陌生语言界面」的人唯一需要的逃生口。

**入口 2：设置 → 账号 → 「外观与语言」（登录后）**
- 现有「外观」分区（成员可见）改名「外观与语言」，描述改为「语言、首页背景与界面质感」，
  **语言卡片放在最上面**。不新开分区；分区 id 仍为 `appearance`，不影响既有链接。
- 选项（单选列表，与现有设置控件同一组件）：

  ```
  语言
  ○ 跟随浏览器 · English        ← 副文案显示当前实际生效的语言
  ○ 简体中文
  ○ English
  ```

- `auto` 是明确的「跟随浏览器」选择：登录后读到它，或用户主动选择它时，清除固定语言 cookie，
  按本次请求的浏览器语言解析；不要把解析结果重新永久写成固定 cookie。
- 选中即保存到 `ui_prefs.language` 并回写 cookie，`router.refresh()` + 切换客户端文案，
  **不整页刷新**、不丢正在播放的状态。
- 不放在用户头像菜单 / 顶栏：切换是一次性操作，顶栏密度优先。

### 5.2 iPhone / iPad

- 设置页「通用」区加一行：`语言    简体中文 ›`（右侧显示 `Bundle.main.preferredLocalizations.first`
  对应的自称）。
- 点按打开 `UIApplication.openSettingsURLString`，即系统设置里 MovieClaw 自己的页面，
  其中有系统提供的「首选语言」。系统改完会自动重启 App，无需我们处理。
- 行下方脚注：「在系统设置中为 MovieClaw 单独选择语言。」系统只在设备语言列表里有两种以上语言时
  才显示该选项，脚注补一句「若没有该选项，请先在『通用 → 语言与地区』添加语言」。
- 不做应用内语言切换（D6）。

### 5.3 Mac

- 设置窗口「通用」加同样一行，点按打开 系统设置 → 通用 → 语言与地区（在「应用程序」列表里为单个
  App 选语言），深链 URL 在 P0 实测确认。脚注说明「重新打开 MovieClaw 后生效」。

### 5.4 Apple TV

- 跟随系统语言。tvOS 26（23J352）系统设置的 Apps 页面未提供 MovieClaw 单 App 语言入口；
  General 中仅有全局 Apple TV Languages。因此**不加任何入口**（不做只读展示行，避免占焦点位）。
  探针为只读检查，未改变系统语言。

### 5.5 后续端（预留口径）

- Android / Android TV：Android 13+ 系统单 App 语言（`localeConfig`），做法同苹果；
  低版本系统与 Windows / 鸿蒙按 Web 的做法放在「设置 → 通用 → 语言」。

## 6. Web 方案

### 6.1 选型：next-intl（不启用按语言分路由）

- 结构化键 + ICU MessageFormat + 服务端 / 客户端组件通用，纯运行时、不碰构建链。
- **类型安全**：`AppConfig.Messages = typeof zhHans`（由中文源文件推导），`t("player.controls.pley")`
  直接是 TS 编译错误，编辑器里有键名补全。
- **不做 `/en/...` 路由前缀**：自托管、要登录的应用，前缀没有收益，还会破坏 middleware、Jellyfin
  转发与插件网页路由。用 next-intl 的「无路由」模式，语言来自 §4.2。
- 用法：

  ```tsx
  const t = useTranslations("player");          // 客户端组件
  const t = await getTranslations("player");    // 服务端组件
  t("controls.play")
  t("loaded", { count, total })
  t.rich("hint", { link: (chunks) => <Link href="/settings">{chunks}</Link> })
  ```

### 6.2 资源文件

```
apps/web/locales/
  zh-Hans/<命名空间>.json      ← 事实源，键与中文
  en/<命名空间>.json           ← 译文，键集合必须与中文完全一致
  _meta/<命名空间>.json        ← 每个键：给译者的说明 + 翻译时中文的哈希（§10.3）
```

- 按命名空间拆文件：并行迁移的 PR 很少在同一个文件上冲突。
- 运行时加载：英文与中文深合并（英文覆盖中文），万一漏翻显示中文而不是键名；CI 保证不会漏（§10）。
- 下发体积：每种语言全部文案估计 6～8 千条，gzip 后约 60KB。首期整包下发（每个用户只下发自己的语言）；
  超过 100KB 再按路由组只下发用到的命名空间。

### 6.3 格式化

- `lib/time.ts`：`TIME_DISPLAY_CONFIG` 改为按语言取值；dayjs 按语言加载 `zh-cn` / `en`；
  `M月D日` 这类写死的格式改为 `Intl.DateTimeFormat` 的组件选项，中文仍得到「10月23日」。
- 新建 `lib/i18n/format.ts`：数字（含中文「万/亿」→ `Intl.NumberFormat` 的 `compact`，
  英文得到 `1.2K`）、文件大小、时长（`1 小时 23 分` ↔ `1 hr 23 min`）、列表连接（`、` ↔ `, and`）。
  37 处 `toLocaleString` 收口到这里。next-intl 的 `useFormatter` 能覆盖的直接用它。
- 时区不变：仍按浏览器本地时区。

### 6.4 容易被忽略的细节

- **中文字体选择**：`<html lang="en">` 时，部分系统（Windows / Linux 的 Chrome）会给片名里的
  汉字挑日文字形。字体栈显式写上 `"PingFang SC", "Noto Sans SC", "Microsoft YaHei"`，
  并给来自元数据的标题、简介元素加 `lang` 属性（取媒体的元数据语言）。
- **英文更长**：通常长 30%～60%。重点排查工具栏、筛选条、按钮组、表格列、卡片标题的固定宽度；
  宁可折行或收进「⋯」，**不缩小字号**。
- **标点与排版**：中文直角引号「」、全角冒号逗号不能出现在英文译文里（CI 校验）；
  英文用 sentence case（只首字母大写），按钮用动词开头。
- **不能换成键的中文**：做识别、匹配、解析的中文（种子标题里的「第1集」「全集」正则、
  拼音搜索、豆瓣字段名、和后端约定的值、测试夹具）是数据不是文案。迁移先分类，只换文案；
  数据类加 `// i18n-ignore` 或放进白名单文件。
- **PWA 清单**：`app/manifest.ts` 的 `name/description` 按请求语言输出。
- **缓存**：Next 的请求缓存、SWR 缓存中凡是含翻译后文本的，键里要带语言。
- **开发用伪语言**：`?locale=pseudo` 时把译文变成加长的带变音英文（`[Ƥļåý ‧‧‧]`），一眼看出
  没换成键的中文和会截断的布局；仅开发模式可用。

## 7. 苹果方案

### 7.1 String Catalog 手动键 + 生成符号（Xcode 26）

- catalog 里的每一条都是**手动键**：键 `player.controls.play`，zh-Hans（源语言）值「播放」，
  en 值「Play」，comment 写给译者的说明。
- 打开构建设置「Generate String Catalog Symbols」，Xcode 为每个手动键生成
  `LocalizedStringResource` 静态成员，代码里写：

  ```swift
  Text(.playerControlsPlay)
  Button(.commonSave) { … }
  Text(.libraryScanProgress(n))           // 实测默认生成无外部标签的带参函数
  String(localized: .errorsAuthWrongPassword)
  ```

  删掉或改名在用的键 → 编译错误。CI 的 Xcode 26.6 支持，部署目标 26.0 无兼容问题。
- **关闭自动提取**（`SWIFT_EMIT_LOC_STRINGS = NO`）：catalog 里只留手动键，不会把残留的
  `Text("中文")` 又自动收进来；残留中文由 §10 的棘轮负责清零。
- 枚举显示名、视图模型里的文案用 `LocalizedStringResource` 传到界面再解析，切语言不残留旧值。
- 数据类字符串（片名、文件名）用 `Text(verbatim:)`。
- **P0 实测**：点号分段的键生成出来的符号名（预期 `player.controls.play` → `.playerControlsPlay`）；
  若不理想，苹果端键名改用同一套段落的 lowerCamel 拼接，跨端对照表由脚本维护。

### 7.2 工程配置（project.yml / XcodeGen）

- `CFBundleLocalizations` 增加 `en`；`knownRegions` 增加 `en`；`LOCALIZATION_PREFERS_STRING_CATALOGS = YES`。
- **回退到英文**（D5）：`CFBundleDevelopmentRegion` 从 `$(DEVELOPMENT_LANGUAGE)` 改为显式 `en`，
  catalog 源语言仍为 zh-Hans。系统在用户语言列表里找不到支持的语言时回退到 `CFBundleDevelopmentRegion`。
  P0 实测：日语系统 → 英文；中文系统 → 中文；画中画、权限弹窗等系统界面跟随 App 语言。
  若不可行，退路是接受「不支持的语言回退中文」，记入实施记录。
- **繁体别名是必要工作**：macOS 实测只有 `zh-Hans/en` 时，`zh-Hant` 会选英文，不能自动满足 D5。
  苹果接入前须提供由简体资源生成的繁体语言标签别名，并覆盖 `zh-Hant` / `zh-TW` / `zh-HK` 的实际
  bundle 选择；这些别名仅复用简体文案，不代表本期提供繁体翻译。
- 注意：苹果的回退**按整个 bundle**而不是按单条文案，英文漏翻的条目可能直接显示键名，
  所以 §10 的漏翻检查是硬门槛。
- catalog 布局：
  - `Shared/Localizable.xcstrings`：Shared 以源码编进 iPhone / Mac / TV 三个 App，一份覆盖三端，
    三个 target 各自生成同样的符号。仅某一端用到的键也放这里（体积影响可忽略）。
  - `AetherCore`（独立 framework）单独一份；生成的符号是 internal，只在本模块内用。
  - 通知扩展、TopShelf 扩展各一份；`InfoPlist.xcstrings` 负责权限说明（相机、本地网络、相册）。
- **xcstrings 合并冲突**：它是 Xcode 整体重写、键排序的 JSON，并行 PR 必冲突。苹果端迁移 PR
  **按模块串行合并**；另备 `scripts/i18n/xcstrings-merge.py`（按键合并两份 catalog）用于变基时解决冲突。

### 7.3 格式化

- 28 处 `DateFormatter`：能用 `.formatted()` 的改用它；必须定制的用
  `setLocalizedDateFormatFromTemplate`，不写死 `yyyy年M月d日`。
- 相对时间、数字、文件大小、时长分别走 `RelativeDateTimeFormatter`、`.formatted()`、
  `ByteCountFormatStyle`、`Duration.formatted()`，集中在一个 `Formatting.swift`。
- 现有断言中文输出的单元测试（如 `ShellLogicTests` 的「几秒前」）显式固定 `Locale(identifier: "zh-Hans")`，
  再补同一组英文用例。

### 7.4 测试

- 方案里加一个英文测试计划：`-AppleLanguages (en) -AppleLocale en_US`。
- 现有 UI 测试大量按中文 label 找元素：中文计划照旧跑；英文计划只挑关键流程，
  **新写的用 `accessibilityIdentifier`**，不批量改造存量测试。
- 排版检查：Xcode 内置「双倍长度伪语言」+ 英文实测截图；Apple TV 重点看焦点放大后的卡片标题截断。

### 7.5 上架

- App Store Connect 增加英文本地化：名称、副标题、描述、关键词、截图、「新功能」。
- 发版技能（`.claude/skills/release`）的 TestFlight「测试内容」与商店「新功能」改为中英两份。
- 隐私政策补英文版（App Store 英文页面引用）。

## 8. 服务端方案

### 8.1 机制

- 新模块 `movieclaw_api/i18n/`：
  - `negotiate()`（§4.1）、`current_locale` contextvar、纯 ASGI 中间件（§4.3）；
  - `t(key, **params)`：在请求上下文里按 `current_locale` 渲染；后台任务里用
    `with use_locale(loc):` 显式指定；
  - 资源与 Web **同一种格式**：`src/movieclaw_api/locales/{zh-Hans,en,_meta}/<命名空间>.json`，
    ICU MessageFormat，同一套 CI 检查脚本；
  - ICU 渲染只需参数、`plural`、`select` 三种：P0 选型，优先纯 Python 实现（复数规则用 Babel），
    不引入 PyICU（原生依赖，镜像体积与 NAS 内存都不划算）。
- **报错**：`AppException` 增加 `message_key` 与 `params`，响应体变为

  ```json
  { "code": "BAD_REQUEST", "message_key": "errors.auth.wrongPassword",
    "params": {}, "message": "Wrong password" }
  ```

  `message` 由服务端按请求语言渲染，旧客户端照旧显示它；新客户端需要按错误分支处理时用 `message_key`
  （它比现在粗粒度的 `code` 精确）。iOS / Android TV 两个接口生成器都要重跑，新字段可空。
- **迁移期兼容**：仍接受 `message="中文"` 的旧写法（原样输出、不翻译），用棘轮逐步清零；
  按用户接触频率排序：登录 / 权限 / 播放 / 下载 / 订阅 先改。
- **接口里的名称**（约 98 处 `label` 等）：构造响应时用 `t()`；服务端内部缓存的键必须包含语言；HTTP 响应同时添加
  `Vary: Accept-Language, Cookie`（cookie 也能决定语言）。`Vary` 不能替代内部缓存键的语言隔离。
- **第三方原文透传**：qBittorrent、TMDB、站点返回的错误原样展示，不翻译。

### 8.2 落库文字（D8）

- 新写入的用户可见文字（系统通知、任务失败原因、事件通知）存 `message_key` + `message_params`（JSON），
  读出时按读者语言渲染；旧列保留并继续写入中文渲染结果，供旧客户端与回滚使用。
- 存量行：用中文源文件生成「中文 → 键」反查表，不带参数的老消息能反查到键的按读者语言显示；
  查不到的原样显示中文。不做数据迁移。

### 8.3 推送、IM、通知

- 推送：按目标设备 `locale` 分组渲染（同一事件对中文设备、英文设备各渲染一次）。不改用 APNs 的
  `loc-key` 让设备端翻译——服务端渲染对所有推送通道（官方云推送、IM、未来的安卓）一致。
- 推送里的绝对时间用 Babel 按设备 `locale` + `timezone` 格式化。
- 「测试通知」等固定文案同样走 `t()`。

### 8.4 Agent

- 系统提示追加一句「使用 {语言名} 回复用户」，语言取自会话发起请求的 `current_locale`；
  IM 入口取成员语言（§4.4）。会话标题生成同理。
- 工具描述、技能、提示词主体保持中文（模型读得懂，且这是开发者内容）。

### 8.5 内容语言（不随界面语言变化）

- 影片元数据语言仍是全局 `tmdb_language`（D9）；**初始化向导**创建超管时，按其浏览器语言预设
  （`en` → `en-US`，中文 → `zh-CN`），之后在「刮削与整理」可改。不新增向导步骤。
- 默认字幕 / 音轨仍按库语言（`track_policy.py`），保持现状。
- 豆瓣数据源只有中文，照旧。

## 9. 插件与主题（P4）

- 清单的展示字段与设置项的 JSON Schema `title/description` 支持多语言：采用
  [W3C Web App Manifest 的 `*_localized` 语言映射](https://www.w3.org/TR/appmanifest/#localized-members)，
  例如 `title_localized = { en = "…" }`、`description_localized = { en = "…" }`；
  Web App Manifest 使用标准的 `name_localized` / `short_name_localized`。值可为字符串或
  `{value, lang?, dir?}` 对象。插件市场索引的 `name`、`summary`、`description` 一并携带对应映射。
  精确匹配当前语言后再匹配归一化语言，无译文时保留原字段。解析缓存保存原文，响应时按请求语言复制渲染。
  这是对原稿 `translations` 写法的修正；该字段并非当前 W3C 规范采用的结构。
- 插件自己的界面文案由插件自理；插件网页、主题通过请求头与 `<html lang>` 拿到当前语言，
  插件 SDK 暴露 `ctx.locale`。
- 插件开发技能、示例插件补「如何提供英文」一节。

## 10. 质量门槛（CI 与端到端）

### 10.1 静态检查

| 检查 | 内容 |
|---|---|
| 键存在 | Web：TS 类型（编译期）；苹果：生成符号（编译期）；服务端：测试扫描所有 `t("…")` 字面量键都在中文源文件里 |
| 键集合一致 | 每种译文的键集合与中文源完全相同（无缺、无多） |
| 过期译文 | §10.3 的哈希锁不一致 → 失败，提示哪些键的中文改过、英文要重译 |
| 未使用的键 | 扫描代码引用，源文件里没人用的键 → 告警（迁移完成后改为失败） |
| 中文棘轮 | 统计 Web（TS 语法树里的字符串与 JSX 文本）、Swift、服务端用户可见路径中**裸写的中文**，基线存 `scripts/i18n/baseline.json`，只许减不许增；`i18n-ignore` 标注与白名单可豁免 |
| 占位符一致 | 每条译文的参数集合与中文源一致；ICU 语法可解析 |
| 英文卫生 | 英文译文中不得出现汉字与全角标点 |
| 跨端一致 | 同一个键在 Web、苹果、服务端的英文必须相同；术语表里的词必须用规定译法 |

### 10.2 迁移 PR 的「中文零变化」校验

迁移脚本在把字面量换成键时记录 `原中文 → 键` 的对应表；CI 校验对应表里每个键在中文源文件里的值与原中文
**逐字相同**。这就把成功标准 5 变成自动检查，而不靠人眼比对。

### 10.3 过期检测（语义键的代价，必须有）

语义键下改中文措辞不改键，英文不会自动失效。`_meta/<命名空间>.json` 为每个键记录「最后一次翻译时中文的
哈希」；中文改了而英文没跟着更新，哈希对不上，CI 失败。翻译脚本更新英文时同时刷新哈希。
苹果 catalog 也需要中文源哈希锁；直接编辑 JSON 时不能依赖 Xcode 自动更新译文状态。
CI 同时拒绝「需要复查」状态。苹果使用 printf / catalog substitutions，Web 与服务端使用 ICU；
跨端共享语义键与逻辑参数名，不直接比较两种格式的原始字符串。跨端参数按显式映射表核对。

### 10.4 单测与端到端

| 范围 | 内容 |
|---|---|
| 单测 | 语言归一与判定优先级（服务端、Web 同一组用例）；格式化函数中英两套期望；ICU 渲染器 |
| Web 端到端（Playwright） | ① `locale: en-US` 打开初始化页、登录页 → 英文，`html[lang=en]`；② 输错密码 → 英文报错，响应带 `message_key`；③ 登录页切到简体中文 → 登录后中文；④ 设置里切 English → 不刷新即生效，刷新后保持；⑤ 新开浏览器上下文（中文 Accept-Language）登录同一账号 → 仍是英文；⑥ 关键页面中英截图，查截断溢出 |
| 苹果端到端 | iPhone / Mac / TV 英文测试计划跑关键流程并截图；日语系统 → 英文；设置里「语言」行打开系统设置；英文设备注册推送后，服务端「测试通知」载荷为英文 |
| 新旧搭配 | 旧客户端 × 新服务器（不认识 `message_key`、照常显示 `message`）；新客户端 × 旧服务器（没有 `message_key` 时显示 `message`，不崩） |

## 11. 翻译工作流与术语

- **术语表** `docs/i18n/glossary.md`：产品词的规定译法与不译词，例如
  洗版 → upgrade（定一个）、刷流 → ratio boost、追新 → follow new episodes、
  原盘 → Blu-ray disc / BDMV、片源 → release、转码器 → transcoder；
  MovieClaw、TMDB、qBittorrent 不译；以及 `common.*` 白名单。先定 50～100 个核心词再开始批量迁移。
- **生成**：迁移 PR 里由 Agent 起键名、写中文源（原文照搬）、按术语表 + 所在页面上下文翻译英文、
  写给译者的说明。
- **评审**：每个 PR 附中英关键页面截图；首页、详情、播放器、登录、初始化这几页人工通读英文；
  键名按 §3 规范人工抽查。
- **繁体（后续可选）**：用 OpenCC（简→繁 + 台湾用词）从中文源自动生成 `zh-Hant`，三端都是
  「多一份资源」的成本，届时把 §4.1 的繁体归一改为 `zh-Hant`。

## 13. 风险

| 风险 | 应对 |
|---|---|
| 起一万多个键名，风格漂移、重复键泛滥 | §3 规范 + 命名空间固定 + `common.*` 白名单；未使用键检查；PR 抽查键名 |
| 改了中文没重译英文 | §10.3 哈希锁，CI 失败 |
| 迁移误把「数据类」中文换成键，导致识别 / 匹配逻辑失效 | 分类先行 + 每个 PR 跑该模块全部单测；种子标题解析、搜索等模块列入人工复核清单 |
| 英文长度撑破布局 | 伪语言 + 英文截图评审；P1/P2 每个 PR 必附 |
| xcstrings 并行冲突 | 苹果 PR 串行 + 合并脚本 |
| 生成符号对点号键的命名不理想 | §7.1 的退路 |
| 回退英文的苹果组合不可行 | §7.2 的退路，影响面仅「不支持语言的用户看到中文」 |
| 服务端缓存串语言 | 缓存键带语言 / `Vary`；P3 加用例：同一接口先英文后中文请求结果不同 |
| 规模大、周期长，期间新代码继续写中文 | P0 即上棘轮，从第一天起新增文案必须用键 |
