# 插件页分层：功能、官方插件、已安装与系统模块

> 状态：**设计稿，第 1 步实施中**（2026-10-09）。关联：`plugin-kernel.md` §10（诊断页）、`plugin-channels.md`
> （随带插件包与替换）、`plugin-phase3.md`（插件包）、`settings-ui.md`（设置页规范）。

## 0. 结论先行

1. **插件页只放用户能做决定的东西**，分三组：「功能」（用户能感知的可选功能）、「官方插件」（随应用提供、
   可用插件包替换的，现在是 IM 通道）、「已安装」（第三方插件包与本地插件）。
2. **系统模块平时不展示**：页面底部一行「另有 N 个系统模块，运行正常 · 查看」，点开是只读清单。
3. **异常自动浮出**：系统模块启动失败或报告降级时，在页面顶部出现异常提示，写明是哪个、为什么，附「查看日志」；
   同时照旧进待处理事项。
4. **分层由服务端定义**：每个内置插件属于且只属于一层，功能目录（名字、说明、设置入口）在服务端，网页只渲染，
   以后 App 展示用同一份。
5. **功能的开关不放插件页**：有专门设置页的功能链接过去；没有开关、又值得关的功能（AI 字幕、AI 助手、片头识别）
   要先做「插件即功能边界」的改造（§5 第 2～4 步），再在各自设置页加开关。

## 1. 为什么改

现在「设置 → 插件 → 内置」把 49 个内置插件全部按领域列出来。其中大多数用户既不能关也不能换：

| 类别 | 数量 | 例子 |
|---|---|---|
| 核心（不能关） | 8 | 数据库、配置、密钥、网络出口、站点目录 |
| 标了「可关闭」，但关了没有用户意义 | 6 | `kernel.*`：关掉后所有第三方插件失效 |
| 既不能关也不能换 | 27 | 维护自愈小任务 12 个（凭据自愈、会话索引校准、光盘片长修正……）；核心功能（媒体库、任务执行器、转码……） |

这些条目对用户是噪音：看不懂、也不能操作。「可关闭」的说法也误导人——要改 `data/plugins.yaml` 再重启，
网页上没有开关；其中几项（刷流、Cloud、实时监控）在各自设置页本来就有开关，插件页是重复入口。

### 1.1 别人怎么做（2026-10-09 调研）

| 产品 | 内部模块 | 出问题时 |
|---|---|---|
| DeepSeek Harness | 管理页只放能操作的（官方插件配置、可选功能、已装包），核心组合包（约 180 个插件）被硬编码排除；全量清单在「设置 → 内置插件」只读页，失败的排最前 | 清单里置顶「启动失败」；管理页坏包带标签 |
| VS Code | 内置扩展默认不在「已安装」里，要 `@builtin` 过滤才看得到 | **出错、要重启、有更新时自动浮到主列表** |
| Obsidian | 「核心插件」页只列用户功能（反向链接、关系图、日记），基础设施完全不出现 | — |
| Home Assistant | 内部组件标 `system` 类型，集成页不显示 | 统一的「修复」中心（分级、可一键修复、可忽略）；启动失败通知附按组件过滤好的「查看日志」；「系统信息」页由组件上报健康数据 |
| WordPress | 必须加载的插件单独一个页签、无开关 | 加载失败的进「已暂停」页签，行内写错误 |

共同点：**按「用户能否感知、能否操作」分层，而不是按代码结构；内部模块可达但不打扰；异常主动浮出。**

## 2. 分层

| 层 | 含义 | 怎么判定 | 页面上 |
|---|---|---|---|
| `feature` 功能 | 用户能感知的可选功能，一个功能由一个或多个内置插件组成 | 出现在功能目录（§3）里 | 「功能」小节，按功能一行 |
| `official` 官方插件 | 随应用提供、能被插件包替换 | 随带插件包（`plugins/bundled.py`）与它们依赖的中枢 `channels.hub` | 「官方插件」小节 |
| `system` 系统模块 | 其余全部 | 默认 | 底部一行入口 + 只读清单；异常时浮出 |

- **新增内置插件默认是系统模块**：要出现在「功能」里，必须显式加进功能目录。宁可少展示，不把内部模块误放给用户。
- 第三方插件包、本地插件不分层，照旧在「已安装」里（替换随带插件包的包，在「官方插件」里那一行标「已被插件包替换」，
  管理操作仍在「已安装」）。
- 原来的领域分组（`BUILTIN_GROUPS`）保留，只用于系统模块清单内部的分组。

## 3. 功能目录（`src/movieclaw_api/plugins/features.py`）

| 功能 | 组成的插件 | 设置入口 | 说明 |
|---|---|---|---|
| AI 助手 | `agent.runs`、`agent.session-index`、`agent.attachments` | `/settings/ai` | |
| AI 字幕生成 | `subtitle.gen`、`subtitle.pgs-warm` | `/settings/ai` | |
| 自动入库 | `library.ingest-watch` | `/settings/import-watch` | |
| 媒体库实时监控 | `library.watch` | `/library/manage` | 开关在每个媒体库的编辑里 |
| 自动刷分享率 | `boost`、`boost.sentinel` | `/settings/sites` | |
| 新片到达通知 | `push.arrivals` | `/settings/notifications` | |
| MovieClaw Cloud | `cloud`、`push.channels-refresh` | `/settings/cloud` | |
| Jellyfin 局域网发现 | `jellyfin.discovery` | — | 让 Jellyfin 客户端在局域网里自动找到服务器 |

- 功能的状态由组成插件汇总：任一失败 / 不兼容 → 异常（写原因）；任一报告降级 → 运行异常；全部关闭 → 已关闭；
  任一在等依赖 → 等待；否则运行中。
- 每个功能写一句给用户看的说明（不出现插件 id、`plugins.yaml` 这类实现细节）。
- 片头片尾识别**暂不放**：`library.skip-segments` 只是「启动补算」，识别本身在媒体库扫描里，放进来会让状态与功能对不上。
  第 3 步做成可关闭时再加。

## 4. 页面（第 1 步）

```
设置 → 插件
  [安全模式横幅]（不变）
  [系统模块异常]（有异常时才出现：每项一行，名称 + 原因 + 查看日志）
  功能            8 行：功能名 · 一句说明 / 状态 · 去设置 ›
  官方插件         IM 通道：微信 / Telegram / Discord / 飞书 —— 内置版本 / 已被插件包替换 · 状态 · 去设置 ›
  第三方插件       （不变：上传、批准、回滚、卸载）
  本地插件         （不变，有才出现）
  ──────────────
  另有 35 个系统模块，运行正常 · 查看          ← 点开：只读清单，按领域分组，带启动耗时
```

- 去掉「已安装 / 内置」页签：分层后一页放得下，页签反而把用户最该看的拆开了。
- 系统模块清单：每行中文名称、状态、启动耗时；不出现开关和「核心 / 可关闭」徽标，统一说明「应用运行所需，无需操作」。
  诊断信息（启动最慢的几个）留在清单顶部。插件 id 小字保留，方便排障时对照日志。
- 「查看日志」链接到 `/settings/logs?q=<条目 id>`：系统日志页支持用 `q` 参数预填筛选。

### 4.1 兼容

- 旧链接 `?tab=builtin`（已发出的待处理事项、已发布的 iPhone / Mac App 写死的兜底跳转）：打开页面并展开系统模块清单。
- 新的启动失败通知带 `action_href = /settings/plugins?module=<条目 id>`：展开清单并定位到那一行。
- `app.plugins.list` 只**新增**字段（每个插件的 `tier`、`feature`，顶层的 `features` 目录），不删不改旧字段，
  老客户端不受影响。

## 5. 分步实施

| 步 | 内容 | 验证 |
|---|---|---|
| 1 | 分层与功能目录（服务端）；插件页改版；异常浮出；通知跳转；日志页 `q` 参数 | 单测：每个内置插件恰好一层、功能目录引用的插件都存在、随带包都是官方插件；网页逻辑单测；NAS 上真实页面截图核对，人为制造一个系统模块失败看浮出与跳转 |
| 2 | 功能开关的底座：开关状态存配置（取代 `plugins.yaml` 里对这些功能的关闭）、运行中启停（`reloadable` 插件 unmount / mount）、依赖检查 | 运行中关掉再打开不重启；依赖它的插件给出明确提示 |
| 3 | AI 字幕生成、片头片尾识别做成可关闭：入口受插件控制，关闭时接口返回「功能已关闭」、界面隐藏入口 | 关闭后播放器与媒体库里没有入口，接口 409 而不是排队卡住 |
| 4 | AI 助手做成可关闭：先把 IM 通道中枢的「对话」与「推送」拆开，没有 AI 助手时推送照常 | 关闭 AI 助手后 IM 推送照常、对话回复「AI 助手已关闭」 |

第 2～4 步动手前各自补充细节。

## 6. 风险

| 风险 | 应对 |
|---|---|
| 系统模块藏起来后，出问题用户找不到 | 异常浮出到页面顶部 + 待处理事项；底部入口常驻，状态写在入口那一行（「运行正常」/「1 个异常」） |
| 新增内置插件默认隐藏，功能该展示却被漏掉 | 评审清单里加一条：新增内置插件时判断要不要进功能目录 |
| 功能状态汇总把细节盖住 | 功能行的说明写出具体是哪个组成插件、什么原因 |
