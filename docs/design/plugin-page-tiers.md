# 插件页分层：功能、官方插件、已安装与系统模块

> 状态：**已实现**（2026-10-09）。关联：`plugin-kernel.md` §10（诊断页）、`plugin-channels.md`
> （随带插件包与替换）、`plugin-phase3.md`（插件包）、`settings-ui.md`（设置页规范）。

## 0. 结论先行

**原则（2026-10-09 用户定）：不为了插件而插件。引擎的扩展能力在，但不一下子都给用户。**

1. **插件页只放真正的插件**：官方插件（随应用提供、可用插件包替换的，现在是 IM 通道）、第三方插件、本地插件。
2. **MovieClaw 自己的能力都是系统模块**：自动入库、实时监控、AI 字幕、刷流、Cloud 这些是产品本身的能力，
   不是插件，不在插件页展示、不在插件页开关。系统模块平时只在页面底部留一行「另有 N 个系统模块，运行正常 · 查看」。
3. **异常自动浮出**：系统模块启动失败或报告降级时，在页面顶部出现异常提示，写明是哪个、为什么，附「查看日志」；
   同时照旧进待处理事项。
4. **功能开关的底座在服务端**（§6）：状态管理、运行中启停、管理员硬覆盖锁定、失败回滚都做好；接口 / CLI / Agent
   可用，**网页上不出常驻开关**。功能确实被停用时，它的设置页顶部提示「已停用」，管理员可一键重新开启。
5. **AI 助手（Agent）是核心**，不进功能目录、不可停用（用户定：内核最重要的一部分）。

## 1. 为什么改

现在「设置 → 插件 → 内置」把 49 个内置插件全部按领域列出来。其中大多数用户既不能关也不能换：

| 类别 | 数量 | 例子 |
|---|---|---|
| 核心（不能关） | 8 | 数据库、配置、密钥、网络出口、站点目录 |
| 标了「可关闭」，但关了没有用户意义 | 6 | `kernel.*`：关掉后所有第三方插件失效 |
| 既不能关也不能换 | 27 | 维护自愈小任务 12 个（凭据自愈、会话索引校准、光盘片长修正……）；核心功能（媒体库、任务执行器、转码……） |

这些条目对用户是噪音：看不懂、也不能操作。「可关闭」的说法也误导人——要改 `data/plugins.yaml` 再重启，
网页上没有开关；其中几项（刷流、Cloud、实时监控）在各自设置页本来就有开关，插件页是重复入口。

### 1.1 别人怎么做（2026-10-09 调研）

| 产品 | 内部模块 | 出问题时 |
|---|---|---|
| DeepSeek Harness | 管理页只放能操作的（官方插件配置、可选功能、已装包），核心组合包（约 180 个插件）被硬编码排除；全量清单在「设置 → 内置插件」只读页，失败的排最前 | 清单里置顶「启动失败」；管理页坏包带标签 |
| VS Code | 内置扩展默认不在「已安装」里，要 `@builtin` 过滤才看得到 | **出错、要重启、有更新时自动浮到主列表** |
| Obsidian | 「核心插件」页只列用户功能（反向链接、关系图、日记），基础设施完全不出现 | — |
| Home Assistant | 内部组件标 `system` 类型，集成页不显示 | 统一的「修复」中心（分级、可一键修复、可忽略）；启动失败通知附按组件过滤好的「查看日志」；「系统信息」页由组件上报健康数据 |
| WordPress | 必须加载的插件单独一个页签、无开关 | 加载失败的进「已暂停」页签，行内写错误 |

共同点：**按「用户能否感知、能否操作」分层，而不是按代码结构；内部模块可达但不打扰；异常主动浮出。**

## 2. 分层

| 层 | 含义 | 怎么判定 | 页面上 |
|---|---|---|---|
| `official` 官方插件 | 随应用提供、能被插件包替换 | 随带插件包（`plugins/bundled.py`）与它们依赖的中枢 `channels.hub`；替换它们的插件包也算 | 「官方插件」小节（中枢只在出问题时露面） |
| `system` 系统模块 | 其余全部 | 默认 | 底部一行入口 + 只读清单；异常时浮出 |

- 新增内置插件默认是系统模块。
- 第三方插件包、本地插件不分层，照旧在「第三方插件」「本地插件」小节。
- 原来的领域分组（`BUILTIN_GROUPS`）保留，只用于系统模块清单内部的分组。
- 设计初稿曾有第三层「功能」（可选功能放插件页、带开关），落地后撤掉：那些是产品本身的能力，放进插件页
  会让人以为它们是可有可无的附加件，而且各自的设置页本来就有入口。

## 3. 功能目录（`src/movieclaw_api/plugins/features.py`，只给功能开关用，插件页不展示）

| 功能 | 组成的插件 | 设置入口 | 可停用（服务端） |
|---|---|---|---|
| AI 字幕生成 | `subtitle.gen`、`subtitle.pgs-warm` | `/settings/ai` | 暂不 |
| 自动入库 | `library.ingest-watch` | `/settings/import-watch` | ✅ |
| 媒体库实时监控 | `library.watch` | `/library/manage` | ✅（各库的开关在库编辑里） |
| 自动刷分享率 | `boost`、`boost.sentinel` | `/settings/sites` | 暂不 |
| 新片到达通知 | `push.arrivals` | `/settings/notifications` | ✅ |
| MovieClaw Cloud | `cloud`、`push.channels-refresh` | `/settings/cloud` | 暂不 |
| Jellyfin 局域网发现 | `jellyfin.discovery` | — | ✅ |

AI 助手（`agent.runs`、`agent.session-index`、`agent.attachments`）是核心，归系统模块。

- 每个功能写一句给用户看的说明（不出现插件 id、`plugins.yaml` 这类实现细节）。
- 片头片尾识别不在目录里：`library.skip-segments` 只是「启动补算」，识别本身在媒体库扫描里，状态与功能对不上。

## 4. 页面

```
设置 → 插件
  [安全模式横幅]（不变）
  [系统模块异常]（有异常时才出现：每项一行，名称 + 原因 + 查看日志）
  官方插件         IM 通道：微信 / Telegram / Discord / 飞书 —— 内置版本 / 已被插件包替换 · 状态 · 设置 ›
  第三方插件       （不变：上传、批准、回滚、卸载）
  本地插件         （不变，有才出现）
  ──────────────
  另有 N 个系统模块，运行正常 · 查看            ← 点开：只读清单，按领域分组，带启动耗时
```

- 去掉「已安装 / 内置」页签：一页放得下，页签反而把用户最该看的拆开了。
- 系统模块清单：每行中文名称、状态、启动耗时；没有开关和「核心 / 可关闭」徽标，统一说明「应用运行所需，无需操作」。
  插件 id 小字保留，方便排障时对照日志。
- 「查看日志」链接到 `/settings/logs?q=<条目 id>`：系统日志页支持用 `q` 参数预填筛选。

### 4.1 兼容

- 旧链接 `?tab=builtin`（已发出的待处理事项、已发布的 iPhone / Mac App 写死的兜底跳转）：打开页面并展开系统模块清单。
- 新的启动失败通知带 `action_href = /settings/plugins?module=<条目 id>`：展开清单并定位到那一行。
- `app.plugins.list` 只**新增**字段（每个插件的 `tier`、`feature`，顶层的 `features` 目录），不删不改旧字段，
  老客户端不受影响。

## 5. 分步实施

| 步 | 内容 | 状态 |
|---|---|---|
| 1 | 分层与功能目录（服务端）；插件页改版；异常浮出；通知跳转；日志页 `q` 参数 | 已实现 |
| 2 | 功能开关的底座与状态管理（§6），服务端先放开 4 个功能；停用的功能在其设置页提示并可一键恢复；网页不出常驻开关 | 已实现 |
| 3 | 其余功能（AI 字幕、片头识别、刷流、Cloud）要不要可停用：按需再定，不主动铺开。真要做时入口须受控、接口返回 `FEATURE_DISABLED` | 暂不做 |

原第 4 步（AI 助手可关闭）取消：AI 助手是核心。

## 6. 功能开关的状态管理（第 2 步）

| 方面 | 做法 |
|---|---|
| 状态存哪 | `data/plugins-features.json`，只记停用的功能（谁、什么时候）；原子写入（临时文件 + 改名）。不放数据库：内核要在数据库就绪前决定哪些插件不启动 |
| 启动 | 停用的功能翻成补丁层的禁用补丁（来源 `feature:<key>`），与 `plugins.yaml`、环境变量同一套机制 |
| 运行中切换 | `PUT /app/features/{key}`（管理员）：先写状态文件，再调内核的运行中启停——停用按逆序、开启按正序；内核这步出错就把文件改回去、把插件恢复原状。同一时刻只处理一个切换 |
| 优先级 | 管理员的硬覆盖（`plugins.yaml`、环境变量）高于开关：被它们关掉的功能，开关锁住、写明原因（`locked_by`），接口返回 `FEATURE_LOCKED` |
| 容错 | 状态文件读不出来按全部开启处理并告警；文件里已不存在 / 不再可停用的功能忽略，免得一个旧开关永远关着某个插件 |
| 谁能看、谁能改 | `GET /app/features` 成员也能读（各端据此隐藏入口）；切换只有管理员 |
| 放开的条件 | 组成插件都 `disableable` 且 `reloadable`；功能外没有插件依赖它们提供的服务；停用后它在各页面的入口要么隐藏、要么明确提示（测试守着前两条） |
| 网页 | 不出常驻开关；停用的功能在它的设置页顶部提示「已停用」与停用人，管理员可一键重新开启（被 plugins.yaml / 环境变量关掉的不给按钮，写明原因） |

## 7. 风险

| 风险 | 应对 |
|---|---|
| 系统模块藏起来后，出问题用户找不到 | 异常浮出到页面顶部 + 待处理事项；底部入口常驻，状态写在入口那一行（「运行正常」/「1 个异常」） |
| 服务端停用了一个功能，网页上找不到开关 | 功能确实被停用时，它的设置页顶部提示并给管理员「重新开启」；诊断清单里那几个插件也写明「已经功能开关停用」 |
