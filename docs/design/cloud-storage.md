## 0. 起因与结论

用户反馈「不支持上传网盘」。网盘玩家的真实诉求是三件事：**NAS 不爆盘；在外面能流畅看高码率**（家里上行常在
50 Mbps 以下，4K 原盘码率更高）；**订阅到能看要快**。上传只是手段。

同类工具（LitePan、SmartStrm、CloudDrive2 + MoviePilot……）的形态是「网盘 → strm 文件 → Emby」：strm、nfo、定时
扫网盘、刷新 Emby，都是因为下游媒体服务器是黑盒、只认文件。MovieClaw 从订阅、下载、入库到播放器全是自己的，这层
间接可以拿掉。

**结论（用户决策 2026-10-17）：**

1. **网盘是媒体库文件的一个存储位置，不是另一个库。** 同一条台账（`library_file`）可以有本地字节、云端副本，或两者都有。
   字节在哪是存储策略，条目、观看进度、规格、派生数据都不变。
2. **本地优先分析，再上云。** 文件还在本地时把所有要读字节的活干完（规格、关键帧、字幕、缩略图、片头片尾识别……），
   上云后全部保留。网盘条目不再是二等公民，也不必为这些远程读整片、撞网盘风控。
3. **首期就支持「上传核验后释放本地」**，不只是「上传保留本地」。
4. **不考虑 Emby / Jellyfin 兼容**：不生成 strm、不写 nfo、不扫网盘。台账就是事实来源。（Jellyfin 兼容接口照常
   工作，取流走同一个读源入口，见 §6。）
5. **分两部分实施**：内核扩展（本文）在主仓库；每个网盘一个**存储后端插件**，放插件仓库。宿主管机制与安全底线，
   插件只管「怎么跟这家网盘说话」——与下载器适配器同一个形状。

strm 不废弃：外部工具生成的 strm 照旧能导入、能播放（strm-playback.md），只是 MovieClaw 自己的网盘副本不走 strm。

## 1. 与现有设计的关系

- **取代** plugin-extension-model.md §2.2 的推演（插件经 `ingest.staged` 上传后写 `.strm` 回库）。那条路要把文件先放
  暂存目录、上传完再以 strm 形态重新入账，规格和派生数据全丢，等于在自己的产品里重做一遍 Emby 玩法。
  `ingest.staged` 槽位与 `cloud_strm` 示例保留，服务其他「整理后交给外部流转」的场景。
- **复用** strm-playback.md 的远程读取：直链作 ffmpeg 输入、按 Range 稀疏读、内网直链转发、直链缓存与并发合并
  （`services/playback/strm_direct.py`）。区别只在「直链从哪来」：strm 从文件内容来，云端副本从存储后端来。
- **领域归属**（按 library-boundary.md §1 的标准）：

| 部分 | 归属 | 理由 |
|---|---|---|
| 副本台账、指纹、读源、选源、淘汰闸门、核验、删除护栏、对账 | 媒体库（宿主） | 不可逆数据操作与安全底线；所有端的核心流程都要用 |
| 存储账号、凭据加密、限速与配额、调度、错误分类 | 宿主（新模块 `storage`） | 同上；对所有网盘一致 |
| 各家网盘协议 | 存储后端插件 | 对接外部第三方，名单长、变化快、每人只用一两家 |
| 本地释放后做种结束删种 | 获取领域（下载模块） | 媒体库不认识种子；下载模块订阅媒体库事件自己决定（§5.3） |

## 2. 数据

### 2.1 存储账号 `storage_account`

| 列 | 说明 |
|---|---|
| `id`、`backend`（存储后端类型，如 `115`）、`name`（用户起的名字） | |
| `credentials` | 加密 JSON（令牌、过期时间、用户 id），只经宿主读写，不进任务输入、不进日志 |
| `status` | `ok` / `auth_expired`（要重新登录）/ `rate_limited`（带恢复时间）/ `disabled` |
| `capabilities` | 插件声明的能力快照（§8.1），插件不在时界面仍能解释 |
| `qps`、`daily_budget` | 限速与每日预算，默认取插件声明，用户可改 |
| `quota_total`、`quota_used`、`profile_at` | 容量与昵称，按天刷新 |

### 2.2 库的存储策略（`library` 新列）

| 列 | 取值 |
|---|---|
| `cloud_account_id` | NULL = 不上网盘 |
| `cloud_root` | 网盘上的根目录（默认 `MovieClaw/<库名>`）；文件在网盘的相对路径与库内相对路径一致 |
| `cloud_mode` | `mirror`（上传，保留本地）/ `offload`（上传核验后释放本地） |

一期是库级策略：整库要么不上，要么全上。按条目、按看过与否、按空间水位淘汰留到二期（§12）。

### 2.3 文件指纹 `library_file_fingerprint`

`library_file_id`、`size_bytes`、`mtime_ns`、`sha1`、`md5`、`head_sha1`（前 128 KB）、`computed_at`。
一次顺序读同时算出所有网盘要用的指纹（§4.1）；大小或 mtime 变了即作废。除上传外还用于：核验、重复文件判定、
云端副本丢失时按指纹秒传恢复（§9）。

### 2.4 云端副本 `library_file_replica`

| 列 | 说明 |
|---|---|
| `library_file_id`、`account_id` | 一期每个文件最多一个副本（唯一约束），表结构不限制以后多副本 |
| `remote_id`、`remote_path` | 网盘文件 id（一切操作只认它）；路径只用于展示与重建目录 |
| `state` | `uploading` / `verified` / `lost`（核验或对账发现不见了）/ `deleting` |
| `method` | `rapid`（秒传）/ `upload`（真传） |
| `verified_at`、`checked_at` | 核验时间；最近一次对账时间 |

### 2.5 `library_file` 新列：`local_released_at`

NULL = 本地字节在 `file_path`；非 NULL = 本地已释放、字节只在云端。**不新增 `state` 值**：「在位」的含义从「文件在本地」
放宽为「我们拥有它」，库存、海报墙、订阅对账、观看统计的所有口径照旧成立。`file_path` 保留原值：它仍是条目在库里的
位置（目录结构、旁车文件、相对路径都从它算）。

## 3. 流程总览

```
入库（本地，现有）──▶ 本地派生活（现有：规格 / 关键帧 / 字幕 / 缩略图 / 片头片尾 …）
        │
        ▼ library.file.created（库开了网盘）
上传任务 storage.upload（持久化任务，挂在入库任务下）
   1 指纹：一次顺序读算 SHA1 / MD5 / 前 128KB
   2 建目录：按库内相对路径
   3 秒传：按指纹（可能要回答区间挑战）——命中就结束字节传输
   4 真传：分片、断点续传、宿主限速读取
   5 核验：网盘返回的大小与哈希 == 本地指纹 → 副本 verified
        │
        ▼ cloud_mode = offload
释放闸门（§5）：副本 verified ∧ 本地派生活都已完成 ∧ 无正在读本地的会话
        ▼
释放本地：删库内文件 → local_released_at → 事件 library.file.local-released
        ▼（获取领域）
做种结束后删种，空间真正回来（硬链接入库时）
```

存量文件：库开启网盘时建一个回填作业，按入库时间从新到旧逐个建上传任务；秒传优先、低优先级、受每日预算约束。

## 4. 上传

### 4.1 指纹

- 一次顺序读算齐 SHA1、MD5、前 128 KB SHA1，结果落 `library_file_fingerprint`。50 GB 在 NAS 机械盘上约 5～6 分钟，
  相对真传（同样 50 GB 在 50 Mbps 上行要两个多小时）可以忽略，秒传命中时省掉全部时间。
- 读取走宿主的磁盘读限速（与刷流、扫描共享），低优先级，不与播放抢盘。
- 已有指纹且大小、mtime 未变就不重算。

### 4.2 任务

- 任务类型 `storage.upload`，去重键 = `library_file_id`，资源锁 = 存储账号（同账号串行或小并发，由能力声明定），
  不持有媒体库资源锁（几十 GB 的上传不能堵住扫描、整理、转移）。
- 续传状态（插件给的不透明 JSON：分片、上传 id……）存任务状态，重启后交回插件续传。
- 结局：网络或限流 → `JobRetry`（指数退避，限流按插件给的等待时长）；认证失效 → `JobBlocked`（带「去重新登录」动作，
  账号状态置 `auth_expired`，同账号其余任务一起阻塞）；网盘空间不足 → `JobBlocked`（带容量说明）；
  本地文件已变化（洗版、被删）→ 放弃，不算失败。
- 插件抛出的异常按 §8.4 分类处理，插件自己不重试、不睡眠。

### 4.3 上行让路

上传读取经宿主的 `UploadSource`（顺序读取器），**限速在宿主这一侧**：

- 全局上传上限（设置里填，默认不限）；
- 有经服务器出字节的外网播放（远程转码、服务器转发直出）时，上传自动降到上限的 20%，播放结束 30 秒后恢复。
  判断依据是播放会话的取流登记（`playback_activity` 的 `device_meters`），不额外采样、不碰盘
  （遵守「统计计量零开销」的约束）。
- 进程外插件读本地文件用路径授权（库根只读），每读一块先向宿主领令牌（按 4 MB 一批，经插件 IPC），保证限速不可绕过。

## 5. 释放本地

### 5.1 闸门

`cloud_mode = offload` 时，以下全部满足才释放：

1. 副本 `verified`（网盘返回的大小与哈希 == 本地指纹）。**这是唯一不可逆的一步，任何一环没确认都不释放。**
2. **本地派生活都已完成**：派生活登记表（新的注册表，各功能登记一个 `pending(file) -> bool`）里没有一项还在等这个
   文件——规格探测、关键帧索引、内封字幕抽取、缩略图、片头片尾识别、刷片预切（开启时）。登记表也是领域中立的：
   以后新增读字节的功能登记一项即可。等太久（默认 24 小时）照常释放，没做完的活以后按远程读取补（与 strm 条目同一套）。
3. 没有会话正在读这个本地文件（播放、转码、离线导出）；有就等会话结束。
4. 释放前**再核一遍**：本地大小、mtime 与指纹记录一致；`stat(remote_id)` 仍存在且大小一致。

### 5.2 动作

删除库内文件本身（不删旁车：外挂字幕、图片、`.nfo` 都留在原处，体积小、离线可读），发事件
`library.file.local-released`（文件 id、条目、释放的字节数、是否仍有其他硬链接）。

**先记台账、再删文件**：先提交 `local_released_at`，再删文件；删失败就把 `local_released_at` 清回 NULL。
顺序反过来不行——实时监控（`library/watch.py`）收到删除事件会立刻触发范围扫描，扫描看到 `local_released_at`
还是 NULL 的行就会把它标成缺失（§14.3）。

### 5.3 空间什么时候真正回来

- **复制入库**：库文件就是独立一份，删了就回来。
- **硬链接入库**：库文件与下载目录是同一份数据，删库文件不释放空间，还在做种。这一半属于获取领域：下载模块订阅
  `library.file.local-released`，对这份数据的来源种子尝试删种，条件复用删除参与方的判断（`services/remove_source.py`
  的 `_skip_reason`，执行时重新校验）：是 MovieClaw 投递的、种子不再供着库里其他**本地在位**的文件、删种否决钩子
  （`dl.torrent.before-delete`）不反对、不是 H&R 种子。下载设置里加一个开关「网盘副本就绪后自动删除下载任务」（默认开）。
- **H&R 现在只是一个布尔值**（来自下载来源记录），没有做种时长、分享率的达标判断。一期对 H&R 种子一律不自动删，
  界面列出「因 H&R 保留的 N GB」，用户可在下载页手动删；做种达标策略（时长 / 分享率）另起设计，届时这里换成它的结论。
  删种否决钩子也让用户能用插件实现自己的规则。
- 界面如实说：「已上传到 115，本地文件已释放；其中 38 GB 仍在做种，做种达标后自动删除」。

## 6. 读源与选源

### 6.1 统一读源入口

现在读字节的地方都经 `streaming.media_input` / `parse_strm` / `open_strm_range` 分叉本地与 strm。扩展为按**台账**而不是
按路径判断：

```
file_source(file) ->
    Local(path)                                     本地字节在
  | Remote(account_id, remote_id, capabilities)     本地已释放、副本 verified
  | Strm(...)                                       外部 strm（现状）
  | Unavailable(reason)                             副本 lost / 账号认证失效 …
```

`Remote` 的读取复用 strm 的整套远程读法；直链由存储后端给（`direct_link(remote_id, ua)`），按（账号、文件、UA 类别）
缓存插件给的时长（最长 1 小时）、同文件同 UA 并发只取一次，删除、移动、洗版时主动作废。服务器自己读（探测、转码、字幕）
用插件默认 UA，与给播放器的链接分开缓存。

**不能借用 `is_strm`。** 现在的 strm 分支都按「路径以 `.strm` 结尾、本地有这个 strm 文件」判断，云端副本的
`file_path` 是 `.mkv` 且本地不存在，一个都接不住，全会落进本地分支然后 404 或静默失败（§14.1）。而且 strm 的
那些规则（不探规格、不做刷片、不挑字幕）是为「规格为空、没有派生数据」设计的，对云端副本多数不合理。所以各处
改为看 `file_source(file)` 的结果，而不是看扩展名。

### 6.2 选源

| 本地字节 | 云端副本 | 客户端 | 直出（档 0） | 换封装 / 转码 |
|---|---|---|---|---|
| 在 | 无 | 任意 | 本地（现状） | 本地 |
| 在 | 已核验 | 内网 | 本地 | 本地 |
| 在 | 已核验 | 外网 | **302 到网盘直链**（绕开家宽上行） | 本地 |
| 已释放 | 已核验 | 任意 | 302 到网盘直链 | 服务器从网盘拉（下行通常充裕） |

- 内网 / 外网按请求对端地址判断（经 nginx 前门时取受信的转发地址）：环回、私网、链路本地、IPv6 ULA 算内网；
  其余（含 Tailscale 等 100.64/10）算外网——字节都要走家宽上行。
- 插件声明直链不是原画（`original_link = False`）或单连接限速太低时，外网直出不走 302，回退本地或服务器转发。
- 用户可在库设置里关掉「外网直出走网盘」（例如网盘非会员限速），关了就只在本地已释放时才用网盘。
- 离线下载（iPhone）不 302：后台下载跟跳转会把设备令牌带给网盘（strm-playback.md §7.1 同理），由服务器读云端转出。

## 7. 配额与调度

所有对存储后端的调用都经宿主的包装（主进程与进程外两种运行方式一致）：

- **超时**：每次调用有硬超时（取直链 8 秒、元数据 30 秒；上传按分片大小放宽）。插件里卡死不会拖住宿主。
- **按账号限速 + 每日预算**，三个优先级：① 取直链（播放）② 用户操作（删除、移动、手动核验）③ 后台（上传、回填、对账）。
  后台用量到预算的 70% 就停，把余量留给播放；限流（`RateLimited`）时后台整体推迟到插件给的时间，取直链继续尝试。
- 同一账号的上传任务并发数取能力声明（115 默认 1 个文件、2～3 个分片）。

## 8. 存储后端契约（`movieclaw_sdk.storage`）

### 8.1 登记

注册表 `storage-backends`（`EXPERIMENTAL`），登记项 `StorageBackendAdapter`：`type`（全局唯一，存进账号）、`title`、
`factory(account_context)`、`login`（支持的登录方式：`qrcode` 扫码 / `cookie` 浏览器扩展导入或粘贴 / `oauth_redirect` 跳转授权；
一个后端可以支持多种，凭据里记着用的是哪种）、`cookie_domains`（接收浏览器扩展推送的域名，如 `115.com`）、`capabilities`：

| 能力 | 说明 |
|---|---|
| `writable` | 能不能写（只读网盘只能当来源，一期不支持） |
| `rapid_upload_hashes` | 秒传用哪些指纹（`sha1` / `md5`） |
| `range_challenge` | 秒传会不会要求回答任意区间的哈希 |
| `original_link` | 直链是不是原画 |
| `link_needs_ua` | 直链是否按取链时的 UA 签发 |
| `single_conn_limit_bytes` | 单连接限速（未知为 NULL） |
| `recycle_bin` | 删除是否进网盘回收站 |
| `max_file_bytes`、`default_qps`、`default_daily_budget`、`upload_concurrency` | |

### 8.2 方法（`BaseStorageBackend`）

| 方法 | 用途 |
|---|---|
| `login_start(method, options)` / `login_poll(handle)` / `login_complete(params)` | 扫码或跳转授权；`options` 是插件声明的登录选项（如 115 的登录端）；成功交回凭据 |
| `login_with_cookie(cookie_header)` | 浏览器扩展推送或用户粘贴的 Cookie：挑出需要的几项、校验，成功交回凭据与账号的网盘用户 id |
| `account_info()` | 昵称、会员、容量 |
| `ensure_dir(rel_path) -> dir_id` | 逐级建目录（插件自己缓存路径到 id） |
| `rapid_upload(dir_id, name, fingerprint, size, challenge: RangeReader) -> RemoteFile \| None` | 秒传；不中返回 None，可附带续传状态 |
| `upload(dir_id, name, source: UploadSource, resume_state, on_state, on_progress) -> RemoteFile` | 真传，断点续传 |
| `stat(remote_id) -> RemoteFile` | 大小、哈希、名字（核验、对账） |
| `direct_link(remote_id, user_agent) -> DirectLink` | 地址、可复用秒数（无请求头：要带头的直链播放器不会带） |
| `move(remote_id, dir_id)` / `rename(remote_id, name)` | 条目转移、整理改名 |
| `delete(remote_ids)` | 删除（有回收站就进回收站） |

插件拿不到数据库、拿不到别的账号；本地文件只能经 `RangeReader` / `UploadSource`（或路径授权的只读库根）读。

### 8.3 凭据

宿主创建适配器实例时注入解密后的凭据。插件刷新令牌后**把新凭据作为调用结果的一部分交回**（`CredentialsChanged`），
宿主先落库再把结果交给调用方——网盘普遍是滚动刷新令牌（用一次就换新），先用后存会在崩溃时丢失登录态。

### 8.4 错误分类

| 异常 | 宿主怎么处理 |
|---|---|
| `RateLimited(retry_after)` | 该账号后台操作推迟；任务 `JobRetry` |
| `RiskControl` | 同上，推迟更久（默认 1 小时），设置页提示 |
| `AuthExpired` | **只有这一种**要求重新登录：账号 `auth_expired`，相关任务阻塞 |
| `NotFound` | 核验 / 对账：副本 `lost`（§9）；取直链：同上并回退 |
| `QuotaExceeded` | 上传阻塞，提示容量 |
| `Conflict` | 同名已存在：插件先按内容判同（同大小同哈希视为已传） |
| `Transient` | 重试 |

未知异常按 `Transient` 处理并记日志。

### 8.5 浏览器扩展导入 Cookie

MovieClaw 浏览器扩展本来就能读当前网页的 Cookie（含 httpOnly）推给宿主（`POST /api/v1/extension/cookies`），现在只认
PT 站点，其他域名返回「未匹配到任何受支持的站点」。扩展本身**不用改**（权限、推送格式都不变），宿主侧改两处：

- **推送分发**：先按 PT 站点匹配；没匹配上时查已登记存储后端的 `cookie_domains`，命中就交给存储模块。
  存储与站点是两个领域，这里是领域中立的「Cookie 接收方」分发，以后别的插件要收 Cookie 也走这里。
- **存储模块收到后**：调插件的 `login_with_cookie` 校验并得到网盘用户 id。已有同一网盘用户的账号 → 更新凭据（扩展开了
  自动同步时，浏览器里 Cookie 变化会自动推过来，账号保持可用）；没有 → 新建账号（用户是在 115 页面上主动点的同步），
  扩展弹窗显示「已添加为存储账号：昵称」。
- 校验失败（没登录、Cookie 不全）原样返回原因，扩展弹窗展示。

Cookie 只存插件挑出的那几项（经 `login_with_cookie` 返回的凭据），不存整页 Cookie；与其他凭据一样加密、不进日志。

### 8.6 进程外运行

照下载器适配器（downloader-adapters.md §4）：子进程按（登记 id、账号）缓存实例；宿主登记 `RemoteStorageBackend`
逐方法转发；`RangeReader` / `UploadSource` 在子进程侧用路径授权直接读，限速令牌经 IPC 领取（§4.3）。

## 9. 对账：不扫网盘

- **台账就是事实来源**，不列网盘目录、不按目录修改时间推断（SmartStrm 的漏扫问题全来自这里：深层改动上级目录的
  修改时间不变、个别网盘时间不可靠、同路径换文件识别不到）。
- 低频抽检：每天用后台预算的一小部分对 `verified` 副本逐个 `stat`，30 天轮一遍；播放或读取时遇到 `NotFound` 立即触发。
- 发现不见了：副本 `lost` → 本地还在就重新上传；本地已释放就**先按指纹秒传恢复**（网盘去重池里多半还有）→ 失败则
  文件标 `missing`（现有语义：缺失提醒、订阅按现有规则处理）。
- 用户在网盘里手动移动、改名我们的文件不影响（只认 `remote_id`）；手动删除会进入上面的流程。
- **库扫描要认已释放的行**（§14.3）：判缺失、库根移除时批量标缺失、自动清除缺失行，都跳过 `local_released_at`
  非 NULL 且副本 `verified` 的行；**改名归并（`_try_relink`）不得把这些行当候选**——否则用户重新下载同一版本时，
  新文件会按「同尺寸、旧路径不在」被认成改名，劫持这一行，云端副本从此无主。

## 10. 删除、回收站、转移、洗版

- **只删自己写进去的**：一切删除只针对 `library_file_replica.remote_id`，绝不按路径、按目录删。
- **回收站**：库文件进回收站时云端副本不动；回收站清理（到期或手动）时删云端副本——有网盘回收站的进网盘回收站，
  第二道保险。
- **批量护栏**：一次清理涉及的云端文件超过 50 个或 200 GB 时，暂停并在任务中心等管理员确认（SmartStrm #37：改顶层
  目录名触发同步删除，批量删掉一大片）。
- **条目转移 / 整理改名**：本地在时照现状搬本地，云端副本跟着 `move` / `rename`；本地已释放时只改台账与云端。
- **洗版**：新版本照常入库、上传、核验；旧文件按现有洗版规则进回收站，其云端副本随回收站清理删除。
- **删除对话框**：预览里写清楚「同时删除 115 上的文件（进 115 回收站）」。硬链接、可释放空间的预览按台账算
  已释放的文件（现在按 stat 算，stat 失败会被静默跳过，文案会说错，§14.2）。

现有代码在这几处都把「本地不存在」当成「已经删掉了」然后删台账行——对已释放的文件，这会让云端文件变成孤儿
（再也没有记录指向它，也不会被删）。§14.2 列了具体位置，都要先看副本再决定。
