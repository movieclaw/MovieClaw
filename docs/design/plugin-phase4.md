# 插件体系第四阶段：插件参数的界面

> 状态：**4.1、4.2 已实施**（2026-10-10 与用户逐条讨论后定稿；取代 2026-10-09 的初稿）。总体模型见
> `plugin-extension-model.md`（§1 第 8 项「插件自有数据与界面」），内核见 `plugin-kernel.md`，进程外运行见
> `plugin-phase3.md`。范围：网页端；接口按多端设计，不写成网页专用。

## 0. 结论先行

1. **插件不带前端代码，只描述「要填什么」，由主程序渲染。** 插件前端与主程序同源运行会带着登录态调所有接口，
   绕开第三阶段的进程隔离。
2. **整个体系只有三个概念：**

   | 概念 | 回答 |
   |---|---|
   | **Schema**（JSON Schema 子集，§2） | 一个贡献的参数长什么样 |
   | **挂载点**（主程序按产品页面定义） | 参数表单出现在哪、值存在哪、存几份 |
   | **流程**（多步：扫码、授权） | 需要多步时怎么推进；一张表单不需要流程 |

3. **Schema 挂在「贡献」上，入口跟着产品功能走。** 插件往扩展点登记的每个贡献（一种下载器、一个 IM 通道、
   一种选种算法……）都可以附带一份参数 Schema；承载它的产品页面决定表单出现在哪、值怎么存：

   | 贡献 | 参数表单出现在 | 存几份 |
   |---|---|---|
   | 插件自身的通用设置 | 插件详情页（兜底入口） | 全局一份 |
   | 下载器类型 | 添加 / 编辑下载器 | 每台下载器一份 |
   | IM 通道 | IM 推送页的绑定对话框 | 每个账号一份 |
   | 将来的订阅算法、刷流策略 | 选中它的那个设置项下面 | 跟着规则组 / 站点 |

   插件详情页只放不属于任何产品功能的通用设置；能归到产品功能下的，出现在那个功能自己的页面里，
   详情页的「插件能力」列表给跳转。**不预设「接入实例」这类抽象**：插件类型很杂（接外部系统、改决策、听事件），
   存几份由产品功能本来的数据结构决定。
4. **不做插件自带网页界面（沙箱 iframe）**，前提条件记在 §6。

## 1. 参照

| 产品 | 做法 | 取了什么 |
|---|---|---|
| VS Code | 清单里声明贡献；配置项是 JSON Schema，由设置页统一画 | 用标准 JSON Schema，不自创格式 |
| Home Assistant | 所有集成同一套配置流程（表单、菜单、跳转授权、进度、中止、完成） | 「流程」的步骤词汇 |
| Atlassian Forge / Slack | 主程序定义挂载点并给上下文；声明式组件为主，iframe 兜底 | 挂载点由主程序定义 |
| MCP（elicitation） | 向用户要输入用受限 JSON Schema（扁平、基本类型） | 子集要小，不认识就拒绝 |

HA 的「接入实例」对它顺（插件几乎都是接设备），对我们不顺，见 §0 第 3 条。

## 2. Schema：JSON Schema 子集

由插件的 pydantic 模型直接生成（`model_json_schema()`），再收窄到子集：

- 顶层是对象，属性只能是：`boolean`、`string`（可带 `enum`、`minLength`、`maxLength`、`pattern`）、
  `integer` / `number`（可带 `minimum`、`maximum`）、字符串数组；可选（`X | None`）收成 `nullable`。
- 每个属性带 `title`、`description`、`default`。
- 界面提示：敏感字段用标准关键字 `writeOnly: true` + `format: "password"`（pydantic `SecretStr` 或
  `json_schema_extra={"secret": True}`）；多行文本 `x-multiline: true`。
- 不支持嵌套对象、任意数组、`$ref`。

**超出子集不报错**：插件照常加载，配置照常从 `plugins.yaml` 读；只是界面上不提供编辑，并说明是哪个字段的
什么类型（诊断页同样提示）。这样已有插件（如关键字规则示例的嵌套配置）不受影响。

渲染器遇到不认识的类型（网页没刷新还是旧版）整张拒绝，不做部分渲染。校验两层：网页只做必填和基本类型；
真正的校验在插件侧（pydantic），错误按字段回显。

## 3. 插件通用设置（第一个挂载点）

- **存储**：`data/plugins/settings/<插件 id>.json`，敏感字段经 SecretBox 加密。不进数据库：不需要迁移
  （带迁移的部署无法回退到旧版本），且与 `plugins.yaml`、插件启动记录同在数据目录、一起备份。
- **生效**：内核构造时接收配置覆盖函数，加载插件时把它叠到清单配置（本地插件的 `plugins.yaml`）上，
  界面保存的值优先。独立进程插件在启动时读合并后的配置。
- **Schema 来源**：主进程内的插件从配置模型生成；独立进程插件由子进程在 `describe` 时报上来（主进程不导入插件代码）。
- **接口**：`GET /plugins/{id}/settings`（Schema、当前值；敏感字段只回「已设置」）、
  `PUT /plugins/{id}/settings`（敏感字段留空 = 不改）。保存时先用配置模型校验（主进程内插件），再写文件并重启插件；
  **重启失败就恢复旧配置、再重启一次，返回失败原因**。
- **网页**：插件详情页加「设置」区，由通用 Schema 表单渲染（基于 `settings-ui`）。

## 4. 实施拆分

| 步骤 | 内容 | 验证 |
|---|---|---|
| 4.1 | Schema 子集（SDK）；设置存储与内核覆盖；设置接口；网页通用渲染器与插件详情「设置」区 | 本地插件进程内 / 外各跑一遍：改设置后插件拿到新值；敏感字段不回显；非法值按字段报错且旧值保留；超出子集的插件照常运行、界面说明原因 |
| 4.2 | 下载器类型的连接参数改由 Schema 描述（添加下载器表单按类型渲染）；字段限于下载器配置已有的地址、用户名、密码三栏，不加存储 | 内置两种行为不变；第三方类型（如只要 RPC 密钥的）能接入 |
| 之后 | 流程引擎 + IM 绑定迁移；订阅算法、刷流策略等开放时按同一规则接挂载点 | 有第二个多步场景时再做 |

每步独立 PR、可单独回滚。旧接口（`/channels/bindings`、`/downloaders`）字段原样保留，其他端不受影响。

## 5. 风险

| 风险 | 应对 |
|---|---|
| 子集太小，插件作者绕路（JSON 塞进多行文本） | 按真实需要加类型，不开自定义组件 |
| 改设置后插件起不来 | 恢复旧配置并重启，接口返回原因 |
| 设置文件与 `plugins.yaml` 两处来源让人困惑 | 界面写明「界面保存的值优先」；`plugins.yaml` 仍可作初始值 |

## 6. 暂不做：插件自带网页界面

只有出现通用渲染器画不出来的需求时再做，届时必须：独立源（不带 `allow-same-origin`，核实登录 cookie 不外带）；
CSP 按插件声明生成、默认全禁；只开一座消息桥（经宿主转发调用插件自己的路由，拿不到凭据和真实路径，危险操作要确认）。
