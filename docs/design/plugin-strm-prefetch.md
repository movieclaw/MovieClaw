# 网盘规格预探：第一个可卸载的官方插件——设计

> 状态：已实施（2026-10-11）。分五步，每步一个 PR；第 4 步先于第 3 步做（第 3 步的宿主操作要用它的
> 退避与结论）。
> 关联：[strm-playback.md](strm-playback.md)（网盘条目的播放与按需探测）、
> [plugin-kernel.md](plugin-kernel.md)、[plugin-extension-model.md](plugin-extension-model.md)、
> [plugin-channels.md](plugin-channels.md) §7（随带插件包）、[plugin-phase4.md](plugin-phase4.md)（参数界面）、
> [persistent-jobs.md](persistent-jobs.md)。

## 0. 起因与结论

网盘（strm）条目的规格在**第一次播放时**才探（strm-playback.md §2）：首播要多等一次远程 ffprobe，没播过的
条目详情页也看不到规格。参考 Emby 插件 StrmAssistant 的做法（播放前在后台预探、探过不再重探），把探测
挪到播放之前，按低并发后台任务补探，按观看信号插队。

用户决定（2026-10-11）：

1. 做成**插件**，而且**可以停用、可以卸载**——它是插件体系里第一个可卸载的官方插件；
2. 默认启用，安装后把已有的、没探过的网盘条目逐个补探；两次探测默认间隔 3 秒；
3. 详情页打开时探这一个条目（撤销 strm-playback.md「详情页不探网盘」的约定：有了后台预探，单条目按需
   探不会触发批量请求）；
4. 平台能力按通用设计补齐，以后的插件都能用。

插件只负责**调度**（先探谁、多快、什么时候插队）；探测本身、失败退避、strm 改写后重探留在主程序——
插件卸掉以后首播现探照常工作。

## 1. 第一步：官方插件可停用、可卸载

随带插件包（`src/movieclaw_plugins/*`）此前只能在 `data/plugins.yaml` 里写禁用补丁再重启，界面上不能停用，
也不能卸载（「卸载」只对同 id 的替换包有意义：卸掉后随带版本回来）。

**状态**：`data/plugins-switches.json`，与功能开关（`plugins-features.json`）同一种写法：只记偏离默认的项。

```json
{"version": 1, "disabled": {"<id>": {"at": "...", "by": "admin"}}, "removed": {"<id>": {"at": "...", "by": "admin"}}}
```

不放数据库：内核要在数据库就绪之前决定哪些插件不加载。

**行为**：

| 操作 | 立即 | 重启后 |
|---|---|---|
| 停用 | 内核 `disable`（来源 `switch`），取消它的后台任务 | 启动补丁 `disabled=True` |
| 启用 | 内核 `enable`；插件启动时自己重新排任务 | 不写补丁 |
| 卸载 | 内核 `unmount`，取消它的后台任务；勾选「同时删除数据」时清插件数据、界面设置、私有目录 | 不加载这个随带包 |
| 恢复 | 从 `removed` 删掉、`mount` 回来 | 照常加载 |

- 适用范围：随带插件包与已安装的插件包（停用 / 启用）；随带插件包（卸载 / 恢复，已安装的插件包本来就能卸载）。
- 管理员硬覆盖（`plugins.yaml`、环境变量）关掉的插件，开关锁住并写明原因，与功能开关一致。
- 被同 id 插件包替换的随带包不能单独卸载（生效的是插件包，卸它）。
- **任务**：停用 / 卸载时取消该插件的全部活动任务（类型取自它在 `JOB_HANDLERS` 里的贡献）。此前停用插件后，
  重启时它排着的任务会被领走并报「当前版本无法执行这类任务，请更新 MovieClaw」——取消是更诚实的结局。
- 接口：`PUT /app/plugins/{id}/enabled`、`DELETE /app/plugins/{id}/bundled`（`purge_data`）、
  `POST /app/plugins/{id}/bundled/restore`；插件列表多返回已卸载的随带包（`removed`）。
- 网页：插件详情页「停用 / 启用」「卸载 / 恢复」；官方插件列表里已卸载的显示「已卸载」与恢复入口。

## 2. 第二步：插件的后台任务

- **SDK 契约**：`movieclaw_sdk.jobs` 提供 `JOB_HANDLERS`、`RegisteredJobHandler`、`JobContext`（协议）、
  `JobRetry` / `JobBlocked` / `JobFailed` / `JobCancelled`，以及创建任务的服务 `PLUGIN_JOBS`。模块不碰数据库
  （与 `test_contract_import_weight` 同一条约束），`services.jobs` 从这里导入并原样再导出。
- **任务名称**：`RegisteredJobHandler` 加可选 `title`；任务列表与详情接口多返回 `job_type_label`，网页任务
  中心优先用它（App 端各自发版时跟上，届时之前显示原始类型名）。
- **插件创建任务**：`PLUGIN_JOBS.scoped(ctx).create(job_type, subject, input, priority, dedupe_key, resources)`，
  只能建插件自己贡献的任务类型；按 `dedupe_key` 去重（`return_existing`）。
- **任务类型名统一**：插件贡献时自己写 `<插件 id>:<名字>`；内核遇到已带本插件前缀的 id 不再重复加前缀。
  于是随带版与同 id 替换包产生的任务类型一致，停用 / 卸载时也能按前缀认出它的任务。

## 3. 第三步：事件与主程序接口

**实时事件**（`EXPERIMENTAL`，发完即忘；漏了不要紧——后台任务本来就按数据库里的待办补探）：

| 事件 | 何时发 | 载荷 |
|---|---|---|
| `library.files.added` | 扫描入账了新文件（扫描任务、实时监控、延迟补扫） | library_id、文件（id、条目、季集、是否 strm） |
| `playback.started` | 网页 / Jellyfin 开始播放 | 条目、季集、文件 id、成员 |
| `library.item.favorited` | 收藏状态变化 | 条目、成员、是否收藏 |
| `library.item.viewed` | 打开条目详情（网页与 Jellyfin） | 条目、成员 |

**宿主操作**（管理员权限，进入操作目录，CLI / MCP / 插件共用；路径前缀 `/library-strm`，免得和
`/libraries/{library_id}/…` 撞）：

- `library.strm.list-pending`：还没有规格、不在失败退避期内的网盘条目文件；可按库、条目、季过滤，可排除
  容器（按直链后缀；双后缀文件名 `foo.mkv.strm` 直接看出），按入库时间新的在前或按季集排序，游标分页；
- `library.strm.probe`：探一个文件的规格（主程序的按需探测），返回结果（probed / ready / failed /
  backoff / not_strm）、失败原因与下次可重试时间；`respect_backoff=false` 无视退避。

实时事件定义在 `movieclaw_sdk.library`（只依赖 SDK 的随带插件包也能订阅）；`HOST_OPS` 服务键随之移进
`movieclaw_sdk.ops`。

## 4. 第四步：主程序的基础能力

- **失败退避持久化**：新表 `strm_probe_state`（每个 strm 文件一行：连续失败次数、最近错误、下次可重试时间、
  探测时的直链指纹）。连续失败按 1 小时、6 小时、1 天、封顶 3 天退避；后台补探遵守退避，**用户点播放不受
  退避限制**（链接可能已经修好）。
- **strm 改写后重探**：扫描遇到已入账的 strm 文件大小或修改时间变了，重读直链：主机或路径变了（换了文件）→
  清空规格，回到待探列表；只是签名参数变了 → 只更新大小与时间，规格保留。旧行没有直链指纹的，按「换了文件」
  处理（重探一次的代价很小）。

## 5. 第五步：插件本体「网盘规格预探」

随带插件包 `src/movieclaw_plugins/strm_prefetch/`，id `strm-prefetch`，默认启用，只导入 SDK。

**参数**（插件详情页表单）：两次探测间隔（秒，默认 3）、跳过的容器（默认 `ts`、`m2ts`、`iso`——网盘上探得慢、
容易失败，留给首播现探，StrmAssistant 同样默认排除）。

**任务**：

| 任务 | 优先级 | 何时排 | 做什么 |
|---|---|---|---|
| `strm-prefetch:backfill`（全局一个，去重） | −10 | 启动时有待探、扫描入账了新的 strm、启用插件 | 每次取一个（新入库的在前）探完歇一个间隔，直到没有待探；一轮最长 10 分钟就交还执行位，后台再排下一轮 |
| `strm-prefetch:item`（每条目 / 季一个，去重） | 0 | 开始播放（下一集）、收藏（整部）、打开详情（前几个） | 只探这个范围里待探的，最多几个 |

插队靠优先级：条目任务优先于整库任务被领取；整库任务每探一个就重新取待办，不会长时间占着别人要的那一个。
整库补探不按库拆：待探列表本来就能跨库按入库时间排，一个任务足够，也免得几个库的补探同时打网盘。

去重拿回来的是正在收尾的旧任务（停用后还在取消中、一轮刚到点）时，等它结束再排，否则它一结束就没有
下一轮了。插队的条目任务也按设置的间隔一个一个探（播放的下一集、打开详情各最多 2～3 个，收藏最多 30 个）。

**先探谁**：播放的下一集 → 收藏的条目 → 打开详情的条目 → 最近入库的 → 其余。

**卸载 / 停用**：取消全部任务，事件订阅随插件撤下，回到「首次播放时现探」。数据：插件只存很少的状态，
「同时删除数据」会一并清掉。

## 6. 验证

每一步：单测 + 相关测试文件 + 端到端。第五步在仿网盘服务（/tmp/strm-lab，按请求加延迟）上跑：入库后自动
补探、播放时下一集插队、失败退避不重复请求、strm 改写后重探、停用 / 卸载后回到首播现探、恢复后接着补探。
