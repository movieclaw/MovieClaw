# 媒体库搜索首版

电视上少输几个字符就能找到片子。全部检索在本地完成，客户端共用同一套匹配规则。

## 已实现能力

- 中文片名、原名、英文名、别名；繁简、大小写、全角字符归一化。
- 全拼、首字母、前缀、子串、词组；中文与拼音混输、全拼与首字母混输。
- 例：《星际穿越》可输入 `xjcy`、`xingji`、`星际cy`、`xj穿越`、`xingjicy`。
- 演员、导演姓名搜索，点击人物浏览其全部可见库内作品。外文姓名按间隔号或空格拆分，
  因而《星际穿越》也能通过 `诺兰`、`nl`、`Nolan` 找到。
- 同一作品跨库去重；结果附匹配原因、可见库 ID 和可用的详情落点。
- 每一页重新检查库权限、内容分级、文件状态、人物关系和名称证据。
  未确认、缺失、回收站文件不参与召回；人物计数及建议只来自可见作品。

## API

`GET /api/v1/search/library?q=xjcy&limit=24`

`GET /api/v1/search/library?person_id=123&limit=24`

`q` 与 `person_id` 至少提供一个，二者同时提供则在人物作品中继续搜索。`person_id` 是
本地人物主键，而非 TMDB ID。`limit` 范围 1–100。响应使用统一的 `success/code/message/data`：

- `items`：`item`（复用 LibraryItemView）、`library_ids`、`match`（命中类型、字段、原名及说明）。
- `people`：最多 8 个匹配人物及其可见作品数。
- `suggestions`：当前结果派生的片名和人物输入建议。
- `next_cursor`：后续请求携带相同的 q/person_id 和此值。
- `index_pending`：当前可见范围仍有待更新的索引，结果已合并最新业务名称。

单次浏览固定候选顺序，翻页只追加。游标绑定账号、查询、人物及当前权限，进程内保留
120 秒；权限变化、进程重启或过期后返回 400，客户端重新搜索。会话最多 32 个、共
10 万候选；超过 10 万结果时要求补充关键词。库存或改名导致失效的候选会在翻页时跳过。

这是三端（Web、iPhone、Apple TV）及 `mclaw search library` 唯一的媒体库搜索接口。
旧的 `GET /api/v1/search/library-items` 已删除：它把相关度结果按库分组、组内再按标题
拼音重排，相关度被整个丢掉——搜「ST」时，演员 Stephen Lang 带出的《阿凡达》(a) 会排在
首字母正中的《三体》(s) 前面。客户端按 `items` 原顺序平铺展示，命中人物单独成行。

## 相关度

文字准确匹配优先，其后是准确全拼、准确首字母、名称前缀、名称包含和词组。
主标题在同档优先于原名、英文名及别名。人物命中增加档位偏移：准确片名优先于人物作品，
准确人物命中优先于片名的弱包含。同档人物按本库里的分量排序：担任主创（导演，或演员表前 5 位）的作品数 > 可见作品数 > 最靠前的一次排位；人物带出的作品同档内按此人在片中的排位排。首字母这类短输入常有一批同档人物（lyt：李一桐、刘奕铁、郎月婷……），只按作品数会打平、退化成按 id 取前 8 个。全部用本地关系表，不会使用隐藏库存或远端热度影响排序。

短的拉丁单字符只匹配准确名称或前缀；中文单字可以匹配实际包含。短缩写可能有多个合理
结果，例如 `cy` 既可能是《星际穿越》尾部首字母，也可能是英文标题的文字片段。

## 索引及更新

新增 SQLite 表 `library_search_document`、`library_search_name`、`library_search_dirty`，
以及 FTS5 表 `library_search_fts`，不修改业务字段。

名称索引保存归一化文本、全拼和首字母。B-tree 召回前缀，FTS 的字符/双字符词元召回包含
及混输候选。FTS 只做候选筛选，最终在一个原始名称上核验，避免不同别名拼出假命中。
用户输入编码为纯 ASCII 词元，不作为 FTS 表达式执行。

召回后按作品主键和人物关联索引实时核验可见性，不预先构建整库可见人物集合。
索引没有 dirty / 旧版本文档时跳过业务名称兜底；当前页只聚合本页候选的可见库存。
连续的一至两个 ASCII 字符无需混输/词组核验，在 SQL 中按同一原名计算档位，
再用窗口函数选每个实体的最佳名称；保留全部实体及原有排名，避免重复返回姓名片段。
名称、关系以及卡片的文件/图片事实由 SQLite 封装为单个 JSON 值，一次传回解码，
减少 sqlite3 逐行逐列转换造成的线程切换。普通名称查询、小批人物关系/图片仍走常规读取，
避免批量封装的固定开销。标量列仍使用 SQLAlchemy 原有类型转换，
日期、布尔、枚举及空值口径保持一致；ORM 实体和二进制列不走这条路径。
人物全名/头像只对前八个人物入口读取，游标保存轻量命中证据，当前页才创建响应模型。
当前页按命中来源核验名称：人物命中只读人物名称和关系，片名命中才读取影片别名。
海报卡只取展示所需的媒体列，减少无关 JSON 字段的解码。

媒体名称与人物名称的 INSERT/UPDATE/DELETE 触发器在同一业务事务标记 dirty，并增加
revision。后台复用持久化 JobDispatcher，分批读取、在线程中转换、短事务写回。
只有 revision 与快照一致才能领取更新，领取与写索引同事务提交，失败回滚不会丢更新。
索引版本变化也会后台重建。首次升级、改名或任务失败期间，待更新实体使用最新业务
名称执行相同规则，不依赖旧索引。

部署时迁移先执行，首次构建不阻塞应用启动。数据全部随已有 SQLite 落在 data/。
新增 OpenCC 纯 Python 依赖用于繁简转换，`docker/runtime-version` 已由 18 增至 19；
合并后需要构建并发布对应运行时镜像。

## Apple TV

系统 searchable 保留遥控器键盘、系统支持的听写和 iPhone 输入。输入防抖 350ms，旧请求
取消并校验请求序号；结果按相关度展示人物和影片。分页按作品 ID 去重，详情返回复用
当前查询与已加载结果，避免重复搜索和焦点跳动。未依赖全局 Siri 搜索能力。

## 验证

自动用例包含索引前/后的一致性、混输、多音词、数字、改名与别名更新、并发 revision、
写入失败回滚、过期/跨账号游标、权限/分级、缺失/未确认库存和跨别名误命中。

`tests/api/test_library_search_lifecycle.py` 在真实 SQLite、文件和业务作业上检查搜索与
库存的一致性：扫描建档、硬链接/复制入库、规范整理、外部改名归并、失联回归、跨库转移、
回收恢复及清理、NFO 重读改名、业务事务回滚，以及后台批量索引与扫描/改名并发写入。
外部 TMDB 和媒体探测使用替身，HTTP、搬运、台账、触发器和索引均走实际实现。
搜索分页还覆盖人物身份更正与最后一个文件在查询期间被移除：展示当前身份，空库存跳过。

`scripts/perf/verify_library_search_api.py` 走真实 HTTP 登录和业务 API，覆盖输入变体、人物
作品、分页、详情落点、旧接口及错误响应。密码只从 `MC_SEARCH_PASSWORD` 读取。
测试报告落在调用者指定路径，不保存凭据。NAS 验收使用独立容器与脱敏媒体库副本，
不修改正式媒体库、认证配置或媒体文件。

可加 `--benchmark-rounds 12` 在功能检查预热后连续测量 14 种输入的 12 轮耗时，
报告包含中位数、P95、最慢值和所有样本，并逐次校验完整结果及排序没有改变。

NAS 上曾捕获全量 GC 在名称匹配期间停顿约 323ms。生产 `movieclaw-api` 入口在创建
Server、事件循环及数据库之前完成静态应用/路由装配并收集垃圾，再用
[`gc.freeze()`](https://docs.python.org/3.12/library/gc.html#gc.freeze) 将已加载的模块、词库等
长期驻留对象及静态路由结构移入永久代，避免反复扫描。自动 GC 保持启用，运行期新建对象仍正常回收。
代价是增加一次启动期收集；永久代对象中后续失去所有外部引用的循环引用不会自动回收，
因此只在生产入口执行，开发热重载和普通应用工厂不冻结。子进程测试验证执行顺序及
运行期循环引用可回收，NAS 验收也使用此生产入口。

并发基准使用 `scripts/perf/benchmark_library_search_api.py`，每个连接独立登录，
报告每次 HTTP 请求的完整等待时间（包含网络、鉴权、查询、解码），并逐次对比完整结果：

```sh
PYTHONPATH=src .venv/bin/python scripts/perf/benchmark_library_search_api.py \
  --url http://192.168.1.10:18379 --username searchtest --concurrency 4 --rounds 12 \
  --queries nl ll ly zh --rotate-queries --report data/search-concurrency-broad.json
```

`--rotate-queries` 使不同连接从不同关键词开始，用于检验不同宽泛缩写同时查询；
只给 `--queries nl` 则测试所有连接连续查询同一缩写。基准不截断结果或缓存响应。

## 后续范围

这一版只做名称与人物搜索。错字纠正、同音纠错、年份/类型/时长等组合条件、剧情语义检索、
自然语言解析和个性化排序仍待后续实现，不将这些能力混入当前确定性匹配规则。
