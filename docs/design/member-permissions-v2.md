# 成员权限 v2：功能盘点与细化方案——设计（草案）

> 状态：**已定稿**（2026-10-01）。拍板记录：不提供「整理元数据」类管理能力；
> 「下载原文件」更名为「下载影片到设备」且默认开；成员分享默认关闭；「手动选种」
> 并入一键下载开关；发现页的分级过滤以后单独评估。
> 前作：[member-management.md](member-management.md)（v1，2026-08-10 定稿：两级角色
> + 三个能力开关 + 库/站点白名单）、[library-access.md](library-access.md)（库可见范围）、
> [library-filtering.md](library-filtering.md) F5（内容分级）。
> 本文沿用 v1 的全部原则（默认拒绝、超管不动、资源公共体验隔离、三问准则、三件套范式），
> 只回答一个问题：**v1 之后功能面翻了几倍，成员权限该怎么跟上。**

## 0. 结论先行

1. **先修后加**。盘点出 6 处后端越权、9 处前后端口径不一致（§2）。这些是 v1 规则没被
   新功能遵守，不需要新概念，先修（P0）。
2. **能力开关从 3 个扩到 5 个**，新增「下载影片到设备」「影片分享」（§3.2）。管理类
   能力（整理元数据、库管理）不下放给成员。
3. **搜索按分区授权**：入口对「至少有一个分区可用」的成员开放，三个分区各看各的权限
   （§3.3）。
4. **开关变多以后，用预设降低管理员负担**：「儿童 / 家人 / 信任的成年人」三档预设，
   只是 UI 上一键填好开关，不落库、不引入「角色」概念（§3.5）。

## 1. 功能全景盘点（成员视角）

盘点基于 2026-10-01 的 main（`5c5adc5e`）。后端以 `api/router.py` 的挂载分组和
`tests/api/test_member_auth.py::_MEMBER_ALLOWLIST` 为准，前端核对了 Web（`apps/web`）
与 iOS（`apps/apple`）两端。图例：✅ 成员默认可用 · 🔑 受成员开关控制 · ⛔ 超管专属。

### 1.1 浏览与播放

| 功能 | 成员 | 控制方式 |
|---|---|---|
| 发现页、影视详情、演职员、图片 | ✅ | 登录即可，**不受内容分级约束**；院线地区切换 ⛔ |
| 媒体库首页、单库海报墙、筛选、图廊 | ✅ | 库可见范围 + 内容分级 |
| 条目详情、分集、字幕预览 | ✅ | 同上；文件路径对成员清空 |
| 播放（直放 / 转码 / 原盘直推）、诊断、QoE 上报 | ✅ | 同上；软件转码开关 ⛔（`can_self_enable=false`） |
| 跳过片头片尾、章节、续播、默认轨记忆 | ✅ | 随播放 |
| 进度 / 已看 / 收藏 / 接下来继续 / 清除自己的观看记录 | ✅ | 按 `member_id` 隔离 |
| 片段（reels） | ✅ | 可见库 + 分级；分享链接 ⛔，成员只能系统分享文字 |
| 合集：浏览、新建、编辑、删除 | ✅ | 私有合集按人隔离；**household 合集任何成员可改删**（§2.1 漏洞） |
| 照片库原图查看 / 下载 | ✅ | 可见库 |
| Jellyfin / Infuse 等客户端 | ✅ | 库可见范围；policy 与超管相同（**可下载影片、可转码**） |
| 全家观看活动、观看统计、掐断播放 | ⛔ | 活动页 |

### 1.2 搜索

| 分区 | 后端接口 | 成员 | 控制方式 |
|---|---|---|---|
| 影视（TMDB / 豆瓣片名） | `POST /search/titles` | 🔑 | `allow_subscribe`；不受内容分级约束 |
| 资源（PT 站点聚合） | `GET /search/torrents[/stream]` | 🔑 | `allow_search` + 站点白名单 |
| 媒体库 | `GET /search/library` | ✅ | 可见库 + 内容分级 |
| 搜索历史 | `/search/history*` | ✅ | 按人隔离；回放结果时按分区补判权限 |
| 搜索预设（分类 / 站点组合） | `GET/PUT /search/presets` | 读 🔑 / 写 ⛔ | 成员前端不读，用内置默认 |
| **搜索入口与 `/search` 路由** | — | 🔑 | **只看 `allow_search`**（§2.2 U1 的 bug） |

### 1.3 订阅与获取

| 功能 | 成员 | 控制方式 |
|---|---|---|
| 发起 / 关注订阅、调整选季、自动续订、暂停、取消关注 | 🔑 | `allow_subscribe` + 发起人归属校验 |
| 立即搜索缺失、洗一轮版 | 🔑 | 同上（洗版前端实际不可用，见 U4） |
| 订阅详情、活动记录 | ✅ | **无归属过滤**（§2.1 漏洞） |
| 订阅在途下载进度 | ⛔ | 成员前端在轮询，403 被吞（U6） |
| 手动选种投给订阅 | ⛔ | 成员前端露出入口（U5） |
| 选规则组 / 目标库 / 投递预演 / 链路体检 / 删除订阅 / 季清理 | ⛔ | 成员订阅一律自动路由 |
| 一键下载（资源推给下载器） | 🔑 | `allow_direct_download`；成员强制自动路由 |

### 1.4 管理与系统（全部 ⛔，v2 不变）

- **媒体库管理**（约 60 个端点）：建库 / 编辑 / 删除 / 排序 / 默认库 / 封面；扫描、
  路径修复；刷新元数据；章节图；选图；整理改名；待识别 / 复核 / 忽略 / 认领；修正识别；
  片源标注；删除条目 / 文件 / 外挂字幕；回收站；重复文件；缺失补下；条目转移、根路径归并。
- **AI 与内容生成**：AI 会话（含 bash）、技能、AI 字幕生成与时间轴校准、LLM 配置、MCP。
- **分享**：影片 / 合集 / 片段分享链接（v2 起可按开关下放，§3.2）。
- **获取链路配置**：站点、下载器、规则组、监听导入、搜索预设写入。
- **系统**：成员、外观之外的全部设置、网络、日志、更新重启、缓存、定时任务、
  作业中心、系统通知、Webhook、IM 通道、外置转码器、插件令牌、手工令牌。

### 1.5 旁路入口

- **CLI / App 设备令牌**：每次请求按令牌主人现组 Principal，完全继承成员当前权限，
  改开关即时生效（`services/auth.py` `_device_principal`）。无需改动。
- **MCP、IM**：只绑定到超管（`is_admin=True`），成员无入口。IM 成员化仍按 v1 §3.8
  的前置条件（先与 Agent 解耦），本文不涉及。

## 3. 细化方案

### 3.1 沿用的判据

新增开关仍须三问全「是」：**成员真实会用 · 开与关有真实风险差异 · 关掉后界面自洽**。
v1 把开关压在个位数的约束不变，v2 之后是 5 个。

另补两条：

- **读和改分开过筛**。很多功能「读」是基线（看自己订阅的下载进度），「改」才需要授权；
  v1 有几处把读也一并锁了（U6）。
- **管理能力不下放**。改的是全家共享的东西（元数据、库、文件）就留给超管，不做
  「部分管理员」。

### 3.2 权限对照：v1 → v2

| 权限 | v1 现状 | v2 | 默认 | 变化 |
|---|---|---|---|---|
| 浏览、播放、个人数据 | 登录即有 | 不变 | — | — |
| 媒体库搜索 | 有权限但无入口 | 登录即有，入口可达 | — | 修 U1 |
| 合集 | 可建私有 / 共享，**可改删他人的共享合集** | 只能改删自己建的；他人的共享合集只读 | — | 修 S2 |
| 订阅详情 | 可读任意订阅 | 只能读自己发起或关注的 | — | 修 S1 |
| 自己订阅的下载进度 | 无 | 只读精简版（进度、速度、预计完成；不含下载器、路径、种子名） | — | 新增基线 |
| **订阅追踪** `allow_subscribe` | 影视搜索、发起 / 关注 / 调整自己的订阅、立即搜索、洗版（洗版实际不可用） | 同左，洗版可用（沿用订阅当前规则组，不选规则组） | 开 | 修 U4、S3 |
| **资源搜索** `allow_search` | 叫「站点搜索」；仅搜索页与发现详情有入口 | 更名「资源搜索」；条目详情也有「搜索资源」 | 关 | 更名，修 U2 |
| **一键下载** `allow_direct_download` | 搜索结果推给下载器；成员弹窗基本不可用 | 同左 + 订阅详情「手动选种」；成员弹窗只给「指定到我能看到的某个库」或「下载器默认目录」（智能入库可能路由到成员看不到的库，服务端对成员拒绝） | 关 | 扩大范围，修 U5、U7 |
| **下载影片到设备** `allow_video_download` | 无开关；Jellyfin 客户端对所有成员开放下载 | 新开关：Infuse 等 Jellyfin 客户端的下载 / 离线缓存（`EnableContentDownloading` 与 `/Items/{id}/Download`）；以后 App 做离线下载也归它 | 开 | **新增** |
| **影片分享** `allow_share` | 超管专属 | 为自己能看到的影片 / 合集 / 片段生成分享链接，只能管理自己建的 | 关 | **新增** |
| 内容分级 | 年龄上限 + 未分级是否可见 | 不变 | 不限 | — |
| 可见库 / 可用站点 | 全部或白名单 | 不变 | 全部 | — |

两个容易混的开关在界面上这样区分：

- **一键下载**：把搜到的资源**下载到服务器**，入库后全家都能看；
- **下载影片到设备**：把库里已有的片子**存到自己的手机 / 平板 / 电脑**离线看。

依赖关系（UI 联动置灰，服务端各自独立校验）：一键下载 → 资源搜索；其余互不依赖。

### 3.3 搜索怎么改

**原则：搜索按分区授权，入口跟着「有没有可用分区」走。**三个分区的权限口径不变，
改的是入口、路由和几处错用的判断。

| 分区 | 谁能用（v1 与 v2 相同） | 默认成员 | 儿童预设 | 全开成员 |
|---|---|---|---|---|
| 影视 | 订阅追踪 | ✅ | — | ✅ |
| 资源 | 资源搜索 | — | — | ✅ |
| 媒体库 | 有至少一个可见库 | ✅ | ✅ | ✅ |
| **搜索入口** | v1：只看资源搜索 → v2：**任一分区可用** | v1 ✗ → v2 ✅ | v1 ✗ → v2 ✅ | ✅ |

具体改动：

| 位置 | v1 | v2 |
|---|---|---|
| 搜索按钮、⌘K（Web 侧栏 / 移动顶栏 / Netflix 顶栏；iOS 顶栏） | `canSearch` | `canOpenSearch` = 影视 ∨ 资源 ∨ 媒体库 |
| `/search` 路由守卫（Web `accessiblePathFor`、iOS `Permissions.allows`） | 无 `allow_search` 弹回媒体库 | 与入口同口径 |
| 进入搜索时预选的分区 | 按页签预选（发现 / 订阅 → 影视，媒体库 → 媒体库，活动 → 资源） | 不变；预选的分区不可用时落到第一个可用分区（搜索页已有兜底，入口改完后才会走到） |
| 条目详情「搜索资源」 | `canManageLibraries` | `canSearch` |
| 订阅详情「手动选种」 | `canSubscribe ∧ canSearch`（投递接口 ⛔） | `canSubscribe ∧ canSearch ∧ canDirectDownload`（选种要先搜资源），投递接口对成员开放并校验订阅归属 |
| 资源结果「去站点设置」链接 | 对成员可见 | 对成员隐藏 |
| 设置页开关名 | 站点搜索 | 资源搜索（PT 站点） |

`canOpenSearch` 由 Web `useSearchAccess` / iOS `SearchAccess` 推导（搜索页内部已经在用这套
口径），入口和路由守卫改成复用它，不另写一套判断。

**影视分区为什么继续跟着订阅开关、而不是对所有人开放**：影视搜索的结果是 TMDB / 豆瓣的
全量数据，**不经过内容分级过滤**（外部搜索结果不带分级信息，逐条补查代价高）。跟着订阅
开关走，儿童账号（订阅关）就搜不到外部片库，只能搜媒体库里已经按分级过滤过的内容。
没有订阅权的成员搜到库外的片也做不了什么，库内的片走媒体库分区就能找到。

顺带记录一个现存的缺口（不在本期范围）：**发现页同样不做分级过滤**，儿童账号在发现页能
看到全部热门作品的海报与简介。是否对设了年龄上限的成员隐藏发现页，单独评估。

### 3.4 梳理过但否决或推迟的候选

| 候选 | 结论 | 理由 |
|---|---|---|
| 整理元数据（修正识别、换图、刷新） | 否决 | 管理能力不下放（§3.1，2026-10-01 拍板） |
| 转码开关（限制服务器转码） | 否决 | 三问第 3 问不过：关掉后部分片子直接放不了，界面不自洽 |
| 观看活动可见 | 否决 | 成员看全家在看什么是隐私问题，不是能力问题 |
| 订阅时选规则组 / 目标库 | 否决 | 规则组是超管的配置知识，成员一律自动结论（v1 §3.5 不变） |
| 影视搜索改为登录即有 | 否决 | 外部结果无法按分级过滤，见 §3.3 |
| AI 字幕生成 / 时间轴校准 | 推迟 | 消耗 LLM 额度；按 subtitle-ai-translate.md §6，随额度护栏（G2）一起评估 |
| AI 助手 | 推迟 | v1 §3.8 的三项前置条件（工具降级、令牌降权、工作区隔离）仍未满足 |
| 订阅数量 / 下载配额 | 推迟 | 尚无真实诉求；出现后作为 `member` 加列 |

### 3.5 权限预设

提供三档预设，**只是一键填表**，保存的仍是各个开关，之后可以逐项微调；不落库、不显示
「这个成员属于哪档」（避免「改了一个开关后算哪档」的歧义）。

| 预设 | 订阅追踪 | 资源搜索 | 一键下载 | 下载影片到设备 | 影片分享 | 内容分级 |
|---|---|---|---|---|---|---|
| 儿童 | 关 | 关 | 关 | 关 | 关 | 12 岁，未分级隐藏 |
| 家人（默认） | 开 | 关 | 关 | 开 | 关 | 不限 |
| 信任的成年人 | 开 | 开 | 开 | 开 | 开 | 不限 |

新建成员弹窗默认选中「家人」，与今天的默认值一致；存量成员迁移后行为零变化
（新列 `allow_video_download` 默认开 = 现状，`allow_share` 默认关 = 现状）。

### 3.6 合集归属（修 S2）

- `collection` 加 `created_by_member_id INTEGER NOT NULL DEFAULT 0`（0 = 超管；存量行
  归超管）。哨兵值语义与 `member_scoped.py` 一致，删成员时 household 合集转为超管所有，
  私有合集随人清理（现有逻辑）。
- 改名、改规则、改名单、删除：**超管或创建者**。其他成员对 household 合集只读。
- 内置 household 合集（如系列合集）的改名与隐藏：仅超管。
- 可见性 household ↔ private 的切换：仅创建者（超管可把任何合集改为 household，
  不能把成员的合集改为自己的私有）。

### 3.7 前端语义权限

`permissions.ts` / `Permissions.swift` 增加语义权限，页面只消费语义，不再拿相近字段凑合：

| 语义 | 推导 | 消费点 |
|---|---|---|
| `canOpenSearch` | 见 §3.3 | 搜索入口、`/search` 路由守卫 |
| `canGrabForSubscription` | `canSubscribe ∧ canSearch ∧ canDirectDownload` | 订阅详情「手动选种」 |
| `canShare` | 超管 ∨ `allow_share` | 影片 / 合集 / 片段的「分享…」 |

其余口径修正：

- **洗版**（U4）：成员分支不拉规则组列表；`upgrade-run-dialog`、`subscribe-dialog`
  （`upgradeIntent`）、`UpgradeRunSheet`、`SubscribeSheet` 四处同改。
- **在途下载**（U6）：新增成员可读的精简口径，范围限自己发起或关注的订阅。
- **一键下载弹窗**（U7）：成员分支不调用下载器配置接口，落点只有可见库与下载器默认目录，
  不读写保存位置记忆（记忆只给超管记）。
- **只关注不发起的成员**：订阅详情下发 `can_manage`（超管与发起人为真），两端据此隐藏
  立即搜索、调整、洗版、续订、暂停、手动选种，只关注的成员只剩取消关注。
- **超管链接**（U8、U9）：对成员隐藏；`/activity`、`/library/manage` 进 Web 路由守卫
  （iOS 已有）。
