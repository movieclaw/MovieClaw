# 插件依赖：安装时按授权下载第三方包——设计

> 状态：已实施（2026-10-17，PR 1～3 见 §8）。修订 [plugin-phase3.md](plugin-phase3.md) §2 / §9 决策 2「依赖只能随包携带纯 Python、
> 安装时不跑 pip」。源起：115 存储后端插件（[cloud-storage-115.md](cloud-storage-115.md)）要用带本机代码的加密库，
> 纯 Python 随包携带装不下。
> 关联：[plugin-phase3.md](plugin-phase3.md)（插件包、批准、进程外运行、路径授权）、
> 统一网络出口 `movieclaw_net`（代理、镜像）。

## 0. 结论

1. **用户决策（2026-10-17）：允许插件声明第三方依赖，安装时由主程序下载安装，但必须经管理员授权同意。**
   授权并入现有的「批准」步骤：批准页在权限之外列出要装的包，同意的是「这一份依赖清单」。
2. **只装预编译好的轮子，不在用户机器上编译、不跑任何安装脚本**；每个包钉死版本与哈希（打包时锁定），下载后逐个校验。
3. **只给进程外运行的插件**（`runtime = "process"`，插件包默认）。进程内运行的插件不能带外部依赖——会污染主程序的环境。
4. **不许覆盖主程序已有的包**：主程序自带的包（`httpx`、`cryptography`……）插件直接用，依赖清单里不能再出现同名包的
   另一个版本，打包与安装时都检查。
5. `vendor/` 随包携带照旧支持；两者可以同时用。

## 1. 清单与锁文件

```toml
[plugin]
id = "cloud-115"
runtime = "process"
# …

[dependencies]
lock = "requirements.lock"     # 包内路径；pip 的 requirements 格式，全部 == 钉死，每行带 --hash
```

- 锁文件由插件打包工具（`pack.py` / `check_plugin`）生成：按**主程序的约束清单**解析（主程序每个 SDK 版本发布一份
  `host-constraints.txt`，列出自带的包与版本），得到完整依赖闭包；与主程序重名的包不进锁文件，直接用主程序的。
- 锁文件里每个包记下：版本、所有可用平台的轮子哈希、大小、是否纯 Python。批准页的「多大、有没有本机代码」从这里读，
  不用先下载。
- 打包时检查：只接受有轮子的包（没有轮子只有源码包的直接拒绝，并说明「用户机器上不编译」）；至少覆盖
  `linux/x86_64` 与 `linux/aarch64` + 主程序当前的 Python 版本（缺哪个平台写进包的说明，安装到那个平台时给出原因）。

## 2. 授权

上传或从插件仓库安装时，批准页在「宿主操作、路径、网络」之后加一节：

> **需要下载并安装 6 个第三方包（共 4.2 MB，来自 PyPI 清华镜像）**
> p115cipher 0.0.6 · pycryptodome 3.23.0（含本机代码）· ecdsa 0.19.1 · lz4 4.4.4（含本机代码）· …
> 这些包在插件自己的进程里运行，权限与插件相同。

- 同意的是**这一份锁文件**（按内容哈希记在 `state.json` 的安装记录里）。升级时锁文件没变就不再问；变了就把新增、
  升级、移除的包列出来再问一次。
- 「含本机代码」单独标出：纯 Python 与本机代码在能力上没有区别（都在插件进程里、都能做插件能做的一切），但本机代码
  更难审查，管理员应当知道。
- 命令行、Agent 安装插件走同一个批准（危险操作，逐次确认），批准页的依赖信息同样输出；不能跳过。
- 随应用提供的官方插件（`src/movieclaw_plugins/`）的依赖仍写在主程序的 `pyproject.toml`，不走这里。

## 3. 安装

批准后、挂载前：

1. **目录**：`data/plugins/deps/<锁文件哈希>-<平台标签>/`。同一份锁文件的插件版本共用；只保留当前版与上一版引用的目录，
   其余清掉。下载的轮子缓存在 `data/plugins/deps/.cache/`（按哈希命名，重装、换平台标签时复用）。
2. **命令**：用主程序自己的解释器：`/venv/bin/python -m pip install --target <目录> --require-hashes --only-binary=:all:
   --no-deps --no-compile -r <锁文件>`（锁文件已是完整闭包，所以 `--no-deps`）；加 `-c host-constraints.txt` 再挡一次重名。
   在临时目录装完、校验后改名，失败不留半截目录。
3. **网络**：经主程序的统一出口（设置 → 网络里的代理）；包索引地址可在设置 → 网络里改，默认 PyPI，提供清华镜像一键切换
   （国内直连 PyPI 常不稳）。
4. **状态**：插件显示「正在安装依赖（3 / 6）」；失败时不挂载，写明原因（网络不通、哈希不对、没有适用于本机平台的轮子），
   给「重试」。安装不卡主程序启动，在后台进行。
5. **离线**：插件包可以把轮子直接放进包内 `wheels/`（受包体积上限约束），安装时优先从这里取（`--find-links`），不联网。

## 4. 加载

- 进程外运行器启动插件子进程时，把依赖目录**用 `sys.path` 追加**（不经 `site.addsitedir`），所以包里的 `.pth` 文件不会被执行——
  不让任何包在解释器启动时跑代码。
- 顺序：主程序源码 → 主程序的 site-packages → `vendor/` → 依赖目录。重名在打包和安装时已经挡住，顺序只是兜底：主程序的包永远优先。
- **主程序升级换了 Python 版本**（如 3.12 → 3.13）：启动时发现平台标签对不上，后台按原锁文件重装（授权已给过，不再问；
  只是重新下载）；装好之前插件处于「正在准备依赖」。

## 5. 安全边界（与第三阶段相同，不放宽）

- 依赖代码跑在插件子进程里，受第三阶段的隔离：主程序是 root 时子进程降权、只有授权的路径、拿不到数据库与别的插件的数据。
- 新增的风险是**供应链**（PyPI 上的包被投毒）：靠打包时锁定哈希挡住「之后被替换」；挡不住「锁定时就已经有毒」——这与
  `vendor/` 一样，靠插件仓库的审核与「同意前看得到装什么」。
- 不跑安装脚本（只装轮子）、不执行 `.pth`：安装与加载过程本身不执行包里的任何代码，代码只在插件导入时运行。

## 7. 对 115 插件的影响

115 插件可以直接依赖 `p115cipher[full]`（pycryptodome、ecdsa、lz4 都有两种平台的轮子），不用自己重写加密函数。
注意它实际是 GPLv3（PyPI 元数据写 MIT，轮子里的 LICENSE 是 GPLv3），115 插件因此以 GPL-3.0-or-later 发布，见
[cloud-storage-115.md](cloud-storage-115.md) §0。选依赖时看轮子里的 LICENSE，别只信 PyPI 元数据。
仍不整包依赖 p115client：它的依赖近 40 个，安装慢、出问题的面大，插件只需要它的加密部分。这一项不卡存储层内核的开工
（里程碑一的主程序 PR 用测试内的假后端），但在 115 插件动工前要先合并本文的 PR 1～3。

与 §3 的差别（实现时定）：

- **锁文件格式**：每个包上方用 `#>` 注释行记下它的每个轮子（文件名、字节数、sha256）——批准页的大小、「含本机代码」、
  是否有本机平台的轮子都从这里读；pip 把它们当注释跳过。
- **下载由主程序自己做，pip 只离线安装**：按 `#>` 行挑出本机要用的轮子，依次取插件包 `wheels/` → `.cache/<sha256>/` →
  经统一出口（服务 `pypi`，跟随设置 → 网络的代理开关）从包索引下载并核对哈希，再
  `pip install --target … --require-hashes --only-binary=:all: --no-deps --no-compile --no-index --find-links … -c host-constraints.txt -r <锁文件>`。
  这样代理（含 socks5、按服务开关）与主程序其余出网一致，失败原因能分清「网络不通 / 哈希不对 / 没有本机平台的轮子」，
  进度按包计数，缓存按哈希复用。
- **批准时装依赖、装好再换版本**：依赖从待批准目录装；失败时不动已安装的版本（旧版本照常运行），待批准的包留着，
  重新批准即重试。启动时依赖没就绪的（换了 Python 版本、目录被删）不挂载，后台补装后挂载；补装失败在插件页显示原因与
  「重试安装依赖」（`app.plugins.packages.retry-dependencies`）。
- 依赖目录名 `<锁文件哈希前 16 位>-<解释器标签>-<平台标签>`（如 `…-cp312-manylinux_2_36_x86_64`）；隔离运行时复制到
  `/tmp/movieclaw-plugins/deps/` 供非特权用户读取。
