# Feature Specification: HarmonyOS TV 端（智慧屏）Apple TV 风格 UI

**Created**: 2026-10-27  
**Status**: Draft  
**Input**: 用户需求：为 MovieClaw HarmonyOS 应用配置 TV（华为智慧屏/Mate TV）端，界面照 Apple TV 版 MovieClawTV（`apps/apple/MovieClawTV`）的风格实现，全部使用华为官方组件渲染、不自绘；官方无对应组件处需列出清单交用户抉择。平板适配本期不做。

## Overview

为 MovieClaw HarmonyOS 应用新增智慧屏（Mate TV）端体验。TV 端 UI 层照 Apple TV 版参考项目的视觉与信息架构全新实现（深色、海报墙、焦点驱动大图区、横滑内容行、两截式详情页、客厅播放器），全部使用 HarmonyOS 官方 ArkUI 组件与官方 Kit 能力渲染。交互同时支持华为灵犀指向遥控（指针悬浮 + 点击 + 滑动手势）与传统方向键焦点导航两套模型。播放走官方 AVPlayer + 服务端 HLS 转码路线，不使用 mpv。复用现有 API 层与同一个 MovieClaw 服务器，TV 端不新增后端接口。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 欢迎与登录：找到服务器并进入 TV 端 (Priority: P1)

用户首次在智慧屏上打开 MovieClaw：应用自动在局域网内寻找 MovieClaw 服务器，找到后展示候选列表；也支持手动输入服务器地址。连上服务器后登录（账号密码，或显示配对码/二维码由手机端批准）。已登录过的用户启动时直接进入上次账号，不重复询问。

**Why this priority**: TV 端无法连接服务器则一切功能不可用，这是所有其他故事的前置条件。

**Independent Test**: 在智慧屏（或模拟器）上首次启动应用，走完「发现/输入地址 → 登录 → 进入主界面」全流程；再次启动直接进入主界面。

**Acceptance Scenarios**:

1. **Given** 局域网内存在已初始化的 MovieClaw 服务器, **When** 用户首次打开应用, **Then** 应用在数秒内列出候选服务器，用户选中并登录后进入主界面
2. **Given** 自动发现失败或用户想连远程服务器, **When** 用户手动输入地址（含端口）, **Then** 应用验证服务器有效性（健康检查）后进入登录
3. **Given** 用户已在 TV 端登录过, **When** 再次启动应用, **Then** 不再询问服务器与账号，直接进入上次账号的主界面
4. **Given** 服务器未初始化或不可达, **When** 应用尝试连接, **Then** 显示对应状态页（引导去网页/手机端完成初始化；连接失败可重试），不白屏不闪退

---

### User Story 2 - 首页：打开就能接着看 (Priority: P1)

用户进入 TV 端首页：上方是跟随选择焦点变化的大图区（焦点所在条目的剧照铺满屏幕，展示标题、集数进度、简介与操作按钮），下方是若干横滑内容行（按用户在网页端自定义的首页行偏好展示：继续观看、收藏、我的媒体库入口、各合集/类型行等）。每行末尾有「查看全部」入口进入完整墙。焦点稳定停留约 0.16 秒后大图切换（划过不逐张闪图）。

**Why this priority**: 「打开就能接着看」是客厅场景的核心价值，用户开机第一屏。

**Independent Test**: 登录后停在首页，用遥控器在内容行间移动，观察大图区随焦点交叉淡入切换；点按任意卡片进入对应详情。

**Acceptance Scenarios**:

1. **Given** 用户有续播记录, **When** 进入首页, **Then** 大图区默认聚焦「继续观看」行的最近条目，按下确认键可直接续播
2. **Given** 焦点在某行卡片间左右移动, **When** 停留超过约 0.16 秒, **Then** 大图区切换为该条目的剧照并交叉淡入，一路划过不逐张闪图
3. **Given** 用户在网页端配置过首页行, **When** TV 端加载首页, **Then** 按该偏好渲染内容行；未配置时使用默认行集
4. **Given** 某行内容超过一屏, **When** 焦点移到行末, **Then** 行内出现「查看全部」尾卡，进入后可浏览该行完整内容墙

---

### User Story 3 - 详情页：了解并播放一部作品 (Priority: P1)

用户从首页或媒体库选中一个条目进入详情页：首屏是该条目原图铺满的大图区，含 Logo/标题、事实行（年份·类型·片长/季数、画质/HDR/音频标签）、简介、操作按钮（继续播放/从头播放、收藏、标为已看）；剧集类首屏底部露出分集卡上沿提示下方有内容。下滑进入下半截：剧集类有选季胶囊、分段页签与分集卡横排（剧照+进度+集名+简介+首播日期），以及演职员行、相似推荐、作品系列、所属合集；电影类为演职员、相似推荐、作品系列、所属合集。

**Why this priority**: 详情页是「决定看什么」的决策页，也是收藏/已看等写操作的落点。

**Independent Test**: 从首页进入任一剧集与任一电影详情，浏览全部区块，执行「继续播放」「收藏切换」「标为已看」并返回确认状态已更新。

**Acceptance Scenarios**:

1. **Given** 用户看过某剧一部分集, **When** 进入该剧详情页, **Then** 主按钮显示「继续 第 X 季第 Y 集 · mm:ss」，按下从此处续播
2. **Given** 剧集有多个季, **When** 焦点在选季胶囊间移动, **Then** 下方分集区跟随切换对应季的分集列表
3. **Given** 用户在详情页点收藏/标为已看, **When** 操作完成, **Then** 按钮状态即时更新，且返回首页/墙后状态一致
4. **Given** 条目无可用片源, **When** 进入详情页, **Then** 播放相关按钮置灰或隐藏，但页面仍可浏览信息、可收藏

---

### User Story 4 - 播放器：客厅观影 (Priority: P1)

用户在详情页或首页按下播放后进入全屏播放：画面由官方 AVPlayer 渲染服务端 HLS 流。底部传输条（标题、缓冲/已播双层进度、当前/剩余时间）可呼出；信息面板提供字幕/音轨/画质三列选择；支持跳过片头按钮、下一集卡片（含倒计时与观看片尾选项）、连播数达上限时的「还在看吗」确认；播放错误时给出重试/返回选项。

**Why this priority**: 播放是媒体应用的最终目的，其余一切故事都为它服务。

**Independent Test**: 播放任一影片，验证起播、暂停/继续、进度条拖动、切换字幕/音轨/画质、退出并再次进入验证续播点正确。

**Acceptance Scenarios**:

1. **Given** 用户按下播放, **When** 播放会话建立, **Then** AVPlayer 起播服务端 HLS 流，数秒内出画
2. **Given** 播放中, **When** 用户呼出信息面板切换字幕/音轨/画质, **Then** 切换即时生效，画质切换走服务端 HLS 重建流
3. **Given** 条目存在片头片段标记, **When** 播放到片头区间, **Then** 右下角出现「跳过片头」按钮，按下即跳至片头结束点
4. **Given** 剧集连播达到上限, **When** 当前集播完前, **Then** 弹出「还在看《…》吗」确认，确认后继续连播、取消则停止
5. **Given** 播放中发生起播/中断错误, **When** 错误发生, **Then** 显示含重试与返回选项的错误提示，不闪退
6. **Given** 用户中途退出, **When** 再次进入该条目, **Then** 播放/详情均从上次进度继续

---

### User Story 5 - 媒体库海报墙：浏览全部收藏 (Priority: P2)

用户从首页「我的媒体库」行或「查看全部」进入媒体库海报墙：5 列海报、海报下不挂字，选中（悬浮/聚焦）的海报底部浮出「片名 · 年份」暗带，背景为当前选中条目剧照的放大模糊版本并随选中交叉淡入；标题行含大标题、总数与「排序与筛选」（排序：加入时间/发行日期/评分/标题；只看没看过的；类型/年代/画质等筛选，每项显示命中数量）；大库提供 A–Z/年份/评分档索引条与窗口式分页，快速滚动时屏幕中央浮出当前定位（如「2015 · 第 n 部/共 N 部」）。

**Why this priority**: 海报墙是「逛收藏」的主要路径，仅次于首页直达。

**Independent Test**: 进入任一媒体库，用遥控器滚动浏览、更改排序与筛选、使用索引条跳转，确认海报墙与浮出信息随选中变化。

**Acceptance Scenarios**:

1. **Given** 媒体库含大量条目, **When** 用户滚动海报墙, **Then** 分页加载无尽头列表，滚动流畅
2. **Given** 用户打开排序与筛选, **When** 选择排序或勾选筛选, **Then** 海报墙按条件刷新，筛选条件与「只看没看过的」在本地记忆
3. **Given** 大型媒体库, **When** 用户使用索引条按年份/首字母跳转, **Then** 墙定位到对应区段，快速滚动时中央浮出定位信息
4. **Given** 选中某张海报, **When** 焦点/指针停留, **Then** 底部浮出「片名 · 年份」暗带，背景模糊图切换为该条目剧照

---

### User Story 6 - 搜索：找到特定作品 (Priority: P2)

用户进入搜索页：通过 TV 系统输入法（遥控器输入）或已连接键盘输入关键词，只搜索媒体库内内容；结果由「人物」行（头像卡，标注库内作品数）与条目卡片行组成，支持分页追加；点人物卡进入影人页（与详情页演职员同入口）。

**Why this priority**: 精确查找是浏览之外的补充路径。

**Independent Test**: 在搜索页输入已知影片名与影人名，验证结果出现且点击可进入对应详情/影人页。

**Acceptance Scenarios**:

1. **Given** 用户进入搜索页, **When** 输入关键词, **Then** 媒体库搜索结果分页展示（人物行 + 条目行）
2. **Given** 搜索无结果, **When** 输入完成, **Then** 显示无结果占位提示，可继续修改关键词
3. **Given** 结果中含影人, **When** 点按影人卡, **Then** 进入影人页展示其作品

---

### User Story 7 - 谁在看：多账号切换 (Priority: P2)

用户从侧边栏进入「谁在看」页：深色星空背景、大标题「谁在看？」、大头像横排（当前账号默认高亮，其余压暗），支持「＋ 添加账号」与「退出登录」（含确认）；底部一行「关于」入口。

**Why this priority**: 家庭多成员各有续播进度与收藏，切换账号是家庭场景的必需能力。

**Independent Test**: 添加第二个账号、切换账号、退出登录，验证各账号的首页/续播数据相互独立。

**Acceptance Scenarios**:

1. **Given** 存在多个已保存账号, **When** 进入谁在看页, **Then** 头像横排展示，选中某账号确认后整棵界面按该账号数据重建
2. **Given** 用户选择退出登录, **When** 确认退出, **Then** 清除当前令牌回到登录流程，其他账号不受影响
3. **Given** 用户点击「关于」, **When** 关于页打开, **Then** 展示应用版本与开源许可信息

---

### User Story 8 - 全局导航与两套遥控交互 (Priority: P1)

TV 端主界面为三页签结构（账号 → 搜索 → 首页），左侧为可收起的胶囊侧边栏：平时仅左上角一枚「‹ 当前页」胶囊，按左键/返回键展开，侧边栏内上下移动不切页、确认才切换；二级页（详情、墙、影人页）盖在整屏之上。所有可交互元素同时支持：① 灵犀指向遥控——指针悬浮高亮（放大 + 亮边）、OK/点击生效、触摸板滑动滚动；② 方向键焦点导航——方向键移动焦点、确认键生效、返回键逐级返回。控件无焦点落空、无「按了没反应」的死角。

**Why this priority**: 交互模型是 TV 端可用性的地基，贯穿所有页面；侧边栏三页签是全局信息架构。

**Independent Test**: 分别用「指针悬浮点击」与「方向键焦点」两种方式完成：展开侧边栏 → 切换三个页签 → 进入详情 → 返回首页，全程无操作死角。

**Acceptance Scenarios**:

1. **Given** 主界面任意页签, **When** 用户按左键到底或按返回键, **Then** 侧边栏以胶囊形式展开，确认后切换页签
2. **Given** 灵犀遥控指针悬浮于卡片, **When** 悬停, **Then** 卡片放大并出现亮边（悬浮态），OK 键触发与点击一致
3. **Given** 使用方向键导航, **When** 焦点移动到任何可交互元素, **Then** 焦点态清晰可见，确认键行为与点击一致
4. **Given** 用户在二级页按返回键, **When** 逐次按返回, **Then** 逐级返回（二级页 → 首页 → 侧边栏 → 退出确认），一次只收一层

---

### User Story 9 - 首页高级体验：Ken Burns 慢推与大图预告 (Priority: P3)

首页大图区在无操作时对当前剧照做极缓慢的推近（约 40 秒、1.06 倍级）；焦点在大图区对应条目停留满约 2 秒后，原地播放该条目的预告片段（续播点前约 30 秒，声音渐入），滚走即停，进入详情/播放前先行拆除。

**Why this priority**: 氛围增强项，核心链路之外的体验加分，优先级最低但属本期全量范围。

**Independent Test**: 在首页停留观察慢推动画持续进行；焦点停在续播条目 2 秒后画面原地切换为预告片段且有声，移开焦点立即停止并回到剧照。

**Acceptance Scenarios**:

1. **Given** 首页大图区显示某剧照, **When** 无人操作, **Then** 剧照缓慢推近，无跳变
2. **Given** 焦点停在「继续观看」某条目满约 2 秒, **When** 停留达成, **Then** 大图区原地播放预告片段、声音短促渐入；焦点移开后立即停止

---

### User Story 10 - 播放器拖动缩略图（trickplay）与快进快退 (Priority: P3)

播放器进度条拖动时浮出目标时间点附近的 trickplay 缩略图与目标时间；支持按住快进键连续倍速快进（20×→40×→80×→160× 级）松手跳落点（方向键交互），以及触摸板滑动式拖动进度（指针交互，满屏一划约为片长 1/5，限制在 1~15 分钟）。

**Why this priority**: 长片的精确回看/跳看体验，属播放器增强。

**Independent Test**: 播放一部影片，拖动进度条验证缩略图与时间浮出并落点正确；按住快进键验证倍速递进与松手定位。

**Acceptance Scenarios**:

1. **Given** 播放中, **When** 拖动传输条, **Then** 浮出目标时间及该位置 trickplay 缩略图，松手跳至目标点
2. **Given** 方向键交互模式, **When** 按住快进/快退, **Then** 倍速按 20×→40×→80×→160× 递进，松手跳至落点继续播放

---

### Edge Cases

- 服务器地址失效/令牌过期：进入对应「不可达/需登录」状态页，可重试或重新登录，不闪退、不白屏
- 首页行偏好为空或接口失败：使用默认行集或显示重试占位，其余行不受影响
- 空媒体库/空搜索结果/空合集：显示空态占位文案
- 剧集无分集数据、影人无头像、图片缺失：用占位图与占位文案兜底，布局不塌
- 网络断开/超时：各页面显示可重试的错误态；播放中断给出重试/返回
- 深浅色：智慧屏系统强制深色，TV 界面固定按深色设计（避免白底白字）
- 低性能/大库滚动：海报墙窗口式分页 + 图片按需加载，避免一次性加载上万条目

## Requirements *(mandatory)*

### Functional Requirements

**连接与账号**

- **FR-001**: TV 端 MUST 支持局域网自动发现 MovieClaw 服务器（与参考实现一致的发现协议），并支持手动输入服务器地址（自动补全协议与常见端口）。
- **FR-002**: TV 端 MUST 支持账号密码登录与设备配对登录（TV 屏幕展示配对码/二维码，手机端批准），并安全保存多账号令牌实现免密切换。
- **FR-003**: 已登录用户启动时 MUST 直接进入上次账号主界面；服务器不可达时显示可重试的状态页。
- **FR-004**: TV 端 MUST 复用现有 API 层与同一 MovieClaw 服务器，不新增/修改后端接口。

**首页**

- **FR-005**: 首页 MUST 按「焦点/选中驱动大图区 + 横滑内容行」的结构渲染；大图区不得自动轮播，切换由选中变化触发并带交叉淡入；选中停留约 0.16 秒内不切图。
- **FR-006**: 内容行 MUST 按用户网页端配置的首页行偏好渲染（继续观看、收藏、我的媒体库入口、合集/类型行等），行尾提供「查看全部」入口。
- **FR-007**: 首页大图区 MUST 支持无操作时的缓慢推近动画，以及选中满约 2 秒的原地预告片段播放（含声音渐入、移开即停）。

**媒体库与详情**

- **FR-008**: 媒体库墙 MUST 按 5 列海报布局渲染，海报下不固定挂字；选中项在底部浮出「片名 · 年份」暗带，背景随选中切换为模糊剧照。
- **FR-009**: 媒体库墙 MUST 提供排序（加入时间/发行日期/评分/标题）与「只看没看过的」筛选，且在本地记忆；大库 MUST 提供索引条（首字母/年份/评分档）与窗口式分页。
- **FR-010**: 详情页 MUST 呈现两截结构：首屏原图大图区 + 操作按钮（继续/从头播放、收藏、标为已看），下滑为剧集分集区（选季/分段/分集卡）、演职员、相似推荐、作品系列、所属合集。
- **FR-011**: TV 端 MUST 支持写操作仅限：收藏切换、标为已看/未看；其余管理操作（改名、转移、删除、订阅等）一律不在 TV 端提供。

**播放**

- **FR-012**: TV 端播放 MUST 使用官方 AVPlayer 播放服务端 HLS 流，不使用 mpv；画质/音轨/字幕切换由信息面板完成并即时生效。
- **FR-013**: 播放器 MUST 提供传输条（缓冲/已播双层进度、当前/剩余时间）、信息面板（字幕/音轨/画质三列）、跳过片头、下一集卡（倒计时+观看片尾）、连播上限「还在看吗」确认、播放错误（重试/返回）。
- **FR-014**: 播放器 MUST 支持进度拖动时浮出 trickplay 缩略图与目标时间；方向键交互下支持按住连发倍速快进快退（20×~160× 递进）。
- **FR-015**: 播放进度与会话 MUST 与服务器同步（续播点、进度上报），详情页与首页的续播信息在播放结束后即时刷新。

**搜索与导航**

- **FR-016**: 搜索 MUST 仅检索媒体库内容，结果含人物行（含库内作品数）与条目行，支持分页追加；搜索输入走 TV 系统输入法。
- **FR-017**: 全局导航 MUST 为「账号 → 搜索 → 首页」三页签 + 可收起胶囊侧边栏；二级页整屏覆盖；返回键逐级返回。
- **FR-018**: 所有可交互元素 MUST 同时适配两套交互：灵犀指向遥控（悬浮态高亮 + OK/点击 + 触摸板滑动）与方向键焦点导航（焦点态 + 确认键 + 返回键），两套路径均可完成全部核心操作。

**工程与渲染约束**

- **FR-019**: TV 端全部 UI MUST 使用 HarmonyOS 官方 ArkUI 组件与官方 Kit 能力渲染，禁止 Canvas/自绘组件实现视觉元素；官方无内建对应能力的，用官方组件与官方动画/事件能力组合实现并记录于组件映射清单。
- **FR-020**: 工程 MUST 保持手机端现有功能与 UI 完全不受影响；TV UI 与手机 UI 在工程内隔离（设备分流），一套工程构建。
- **FR-021**: TV 端 UI MUST 固定深色主题，适配 1280×720 vp 画布（3840×2160 px @3x）与横向 lg 断点，避免白底白字。
- **FR-022**: 官方组件覆盖清单中列出的「无内建对应组件」项 MUST 在进入实现前提交用户确认取舍。

### Key Entities *(include if feature involves data)*

- **服务器（Server）**: 基址、健康状态、初始化状态；局域网发现候选
- **账号（Account/令牌）**: 服务器 + 用户名唯一标识；多账号本地保存与免密切换
- **首页行偏好（Home Rows）**: 用户自定义行集合与顺序（读取自服务器偏好）
- **媒体库（Library）**: 库 id、类型、条目数；作为首页入口与海报墙数据源
- **条目（Item）**: 影片/剧集；标题、年份、海报/剧照、简介、集数结构、播放进度、收藏/已看标记、画质/HDR/音频标签
- **合集/系列（Collection/Series）**: 条目分组；「作品系列」展示已有 n/共 m
- **影人（Person）**: 头像、姓名、库内作品数
- **播放会话（Playback Session）**: 起播决策（HLS 档位）、进度上报、ping 保活、续播点
- **字幕/音轨/画质（Tracks/Quality）**: 可选轨道与转码档位；画质建议
- **trickplay 缩略图**: 按时间轴的预览图集，用于拖动定位
- **排序与筛选状态**: 用户对每个媒体库的本地记忆（排序、只看没看过）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户使用遥控器（指针或方向键任一路径）可独立完成「启动 → 登录 → 首页选片 → 详情 → 播放 → 暂停/退出」全流程，无任何一步出现操作死角或按键无响应。
- **SC-002**: 全部 TV 页面在 1280×720 vp 画布下无内容截断、无重叠错位、无白底白字；空态/错误态均有占位反馈。
- **SC-003**: 两套交互（悬浮点击 / 方向键焦点）各自通过全部核心操作的用户验收用例（用例集覆盖 10 个用户故事）。
- **SC-004**: 冷启动到首页可操作 ≤ 5 秒（服务器正常网络下）；首页大图区切换、海报墙滚动无明显卡顿（模拟器/预览器目测流畅）。
- **SC-005**: 播放链路（起播、轨道切换、拖动定位、续播）在服务端 HLS 正常输出时全部用例通过；错误场景（断网、无效令牌、转码失败）均有对应错误态而非闪退。
- **SC-006**: 手机端现有页面与功能回归零变化（构建产物中 TV 代码不进入手机 UI 路径）。
- **SC-007**: 官方组件映射清单 100% 覆盖 TV 端用到的视觉与交互元素；无自绘组件（Canvas 绘制）进入 TV UI。

## Assumptions

- 服务端已具备 Apple TV / Android TV 端在用的全部能力（首页行偏好、HLS 转码、trickplay、预告片段、跳过片头、连播上限、配对登录协议），TV 端不新增后端接口。
- 平板（tablet）适配不在本期范围，本期仅交付 TV 端；`deviceTypes` 维持现有 phone/tablet/2in1 并新增 tv。
- 无智慧屏真机：验收以「构建通过 + 模拟器/预览器截图对照」为准；真机（WiFi 5555 无线调试）验证列为交付后的后续事项。TV 屏幕键盘（系统输入法在智慧屏上的表现）为真机验证项。
- TV 端不使用 mpv（AVPlayer + HLS 路线），因此 TV 端无 mpv/LGPL 许可披露需求；「关于」页许可清单按 TV 实际引入展示。
- TV 端固定深色主题（智慧屏系统强制深色），不做浅色适配。
- 首页行偏好等读取逻辑与手机端现有 `LibraryHomeStore` 同源，行为一致。
- 手机端现有 104 个组件文件保持原样；TV UI 为新增代码目录，不修改手机 UI（除非构建配置必需的接线改动，如入口分流）。

## Open Questions

- **OQ-1（工程分流形态）**: TV UI 与手机 UI 的工程隔离采用「同一 entry 模块内按设备类型运行时分流」还是「官方推荐的独立 HAP/产品定制层」——属 Phase 2 架构决策，两种形态均满足 FR-020。
- **OQ-2（焦点/悬浮放大视觉的官方组合实现）**: ArkUI 无内建「TV 卡片聚焦放大 + 抬升 + 亮边」组件样式，拟用官方事件（onFocus/onHover）+ 官方动画能力组合实现（非自绘）。按用户规则记入组件缺口清单，实现前请用户确认取舍。
- **OQ-3（无真机风险项）**: 智慧屏系统输入法（搜索打字）、灵犀遥控滑动事件的真实表现、List 默认渐隐等差异点，在无真机条件下只能按官方文档实现并在模拟器验证，真机表现存在不确定性，需用户知悉。
