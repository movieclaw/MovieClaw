# Feature Specification: HarmonyOS 车机端（Car）适配

**Created**: 2026-10-27  
**Status**: Draft  
**Input**: 用户需求：为 MovieClaw HarmonyOS 应用创建车机端（`car/` 目录，与 TV 端类似但按车机惯例适配），按照业界车机软件的通行做法逐页分析拆解现有页面后裁剪改造；先实现，最后用模拟器（Huawei_Car）检查 UI；UI 全部用华为官方组件渲染。

## Overview

为 MovieClaw HarmonyOS 应用新增车机端体验：新增 `entry/src/main/ets/car/` 产品定制层（与 TV 端 `tv/` 平行），`module.json5` 增加 `car` 设备类型，`EntryAbility` 按设备类型分流到车机根页面。车机端按业界车机媒体软件通行做法（鸿蒙座舱 / Tesla / Android Automotive / CarPlay 媒体类应用惯例）对现有页面逐页裁剪改造：扫码登录、大卡首页、触屏海报墙、简化详情、行车锁视频的播放器、常驻 mini 播控条、语音优先搜索、轻量账号；发现/订阅、离线下载、Agent 聊天、通知、设置/分享一律不做（留给手机端）。全部 UI 使用 HarmonyOS 官方 ArkUI 组件渲染，固定深色主题，宽屏横屏响应式布局，大触控目标（≥48vp）、层级 ≤3 级、3 秒注视原则。复用现有 API 层与 MovieClaw 服务器，不新增后端接口。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 车机登录：扫码即用 (Priority: P1)

车主首次在车机上打开 MovieClaw：车机屏幕显示配对二维码与配对码，用手机扫码后在手机端批准，车机自动完成登录进入主界面；也支持手动输入服务器地址兜底（简化键盘）。已登录过的车机启动时直接进入上次账号主界面，不重复询问。

**Why this priority**: 车机无法登录则一切功能不可用；扫码是车机登录的行业标配（免打字）。

**Independent Test**: 清数据后启动（Huawei_Car 模拟器），走完「扫码/手动地址 → 登录 → 进入主界面」；再次启动直达主界面。

**Acceptance Scenarios**:

1. **Given** 车机未登录, **When** 打开应用, **Then** 屏幕展示配对二维码与配对码（ScanKit 官方生成），手机扫码批准后车机自动进入主界面
2. **Given** 扫码不可用或连接远程服务器, **When** 用户选择手动输入, **Then** 简化键盘可输入服务器地址（自动补全协议/端口），验证通过后进入登录
3. **Given** 车机已登录, **When** 再次启动, **Then** 直接进入上次账号主界面
4. **Given** 服务器不可达, **When** 启动, **Then** 显示可重试的状态页，不白屏不闪退

---

### User Story 2 - 车机首页：3 秒内继续观看 (Priority: P1)

用户进入车机首页：继续观看/收藏以大卡片置顶（宽屏左信息右内容布局），点一下即可续播；下方是少量精选内容行（横滑）。页面遵循车机通则：大触控目标、3 秒注视原则、高对比、无高频闪烁动画。

**Why this priority**: 「上车 3 秒内点一下就能接着看/听」是车机媒体应用的核心价值。

**Independent Test**: 登录后停在首页，点继续观看大卡直接进入播放；浏览下方内容行进入详情。

**Acceptance Scenarios**:

1. **Given** 用户有续播记录, **When** 进入首页, **Then** 继续观看大卡置顶显示（剧名/集数/进度），点击直接续播
2. **Given** 用户有收藏, **When** 进入首页, **Then** 收藏以可横滑的大卡行展示，点击进详情
3. **Given** 首页任意卡片, **When** 用户点按, **Then** 触控目标 ≥48vp，点击响应无歧义
4. **Given** 无任何观看记录, **When** 进入首页, **Then** 显示引导态（去媒体库浏览）

---

### User Story 3 - 媒体库海报墙：大目标触屏浏览 (Priority: P1)

用户进入媒体库海报墙：大触控目标海报网格（触屏直点，无遥控焦点/悬浮模型），选中海报浮出「片名·年份」，背景随选中模糊切换；排序与筛选以大按钮抽屉提供；大库分页加载。

**Why this priority**: 海报墙是车机「逛收藏」的主路径，触屏直点是车机与 TV 的核心差异。

**Independent Test**: 进入任一媒体库，滚动浏览、更改排序筛选、点海报进详情。

**Acceptance Scenarios**:

1. **Given** 媒体库含大量条目, **When** 用户滚动海报墙, **Then** 分页加载流畅，触控目标足够大（行车场景下也可盲点）
2. **Given** 用户打开排序与筛选, **When** 选择条件, **Then** 海报墙按条件刷新，条件本地记忆
3. **Given** 点选某张海报, **When** 进入, **Then** 跳转对应详情页

---

### User Story 4 - 车机详情页：一眼决策 (Priority: P1)

用户从首页或海报墙进入详情页：首屏大图区 + 操作按钮行（继续/从头播放、收藏、标为已看），宽屏布局；下半截简化为分集列表（剧集类）、演职员、相似推荐；系列/合集等重信息结构简化或省略。

**Why this priority**: 详情页是「看什么」的决策页，车机上要一眼可读、一下可点。

**Independent Test**: 进入剧集与电影详情，验证按钮行操作（收藏/已看点按即时反馈）、分集切换、相似推荐跳转。

**Acceptance Scenarios**:

1. **Given** 用户看过某剧一部分集, **When** 进入详情页, **Then** 主按钮显示「继续 第 X 季第 Y 集」，点击从此处续播
2. **Given** 剧集有多个季, **When** 用户切换季, **Then** 分集列表跟随切换
3. **Given** 用户点收藏/标为已看, **When** 操作完成, **Then** 按钮状态即时更新，返回后状态一致
4. **Given** 条目无片源, **When** 进入详情页, **Then** 播放按钮置灰，页面可浏览可收藏

---

### User Story 5 - 车机播放器：驻车看视频，行车听声音 (Priority: P1)

用户在车机上播放内容：**驻车状态**下全屏视频播放（AVPlayer + 服务端 HLS，传输条/信息面板/跳片头/下一集与 TV 端同等能力）；**行车状态**下视频画面锁定，音频继续播放，界面切换为大控件播控卡（大播放/暂停/上下集/收藏按钮 + 进度条），并提示「行车中视频已锁定」。行车信号不可得时提供手动「驾驶模式」开关兜底（模拟器上以手动开关验证）。

**Why this priority**: 行车安全是车机应用的第一约束（行业惯例与合规要求），播放是核心功能。

**Independent Test**: 播放任一内容验证起播/暂停/进度/退出续播；切换手动驾驶模式开关验证视频锁定与音频继续。

**Acceptance Scenarios**:

1. **Given** 驻车状态, **When** 用户起播, **Then** 全屏视频正常播放，传输条与信息面板可用
2. **Given** 行车状态（或手动驾驶模式开启）, **When** 正在播放视频, **Then** 视频画面立即锁定转音频，界面切为大控件播控卡并显示锁定提示
3. **Given** 行车中音频播放, **When** 用户点下一集/上一集/暂停, **Then** 大控件即时响应
4. **Given** 行车转驻车, **When** 状态切换, **Then** 可手动恢复视频画面
5. **Given** 播放中退出或错误, **When** 再次进入, **Then** 从上次进度续播；错误显示重试/返回选项，不闪退

---

### User Story 6 - 常驻 mini 播控条：任何页面一键回播 (Priority: P1)

车机端所有非播放器页面底部常驻 mini 播控条：封面、标题、播放/暂停、下一集，点击条体回到播放器（行车中回播控卡）。播控条在无播放时隐藏。

**Why this priority**: 车机媒体应用标配——跨页面不间断控制，减少页面往返（层级 ≤3 级通则的配套）。

**Independent Test**: 开始播放后返回首页/海报墙，mini 条常驻可控制；点击回播放器；停止播放后 mini 条消失。

**Acceptance Scenarios**:

1. **Given** 正在播放, **When** 用户处于任意非播放器页面, **Then** 底部 mini 播控条显示封面/标题/播放暂停/下一集
2. **Given** mini 播控条可见, **When** 点击条体, **Then** 返回播放器（行车中为大控件播控卡）
3. **Given** 播放停止, **When** 播放器关闭, **Then** mini 条隐藏

---

### User Story 7 - 车机搜索：语音优先 (Priority: P2)

用户进入搜索页：输入以语音为主（系统语音能力可达时）、简化键盘为辅；只搜媒体库；结果为条目与影人的大卡列表。

**Why this priority**: 车机打字体验差，语音是主输入；精确查找是浏览的补充。

**Independent Test**: 用键盘输入已知影片名出结果并进入详情（模拟器上语音能力以系统输入法可达性为准）。

**Acceptance Scenarios**:

1. **Given** 用户进入搜索页, **When** 输入关键词, **Then** 媒体库结果以大卡列表展示并分页追加
2. **Given** 搜索无结果, **When** 输入完成, **Then** 显示无结果占位，可继续修改

---

### User Story 8 - 车机账号：轻量切换 (Priority: P2)

用户可查看当前账号（头像/昵称）、切换已保存账号、退出登录（确认弹窗）；「关于」折叠入口显示版本与许可。不做 TV 端「谁在看」的大型头像墙，仅做轻量账号面板。

**Why this priority**: 车机以主驾单用户为主，账号能力够用即可。

**Independent Test**: 切换第二个账号验证数据隔离；退出登录回登录流程。

**Acceptance Scenarios**:

1. **Given** 存在多个已保存账号, **When** 用户切换账号, **Then** 界面按新账号数据重建
2. **Given** 用户退出登录, **When** 确认, **Then** 清除当前令牌回到登录页，其他账号不受影响

---

### User Story 9 - 车机系统集成播控 (Priority: P3)

播放状态接入 AVSession（官方 AVSession Kit）：车机系统媒体控制（系统播控卡片/方向盘媒体按键等系统级播控入口）可控制应用播放（播放/暂停/上一集/下一集），元数据（标题/封面/进度）正确上报。

**Why this priority**: 系统级联动是车机体验加分项，依赖真车环境验证，优先级最低。

**Independent Test**: 播放中在系统播控入口（模拟器可达范围内）验证播放/暂停联动与元数据显示。

**Acceptance Scenarios**:

1. **Given** 应用正在播放, **When** 系统播控发起播放/暂停/上下集指令, **Then** 应用播放状态同步响应
2. **Given** 播放状态变化, **When** 元数据更新, **Then** 系统播控显示正确标题/封面/进度

---

### Edge Cases

- 服务器不可达/令牌过期：可重试状态页，不闪退
- 首页无记录、空库、空搜索、图片缺失：占位图与占位文案兜底
- 行车/驻车状态切换瞬间：播放不中断（视频→音频平滑过渡），播控卡与视频界面切换无黑屏
- mini 播控条与页面滚动：条体固定底部不遮挡最后一行内容（列表留底部安全边距）
- 断网/转码失败：错误态（重试/返回），播放中断音频也给出反馈
- 深色固定主题下高对比校验：文字与背景对比度满足可读性
- Huawei_Car 模拟器（HarmonyOS 7.0.0 Beta1）与工程目标 SDK 6.1.1(24) 的前向兼容问题：以模拟器实测为准，出现不兼容时降级处理并记录

## Requirements *(mandatory)*

### Functional Requirements

**连接与账号**

- **FR-001**: 车机端 MUST 支持扫码配对登录（车机屏显二维码+配对码，手机端批准），并支持手动输入服务器地址兜底；已登录启动直达主界面。
- **FR-002**: 车机端 MUST 复用现有 API 层与同一 MovieClaw 服务器，不新增/修改后端接口。
- **FR-003**: 车机端账号能力 MUST 限于：查看当前账号、切换已保存账号、退出登录（确认）、关于；不做管理功能。

**页面与交互**

- **FR-004**: 车机端功能范围 MUST 为：登录、首页、媒体库海报墙、详情页、播放器、搜索、账号；发现/订阅、离线下载、Agent 聊天、通知中心、设置、分享一律不提供。
- **FR-005**: 车机全部页面 MUST 遵循车机通则：触控目标 ≥48vp、导航层级 ≤3 级、3 秒注视原则内可完成主操作、高对比、无高频闪烁动画。
- **FR-006**: 车机端交互为纯触屏模型（点击/滑动/长按），MUST NOT 引入 TV 端的遥控焦点/悬浮双态体系。
- **FR-007**: 首页 MUST 以继续观看/收藏大卡置顶（点击一次即续播/进详情），辅以少量横滑内容行；无记录时显示引导态。

**播放与行车安全**

- **FR-008**: 驻车状态 MUST 支持全屏视频播放（AVPlayer + 服务端 HLS），具备传输条、字幕/音轨/画质信息面板、跳过片头、下一集、错误重试能力。
- **FR-009**: 行车状态 MUST 锁定视频画面、音频继续，界面切换为大控件播控卡并显示锁定提示；行车转驻车后可手动恢复视频。
- **FR-010**: 行车信号不可得时 MUST 提供手动「驾驶模式」开关兜底；真车行车信号接入作为预留（接口留位，不阻塞模拟器验证）。
- **FR-011**: 车机端 MUST 提供全局常驻 mini 播控条（封面/标题/播放暂停/下一集/点击回播放器），无播放时隐藏。
- **FR-012**: 播放进度与会话 MUST 与服务器同步（续播点、进度上报），跨端（手机/TV/车机）续播一致。
- **FR-013**: 播放状态 MUST 接入官方 AVSession 上报（元数据与播控指令），车机系统级播控联动。

**工程与渲染约束**

- **FR-014**: 车机端全部 UI MUST 使用 HarmonyOS 官方 ArkUI 组件与官方 Kit 能力渲染，禁止 Canvas/自绘视觉元素。
- **FR-015**: 工程 MUST 保持手机端与 TV 端现有功能零回归；车机代码全部隔离在 `entry/src/main/ets/car/`，对现有代码的改动仅限设备分流接线与清单文件。
- **FR-016**: 车机端 MUST 固定深色主题，宽屏横屏响应式布局（不锁固定画布，适配 Huawei_Car 模拟器实际分辨率与真车屏幕差异）。
- **FR-017**: 验证顺序 MUST 为「先实现 → 构建 → Huawei_Car 模拟器 UI 检查」。

### Key Entities *(include if feature involves data)*

- **车机登录会话**: 配对码/二维码内容、轮询状态、服务器地址（复用现有配对与令牌体系）
- **首页卡片（Continue/Favorite Card）**: 条目、进度、集数信息、点击行为（续播/详情）
- **海报墙状态**: 排序/筛选条件（本地记忆，复用 TV 端同类持久化模式）
- **播放模式（Playback Mode）**: 驻车视频 / 行车音频（大控件播控卡）；驾驶模式开关（手动兜底）
- **mini 播控条状态**: 当前播放条目、播放态、显隐
- **AVSession 上报**: 元数据（标题/封面/时长/进度）、播控指令（播放/暂停/上下集）
- **复用实体**: 服务器、账号、媒体库、条目、合集、影人、播放会话、轨道/画质（同 TV 端口径，不改结构）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在车机端可完成「启动 → 扫码登录 → 首页点卡续播 → 播放器控制 → 退出续播一致」全流程，主操作均在 3 秒注视/3 次点按内可达。
- **SC-002**: 行车锁视频用例通过：手动驾驶模式开启后视频画面锁定、音频继续、播控卡可用；关闭后视频恢复。
- **SC-003**: 全部车机页面在 Huawei_Car 模拟器上无内容截断/重叠/白底白字，触控目标 ≥48vp，空态/错误态齐备。
- **SC-004**: mini 播控条在所有非播放器页面正确显隐与联动，点击回播放器路径正确。
- **SC-005**: 手机端与 TV 端零回归（构建产物中车机代码不进入手机/TV UI 路径）。
- **SC-006**: 官方组件覆盖 100%：车机 UI 无 Canvas/自绘视觉元素。
- **SC-007**: 验证按「构建通过 → Huawei_Car 模拟器 UI 检查」顺序完成，模拟器截图对照验收用例通过。

## Assumptions

- 服务端能力与 TV 端在用集合相同（配对登录、HLS、trickplay、进度、收藏/已看），车机不新增后端接口。
- 车机端复用 TV 端已验证的架构模式：产品定制层目录（`car/`）、EntryAbility 设备分流、V2 状态管理、复用 common/AppModel 与 api/ 数据层、自管轻量路由。
- TV 端验证（T031~T033）此前被用户取消待补，不阻塞本特性；两端互不回归。
- 无真车环境：行车信号以手动驾驶模式开关兜底验证；AVSession 系统级联动在模拟器可达范围内验证，真车表现列为后续事项。
- Huawei_Car 模拟器为 HarmonyOS 7.0.0(26) Beta1，工程目标 SDK 6.1.1(24)，以前向兼容方式运行；不兼容项以模拟器实测为准降级处理。
- 车机端固定深色主题（用户已决策，不做昼夜切换）。
- 车机端语音输入依赖系统语音能力可达性，模拟器上以系统输入法为主验证路径。

## Open Questions

- **OQ-1（行车信号来源）**: 真车行车状态 API 在当前 SDK 面向三方应用的开放程度未知——设计以「手动驾驶模式开关」为主控、预留行车信号接入位（Phase 2 定接口形态）；若官方开放行车信号接口则自动优先、手动为兜底。
- **OQ-2（系统媒体模板深度集成）**: avMusicTemplate（Car 专属系统媒体模板，API 23+）可将内容接入车机系统级媒体界面，属深度系统集成路线，本期仅做标准 AVSession 联动（FR-013），模板集成是否后续立项由用户另行决策。
- **OQ-3（模拟器分辨率差异）**: Huawei_Car 模拟器实际分辨率/断点与真车屏幕（问界等）存在差异，布局按响应式实现不锁死画布；真机/真车适配列为后续事项。
