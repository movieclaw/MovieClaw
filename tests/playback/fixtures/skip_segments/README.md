# 跳片头：真实媒体指纹回归数据

这里的指纹来自实际编码的 H.264/AAC MP4，不是手工拼出的哈希。
音频为固定随机种子生成的三声部乐音（含泛音、淡入淡出），非重复区域每集不同。
这些是可控的合成媒体，不是实际影视片库的准确率样本。

每种场景有三集，每集 960 秒，视频色块按下表标示剪辑内容；黑色为本集独立内容。
预期边界由生成器的剪辑清单决定，不依赖识别输出。指纹从最终 AAC 解码提取，
因此包括真实的编码误差、chromaprint 预热与时间分辨率影响，边界测试容差为 3 秒。

| 内容 | 原始时间（秒） | 色块 |
|---|---|---|
| 冠名广告 | 5–30 | 黄 |
| 正式片头 | 65–135 | 蓝 |
| 开头窗口内的插播广告 | 180–210 | 橙 |
| 较长的重复配乐剧情 | 755–825 | 紫 |
| 真正片尾 | 920–960 | 红 |

三种数据：

- `fingerprints.npz` / `aligned.json`：三个开头段在各集的位置相同。
- `shifted.npz` / `shifted.json`：第 n 集的三个开头段整体后移 `7 × n` 秒。
- `unique.npz` / `unique.json`：冠名广告每集不同，插播广告缩短为 8 秒。

每个 NPZ 有 `1_intro`、`1_outro` 至 `3_intro`、`3_outro` 六个 uint32 数组。
片头窗为 0–240 秒，片尾窗为 720–960 秒。JSON 记录剪辑清单、视频 SHA-256 与
指纹工具版本。生成时使用 FFmpeg 5.1.9 的 chromaprint 封装器，视频和大 PCM 文件不进 Git。

## 复现

在仓库根目录运行（需要 numpy、支持 chromaprint 的 ffmpeg）：

```sh
python scripts/generate_skip_segments_fixture.py \
  --scenario aligned --output data/skip-segments-check/aligned
```

将 `aligned` 分别替换为 `shifted`、`unique` 可重建另外两组。可通过 `--encoder` 和
`--ffmpeg` 分别指定编码器和指纹工具；输出目录包含可播放视频、指纹和清单。
不同 FFmpeg 版本编码字节可能不同，应检查时间边界，不要求跨版本视频 SHA-256 一致。

运行回归：

```sh
PYTHONPATH=src python -m pytest tests/playback/test_skip_segments.py -k encoded
```

## 修复前后

算法 v1 对 `aligned` 的第一集只返回片头约 64.46–134.00 秒，并将剧情配乐
754.55–824.15 秒误标为片尾；两段广告和真正的片尾全部漏掉。
原因是相同对齐位移只留下最长连续段。

算法 v2 保留每个位移下所有达到长度门槛的连续段，再做现有的去重、跨集支持验证和分类。
同一份指纹得到两段 `other`、一段 `intro`、一段真正的 `outro`，且 `outro.to_end=true`。
整体平移场景同样保留全部段；不同广告和不足 15 秒的短段不被识别。

## NAS 实际剧集回归（算法 v3）

`nas-diner.npz` 来自用户 NAS 的《深夜食堂》（2009）S01E01–E04，实际 MKV 音轨用
FFmpeg 5.1.9 chromaprint 提取；没有合成或改写哈希。文件只保留不可还原音视频的指纹，
不包含原片、画面或 NAS 路径。键 `1`–`4` 为四集开头窗口的 uint32 指纹，`durations`
为原片总时长：1476.992、1476.992、1514.208、1476.384 秒。提取窗口是各集前 25%。

2026-10-03 对片段边界前后和中间抓帧核对：125–144 秒为固定开店片头（挂门帘、店内
时钟等镜头），不是广告或本集独有剧情。

第一集在该处与第二集有 0.12–154.18 秒长匹配，与第四集有 125.45–144.15 秒短匹配。
原算法直接对支持区间的端点取中位数，将短候选扩成约 62.79–149.16 秒；v2 多段识别后，
它又因与 78.27–104.64 秒候选重叠而被丢弃，最终漏掉真正的片头末段。
v3 将支持区间裁到候选范围内再取中位数，稳定保留 125.45–144.15 秒这一段。
测试 `test_real_episode_short_match_does_not_borrow_long_partners_boundaries` 在 v2 失败，
v3 通过。

这项修复不将片头里的未匹配间隔强行合并，因此某些实际片头仍会表现为多个跳过按钮。

`nas-crown.npz` 使用相同结构，来自《王冠》S03E01–E04 的真实开头窗，原片时长为
2937.441、2935.105、3397.814、3686.016 秒，窗口均为前 600 秒。第三集 278–301 秒
画面已出现演员署名，是正式片头的前半段；v1 只保留 305–347 秒后半段，多段修复后两段
都保留。该样本为多段修复补充真实影视来源的正例。

## 实片发现的片尾误报（算法 v4）

`nas-threebody-outro.npz` 来自《三体》（2023）S01E01、02、03、05、10、11、13、17、18、23、24。
键 `numbers`、`durations`、`starts` 分别是集号、原片时长、片尾指纹窗口起点；各集号对应
该集后 420 秒的真实 uint32 指纹。保留完整 11 集上下文，避免少取伙伴改变多数门槛。

S01E01 的 2367.75–2384.71 秒是剧情中的资料画面，边界前后和中间均已抓帧核对。
v2/v3 新增多段后，把它与 E11、E24 的配乐匹配当成片尾；这两对后面还有更晚的共享段，
但后段没通过共识门槛，算法才退回前面的配乐。v4 将「每对只取最后片尾候选」提前到共识
验证之前，不允许退回，结果不再含有该误报。测试同时要求同批 E10 的真实片尾仍能识别到结尾。

此轮只读抽样共 4 部剧 23 集：《三体》11 集、《潜伏》S1 前 4 集、《深夜食堂》S1 前 4 集、
《王冠》S3 前 4 集。v4 相对 v3 在这批样本中只删除上述误报；这不是整库准确率测量，
没有识别出的集也不能仅凭本次有限伙伴样本判定为算法错误。

## 扩大实片测试后仍未解决的问题

累计只读检查 6 部剧 61 集：《三体》11 集、《潜伏》4 集、《深夜食堂》S1 全 10 集、
《王冠》S3 全 10 集、《我的大叔》S1 全 16 集、《间谍过家家》S1 抽 10 集。
复核了本轮所有原片的大小与修改时间，均未改变。识别结果对比覆盖全部 61 集，画面
仅针对边界、变化和疑点抽查；这不等于 61 集全部内容都有人工作为准确率真值标注。

扩大伙伴集合会改变结果：《深夜食堂》E01 的片头由零散段变为 0.25–153.31 秒；
《王冠》E03 变为 277.40–346.75 秒，E04 仍分成两段。《我的大叔》E02 的 68:34
误报在前 6 集数据下出现，整季 16 集时改选更晚的区间；E03 的误报整季仍在。
因此回归保留前 6 集场景：追更或部分文件暂时不可读时同样会出现，不能用整季结果
掩盖它，也不能把整季出现的新区间未经画面核对就算成正确结果。

`nas-spy-outro.npz` 为《间谍过家家》（2022）S01E01–E06、E12–E15 的真实片尾窗，
结构同 `nas-threebody-outro.npz`。E01 在算法 v1、v4 都得到 1311.68–1379.42 秒。
2026-10-03 抓帧核对：1365 秒仍有片尾字幕，1368、1370、1372、1374、1376、1378 秒
已是屋内角色剧情。点击跳过会越过至少 11 秒剧情；不能因为音乐继续就把这些画面算成片尾。
这里的 1368 秒是确认剧情已经恢复的保守上界，不是声称帧精确的片尾终点。

`test_real_outro_must_not_cover_post_credit_story` 明确标记 `xfail(strict=True)`，
记录**真实存在、尚未修复**的问题。可取消预期失败处理来直接看到失败：

```sh
PYTHONPATH=src python -m pytest tests/playback/test_skip_segments.py \
  -k real_outro_must_not_cover_post_credit_story --runxfail
```

该样本的第 4 集有正常的到结尾片尾，作为后续修复的正例约束。不能通过禁用所有片尾
让负例通过，也不应根据这一部剧任意提高音频阈值。音频重复不能单独证明画面内容类型；
后续需验证画面或字幕边界，再决定是否输出或裁短片尾。

`nas-mister-outro.npz` 为《我的大叔》（2018）S01E01–E06 的真实片尾窗，结构同上。
E02 当前结果为 4114.36–4140.31 秒，与 E01、E03 的对应音频质量分别约 0.813、0.773。
用户观看上下文视频后确认：E02 的 68:34–69:00 全为本集剧情。E03 按短视频起点
75:07 计时，前 17 秒为本集剧情，18–36 秒为本集片段，39 秒起为下集预告；用户再次
确认相对计时起点为 75:07。这对应 4507–4524 秒为本集剧情，4525–4543 秒为本集片段，
4546 秒起为下集预告（未对中间过渡秒数作精确标注）。当前 E03 识别区间为
4516.45–4542.20 秒，越过了前面的本集剧情。

两集各有一个严格 `xfail` 回归用例，约束输出不能覆盖用户确认的剧情段。
这些均是已确认但尚未修复的误报；可用 `-k user_labeled_story --runxfail` 直接复现。

## 四地区扩大验证与音轨修复（算法 v5）

累计 14 部剧、93 集，包含大陆剧 23 集、美剧 12 集、韩剧 20 集、日剧及日本动画
28 集，另有《王冠》10 集。新增《开端》《漫长的季节》《老友记》《绝命毒师》
《人生切割术》S2、《信号》《非自然死亡》《重启人生》各前 4 集。
同样只对输出边界和疑点抓帧；没有把“跑完识别”当成“每段都标注正确”。

`nas-reset.npz` 保存《开端》E01–E04 的原始开头窗，格式同 `nas-diner.npz`。
E02/E03 的前 600 秒指纹逐项相同，进一步对第一条完整压缩音轨做 SHA-256，两者都是
`0a009974cfed46448a775c3e4b17ec98f4ea6e15d67d3d4f35357071a1657ba9`。
该重复音轨在 E01 的 427.62–452.39 秒剧情配乐上重复投票，v4 因 2/3 伙伴支持而
误标 `other`，播放器显示“跳过片头”。抓帧确认这里是男女主在公路旁的连续对话。

v5 对**长于最大可跳片段的完整指纹窗口**去重，相同窗口只算一份独立证据；目标自己
的重复版本也不当作独立伙伴。短窗口可能全部处于正常片头内，因此不作这种去重。
回归先在 v4 失败，修复后四集正常片头保留，E01 剧情误报消失。对同批 93 集重跑，
只改变《开端》E01/E04 的片头支持数及小幅边界，并删除 E01 的错误 `other`；其他
13 部剧的结果完全不变。

`nas-reset-audio.json` 是 E03 的真实 ffprobe 音轨时长信息。文件时长 2671.701 秒，
第一条 E-AC-3 仅 2422.368 秒（误封了 E02），第二条 AAC 为 2671.701 秒。原本固定
读取第一轨，把 E03 片尾窗提成 1357 个哈希，正确轨则是 3371 个。
服务现在仅在第一轨明确短缺、存在同语言且覆盖全片的普通音轨时改选；解说轨、其他
语言、时长未知都不盲目替换。多音轨旧缓存按选择策略版本重建，单音轨不为此重读。
新指纹写回时撤下旧分段，即使文件大小没变，也不会在新旧音轨切换过程中沿用旧时间点。

`nas-reset-complete-outro.npz` 是完整音轨的真实回归产物（同 `nas-threebody-outro.npz`
结构）。其中 E03 来自修改后的实际服务 `compute_fingerprint`，真实 ffprobe 与
FFmpeg 处理原 NAS 文件，没有替身。E03 片尾修正到约 2519.92–2668.34 秒，边界前后
和中间抓帧均确认已进入演职员字幕；E01 也找回了此前缺失的片尾前半段。

产品体验试验还发现两个待用户标注区间：《信号》E04 539.07–560.00 秒被当成片头，
《非自然死亡》E01 3372.90–3397.43 秒被当成片尾。未收到内容标注前不写死预期类型。

本地 OCR 对 30 张较高分辨率的实片画面进行了试验，能读出《开端》的“广告”标记、
中英日演职员职务；内封 ASS 字幕还能提供《我的大叔》的“下集预告”标题。但正常动画
片尾中也有无文字的画面，单凭 OCR 没读到文字就删除区间会漏掉正常片尾，因此这轮
没有将该规则接入生产，也没有新增生产依赖。实验模型、截图、字幕和视频只在本地
`data/` 中，不随这些指纹夹具提交。广告、预告的专属按钮应建立在可靠类型证据之上，
不能把所有 `other` 一律改称广告。

本轮最终验证：片段算法与服务端定向测试 51 项通过、3 项严格预期失败（上述仍未修复
的真实剧情误报），网页播放器 6 项通过；格式与静态检查通过。再次逐一核对 93 个
NAS 原文件，大小和修改时间均与提取前一致。《老友记》E02 与《绝命毒师》E02 的
片头起止前后也已抓帧确认。尚待标注的片段不计入正确样本，未输出结果也不计为识别成功。
